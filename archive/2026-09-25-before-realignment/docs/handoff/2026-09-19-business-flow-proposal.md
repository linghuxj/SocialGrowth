## 1. 产品组织与商业交付的关系

以“为某个客户，在特定受众与时间范围内完成一项可评价的运营目标”为服务单元。账号、素材、设备、策略和短链服务于这一目标，不能各自只有状态而无法说明对客户的作用。商业承诺与产品能力分别规划，能力依赖见[产品路线](../product-roadmap.md)，不以月度数量或商业验收结果限制功能设计与开发。

首期仍由内部运营人员使用系统；客户接入信息可以由运营代录，不因此建设客户门户或多人审批。

**G-02/G-02a 已确认**：兼容公司自有账号与客户授权代运营账号，逐账号分别记录所有方、服务客户与授权范围。账号同一时期默认服务一个客户；共享须明确授权、目标冲突与归因边界，再由运营人员人工批准。运营权限不等于账号所有权，现有设备/账号资源数量不作为具体归属或授权已核验的证据。

共享记录列明账号、客户范围、适用期间与限制；账号总体频次及资源约束不因多客户叠加放大。各客户策略和结果保留服务关系，无法可靠区分的账号级指标不伪分摊到客户；共享不自动授权客户素材、数据和导流入口交叉使用，目标变化仍遵守 G-01a/G-01b。

**G-01 已确认**：主目标按客户或阶段分别明确，系统不设置全项目统一的导流、账号资产与效率排序。各运营项目依照自己的主目标判断策略取舍，不能通过统一加权分数替代这一选择。

**G-01a/G-01b 已确认**：AI 可建议切换主目标，须经运营人员人工确认后生效；切换时暂停受影响范围内尚未开始的旧计划，按新目标重新审查、批准后执行。自主托管不能代替目标切换确认或本次旧计划重审。实验分段、主指标与约束按第 4 节 G-05 规则落实，不从本次选择推定所有具体判据已获确认。

## 2. 完整业务主流程

客户目标与服务约定 → 接入就绪检查 → 素材准入与可用库存 → 账号定位与内容组合 → 候选策略与验证计划 → 审核或范围内托管 → 排期与发布前复核 → 发布结果确认 → 受众导流与表现观察 → 复盘判定 → 保留、调整、分批扩大、暂停或退出。

这一流程允许“暂不发布”和“证据不足”。并非每个输入都必须产出发布任务，也并非每轮实验都必须选出赢家。

| 环节 | 必需输入与业务规则 | 输出与完成条件 | 未满足时 |
| --- | --- | --- | --- |
| 客户目标与服务约定 | 客户目标、目标受众、服务期限、主要指标、禁止事项、报告范围、预算观察口径；退出后的内容保留、链接维护、权限与资料交接约定 | 可供运营引用的业务简报；明确无法观测的结果和退出责任 | 缺目标先澄清，不默认以最大播放量代替；未约定的退出责任待落实 |
| 接入就绪检查 | G-02 的账号来源、所有方、服务客户、授权方与范围/期间/依据，以及素材提供方、导流入口、目的地、数据权限、异常联系人 | 按账号及平台列出可运营/待核实/待授权等状态及依据 | 兼容两类账号不证明具体账号已经获权；不以其他平台成功替代 |
| 素材准入 | 来源、权利范围与期限、内容质量、语言、地区、剧集信息、重复/重叠关系 | 可发布、需补充、退回或撤回；形成合格库存 | 不合适时不排期；按需要另议加工，不默认越过首期范围 |
| 定位与内容组合 | 已确认受众定位、合格库存、剧集顺序、题材覆盖、账号已有内容 | 账号定位版本与内容组合建议 | 无合适素材时说明缺口，不硬选最高分 |
| 候选策略 | 主目标、规则版本、适用人群、历史证据或冷启动假设 | 策略理由、预计动作、观察方法、停止条件 | 规则冲突先裁决；外部禁止事项不能人工放行 |
| 审核或托管 | 审核范围、内容和文案、目的地、排期、引用规则 | 批准的明确版本和适用范围 | 驳回、修改或重新生成；重大修改使旧批准失效 |
| 排期复核 | 账号资格、授权有效性、内容库存、执行条件、时区与频次 | 仍有效的可执行安排 | 过期、暂停或条件变化时重新安排，不批量补发过期任务 |
| 发布结果确认 | 操作记录、平台内容标识、公开可见性与失败信息 | 明确公开成功、明确失败、处理中或待核对 | 结果未知保留关联并核对，不先认定未发布 |
| 导流与观察 | 实际可点击入口、短链来源、数据来源、观察窗口 | 有边界的内容/账号表现及点击报告 | 缺失和延迟可见；不推断到达、付费或单条归因 |
| 复盘与后续决定 | 同口径证据、异常、人工与成本、预先确定的判定规则 | 保留、调整、分批扩大、无改善、证据不足或停止 | 无足够证据时维持已批准范围或暂停相关自动决策 |
| 变更与退出 | 客户指令、授权变化、成本或风险触发、停止原因 | 停止新增动作，处理待发内容、历史入口与交接记录 | 无法删除/修改的外部内容明确记录，不承诺全部撤回 |

## 3. 业务分支与处置规则

### 3.1 切片与发布生命周期

内容权利、分配归属和发布结果是三个不同问题，应分别说明，而不是用一个“已发布”覆盖全部情况。

| 场景 | 业务规则 |
| --- | --- |
| 同一切片重复导入 | 关联到已有资产记录；文件名变化不自动获得新发布资格 |
| 字幕版、配音语言版 | G-03=A 已确认：同一画面片段的版本共用同一内容身份及账号归属，不因语言变化跨账号分发 |
| 不同片段部分重叠 | G-03c=B：主体剧情不同且仅有必要的少量衔接，经人工确认并记录来源、重叠范围及判断依据后，可作为不同内容分别发布；依据不足则待核对，不计可分配库存 |
| 审核前预占到期 | 释放预占并使旧草案不可直接审批执行；需要重新确认库存 |
| 已批准但确定尚未提交 | G-03a=A：取消原安排，确认全部版本均未提交、无发布历史，且旧批准与执行安排失效后，可释放并重新审核分配；保留核对依据、原因、确认人及时间 |
| 进行中、已提交或结果未知 | 不适用未提交释放规则；维持归属并核对，不以超时或取消操作证明从未提交 |
| 已提交但结果未知 | 不释放给其他账号、不再次发布；先核对平台结果 |
| 已公开成功 | G-03b=A：同一内容及所有语言版本不得再在原账号或其他账号另发一条；保留防重事实，具体资料留存按客户约定 |
| 已公开后删除、受限或撤回 | 保留历史，不把“已不可见”等同“从未发布”；不恢复原账号或其他账号的再次发布资格 |
| 编辑原帖 | 不属于另发一条，仍须符合权限、授权与变更审核；不计为新增独立发布内容 |
| 确定从未发布后的失败恢复 | 与已发内容重发区分，仍按异常流程及当前有效批准处理；结果未知时先核对，本条不授权自动重试 |
| 甲方撤回授权 | 停止受影响新发布；列出已有帖子和入口，按可用权限处理并记录例外 |

### 3.1.1 素材准入、剧情关系与缺货

记录源剧/集数、提供方与权利方、成品版本、适用地区/语言/平台、期限及音乐/配音/图片权利依据。素材分为待补充、可用、需调整、撤回/失效；权利未明、无法播放、语言不适配、剧情或入口承诺不符的内容不能仅靠高匹配分进入真实发布。

合格候选再按账号定位、剧情顺序、题材组合和近期已发内容匹配；续集说明前后关系，不能制造不存在的剧情承诺。没有合适内容就记录缺口与责任，退回补充或提出加工需求，不以填满排期为目标。加工/生成产物须重新准入，产品路线可提前设计，不自动成为本轮实现或首期商业承诺。

同源重叠、语言版本及重复导入按 G-03 系列关联；权利或成品变更重新核对受影响安排，已有发布记录不抹除。客户退出不自动改变素材所有权或新增跨客户使用权。

### 3.2 审核与托管

**已确认边界（G-01a/G-01b）**：目标切换由 AI 提议、运营人员人工确认；既有托管授权或预设条件满足不能代替该次确认。切换时暂停受影响范围内尚未开始的旧计划，按新目标重审并批准后执行，合适的内容可以复用。确认记录明确适用客户/阶段、原目标、新目标、理由、确认人、生效时间及受影响计划。

**落文细化**：暂停不等于取消或释放素材；原目标下的批准不自动适用于新目标。已完成发布保留原目标与记录；进行中或结果不明的发布先单独核对，不归为尚未开始重发，也不因目标切换自动强制终止。异常处置按第 3.7 节执行，实际核对证据仍需取得，实验分段与评价判据按第 4 节 G-05 执行。

**新策略启动权限（G-04=A 已确认）**：日常执行限于已验证规则及明确授权范围；未经验证的新策略先生成小批试验草案，由运营人员人工批准后启动。账号成熟或启用托管开关不能替代这次批准。

托管授权明确适用客户/主目标、账号和平台、允许的操作、已验证策略版本或规则范围、合格素材及目的地条件、频次与成本限制、起止时间；异常暂停与恢复方式需配套记录。试验批准另列待验证假设、版本、试验账号/发布量、预算、期限、观察方法、停止条件、批准人及时间。

在已验证规则与授权参数内选择合格内容、生成文案或排期属于常规执行；未经验证假设、关键规则变化或超出已验证适用范围属于待审新策略。一次批准可覆盖范围清楚的一批试验，批内完全符合批准的动作不逐次重审；试验假设、关键规则或范围变化、批准到期及停止条件触发后，受影响的未开始安排不再沿用旧批准。疑义待审，不能把试验伪装成日常调整。

试验启动许可与有效性结论分开，批准试验不授权自动扩大或转为常规托管；评价与推广判据按第 4 节 G-05 执行。G-01a/G-01b 的目标变更与重审、G-03c 的内容重叠人工核对继续分别适用。

可自动处理的常规事项与需人工确认的变更分别列清：新客户目标、定位调整、新目的地、未验证规则、权利异常、平台限制及超出托管范围的动作，不能仅因账号“成熟”而自动批准。

单人运营需要值守窗口，而非全天候响应假设。实际审核、新策略试验、内容重叠核对、异常和复盘的耗时分别记录，不能把每日 5–10 分钟作为未经验证的承诺。

**非值守安排（G-04a=A 已确认）**：继续执行有效批准范围内的发布；需人工处理的异常暂停受影响及关联安排，只有确认无关联的安排可继续。不能确定影响范围时暂停无法排除风险的相关范围，不默认只影响当前任务。值守窗口、时区、责任人与待办处理安排在服务约定中记录，通知不等于人工已经接管，不承诺单人全天即时响应。

技术执行超时、验证挑战有效期、排期有效期和人工服务时间分别判断；超时不证明未发布，设备复位不自动恢复业务。恢复须人工核对异常、发布结果、授权及排期，过期任务重新安排，不自动补发；详细规则见第 3.7 节。

紧急停止应能说明影响哪些账号、素材、目的地和未执行安排；恢复时复核当前条件，不将积压任务全部补发。

### 3.3 账号异常与恢复

| 异常 | 首要处理 | 允许恢复的依据 |
| --- | --- | --- |
| 设备/网络故障 | 暂停该执行资源，核对进行中发布 | 资源恢复且待核对结果已明确；不直接消耗新账号 |
| 登录过期或身份验证 | 联系有权限人员处理 | 身份和授权有效，平台允许继续操作 |
| 暂时发布受限 | 记录通知、范围、期限，暂停受影响动作 | 按平台要求整改或等待，取得恢复证据 |
| 内容移除或版权争议 | 暂停同源风险素材，保留证据并联系权利方 | 处理结论支持继续发布；不简单换号重发 |
| 推荐资格变化 | 与发布能力分别记录，检查内容策略 | 限制状态与影响范围已明确，调整后重新观察 |
| 流量低且原因未知 | 先检查数据、时窗、内容与受众 | 不直接认定限流，不据此启动换号 |
| 频道终止 | 停止受影响业务，核对申诉与禁止范围 | 平台允许的恢复路径；不能绕过终止使用备用频道 |

频道终止与恢复边界以[官方说明](https://support.google.com/youtube/answer/2802168?hl=en)为依据，具体账号状态仍需实际核查。备用资产可用于合法的新接入、资源安排等场景，但其使用资格不能由“清理设备”证明。

### 3.4 受众导流与链接变化

受众路径：看到切片 → 理解片名/语言与引导承诺 → 找到实际可点击入口 → 必要时按明确路径找到对应内容 → 请求短链 → 跳转处理 → 客户目的地。只报告有证据的环节，不将前一步成功等同下一步成功。

| 情况 | 业务规则 |
| --- | --- |
| 入口可用性 | 按平台、账号和展示面核实；Shorts 描述/评论 URL 不可点击，FB 不能只因可填 URL 就认定可点；未确认入口列待核实 |
| 剧集与目的地对应 | 记录客户、剧名、语言、目的地与承诺；只提供首页时说明查找路径，无法识别对应内容则补资料或调整引导，不宣称精确直达 |
| 多内容共用入口 | 利用客户现有可用的查找或选择路径说明如何找到对应剧集；是否另做选择页面留给后续产品方案，不强制新增实现。统计只到实际来源层级，不伪分摊到单条内容 |
| 请求与跳转 | 原始访问、规则过滤点击和跳转处理分开，预览、测试及重复访问单列；过滤后点击不等于真人或到达 |
| 预览一致性 | 封面/标题/描述与真实目的地一致；记录变更后旧预览可能未刷新，不为审核者展示不同去向 |
| 目的地变更 | 按客户授权和内容对应关系人工确认，留生效时间、历史版本及受影响内容；共用主页入口的旧内容一起核对，不改给无关新客户 |
| 不可用或故障 | 区分服务、目的地和平台拦截，暂停受影响新导流；替代目的地须获授权且与旧内容承诺一致，无适用替代时记录不可用，不以无关页面顶替 |
| 历史入口恢复 | 平台可能在请求到达服务前拦截，换域名/服务端地址不保证修复旧帖。能修改的经授权处理，不能修改的记录原因与责任，不承诺全部恢复 |
| 合作结束 | 按 G-02b 继续/停用及维护期限执行，资料按权限和约定留存，不自动转给其他客户 |

入口事实和来源见[平台规则](../platform-rules.md)。实际账号待核实只限制相应真实操作，不阻碍产品流程设计开发。

### 3.5 数据缺失和实验失败

缺失原因至少区分：尚未到采集时间、来源延迟、无权限、指标不提供、调用故障、内容不可访问和已确认零值。切换来源后重新判断比较资格。

数据不足时可保留观测和人工分析；暂停依赖这些指标的自动晋级。已公开内容的低表现也不意味着发布失败。没有改善的实验仍可形成完整复盘；不能为了通过验收而强行选出胜者。

### 3.6 客户服务退出（G-02b 已确认）

**已确认原则**：正常合作结束后，停止该客户的新增运营服务，在内容授权及账号管理权限允许的前提下保留已发内容。旧短链按接入时约定继续有效或停用，不自动转给其他客户。继续保留不等于新增运营或无限期维护。

以下是该原则的业务落文细化，不新增固定留存天数或收费承诺：

| 环节 | 处理规则与完成记录 |
| --- | --- |
| 接入时约定 | 明确已发内容保留依据、旧链接继续/停用条件、期限与维护责任、权限交接方式、历史资料可访问范围和保留期限；既有客户缺少约定时列为待补，不推定无限授权或永久服务 |
| 确认退出范围 | 记录客户、账号、停止生效时间、原因、确认依据及经办人；共享账号仅停止退出客户的服务，复核其他客户仍有效的授权和安排 |
| 停止新增服务 | 停止新增发布和互动等运营；暂停或取消尚未开始的安排并记录处置，既有托管授权不继续产生退出后的新任务 |
| 核对执行结果 | 对已进入执行或结果未知的发布保留关联、核对最终结果；不当作未发布重发或释放素材，不承诺退出生效即能撤回已提交操作 |
| 处理已发内容 | 正常退出按原则保留；保留原客户、目标和发布历史，不因账号以后服务新客户而改写归属。授权到期/撤回时按权利要求及可用权限处理，无法下架的记录原因、责任人与待办 |
| 处理旧入口 | 按约定继续指向获授权的原客户目的地范围或停用；记录期限、责任人、变更依据和受影响内容。共享主页入口不能按单条旧视频独立更换，需核对全部受影响内容；不得自动改指其他客户 |
| 交接与留档 | 按原有账号归属和授权交接或撤销管理权限；按约定交付可交付的资料、保留必要历史证据，明确访问范围和期限，不把客户素材/数据自动复用给其他客户 |
| 退出复核 | 汇总已完成处置、继续履行的链接维护、未完成交接及外部不可控事项，列明责任与期限；正常服务结束与遗留事项完成分别记录，不将无法操作写成已下架或已交接 |

本流程确定文档要求，不能替代具体账号授权、客户约定及平台实际可操作范围的核验。跨语言内容身份按 G-03 执行；未提交取消后的归属按 G-03a 执行，同账号禁止重发按 G-03b 执行，部分重叠按 G-03c 人工确认规则处理；执行异常按第 3.7 节处理，具体平台核对与恢复资格仍须实际取得证据。

### 3.7 异常暂停、结果核对与恢复

本节依据 G-04a 及已确认的目标、内容和取消规则补齐业务处置，不要求开发实现，也不将技术命令成功视为业务恢复成功。

| 步骤/状态 | 业务处理与所需证据 |
| --- | --- |
| 发现需人工处理的异常 | 记录发生时间、原因、原计划/批准、账号、执行资源、内容和入口；保留必要证据并通知责任人，非值守进入待办 |
| 判断影响范围 | 按共同原因覆盖账号权限、共用设备、同源素材权利、共同目的地或服务故障影响的任务；无法排除风险的相关范围先暂停，只有确认无关联且批准仍有效的安排可继续 |
| 确定尚未提交 | 保持暂停；需要取消并释放时核对该内容全部版本无提交和发布历史、旧安排失效，严格适用 G-03a |
| 已提交但仍处理中/结果未知 | 保留关联和归属，不再次提交、不跨账号分配；核对平台内容标识、账号内容记录及可取得的处理结果，不能仅以无回执、没看到帖子、超时或设备复位认定失败 |
| 确认已经发布 | 记录内容标识、账号和发布证据，执行 G-03b 一次发布约束；后续不可见不改判为从未发布 |
| 确认从未发布的失败 | 需要平台明确拒绝等可核对依据，并排除仍在处理或存在对应帖文；经人工确认异常解除、原账号可用、授权有效及当前排期合适后可批准恢复。不是已有发布历史的重发，也不自动获得跨账号释放资格 |
| 持续无法确认 | 标为待核对，记录责任人、缺少证据和下次检查安排；证据未变不自动转失败或重新发布，必要证据不能因清理缓存丢失 |
| 挑战或授权过期 | 按当前身份验证/权利状态重新处理；验证通过不自动证明平台限制解除，不沿用失效验证码、凭据或批准 |
| 恢复前复核 | 运营人员记录异常解除依据、受影响范围的发布结果、当前权限及内容资格、仍有效的计划与批准；仅对明确符合条件的范围批准恢复，风险未解除的继续暂停 |
| 排期已过期或需重排 | 原排期失效，记录原因与未达成量；重新安排须符合当前批准范围、频次/资源/成本限制及必要审核，不自动集中补发积压任务 |
| 完成处置与留档 | 执行资源状态、平台发布结果、业务是否恢复分别记录；留存恢复人、时间、依据和未解决项目。资料按约定访问/留存，仍待核对且无其他副本的必要证据不得提前清理 |

示例：设备断线可能同时影响该设备的 FB 与 YT 安排，不能仅停报错账号；单一客户素材撤权不必自动停止已确认无关联的其他客户；超时后发现帖子已公开则登记为已发布，不补发；进入上班时间但权限仍失效则继续暂停。

恢复许可不解除平台限制、不替代账号所有方或素材权利授权，也不允许已发内容重新发布。上述记录可用于文档验收，真实恢复仍需平台和账号的实际证据。

### 3.8 规则、版本与排期变更

外部约束、已确认内部规则与待验证经验分开；经验冲突由运营修订或停用，人工不能覆盖外部禁止事项。无经验时可依据目标、已核查规则和定位形成待验证草案，按 G-04 批准，不能编造历史效果。

定位的地区、语言、受众或垂直方向由 AI 建议调整后仍须运营确认并保留版本；受影响的未开始计划重审素材适配、规则及排期。涉及主目标变更时执行 G-01a/G-01b，已发内容和数据保留原定位依据。

长期策略版本是否有效、排期是否获批和一次执行是否完成是不同状态。新版本不自动释放旧内容或覆盖历史；旧草案被替代后不得继续审批/下发。目标、目的地、内容身份、关键规则或排期条件改变须核对批准有效性，保存表单不等于批准。

账号/客户安排使用受众时区，值守时区另列；记录当地显示时间与确定的实际时刻。运营日、滚动窗口和间隔按对应规则分别检查，跨日、夏令时、时区变化及重排不得放大限额；不集中补发积压任务，不回写历史发生时间。

互动针对真实问题或内容上下文，不制造赞评或重复导流。超出已授权回复范围的承诺、权利争议或投诉交人工；删除评论等有外部影响的操作需明确权限，不因托管自动取得全部权限。

## 4. 指标与实验的业务口径

| 指标 | 可以说明什么 | 不能说明什么 | 规格必须补充 |
| --- | --- | --- | --- |
| 计划发布达成 | 已确认公开的计划内容 / 冻结计划范围 | 账号已增长或客户已获客 | 计划冻结点、取消/暂停原因、重复与重试处理 |
| 公开发布确认率 | 首次提交内容中取得公开成功证据的比例 | 每次 UI 动作都正确或长期可见 | 按内容计数、核对期限、未知结果单列 |
| 短链有效点击 | 经已声明过滤规则的点击事件 | 真实独立人数、目标页到达或订单 | 过滤版本、去重窗口、来源粒度、测试访问排除 |
| 目标受众匹配 | 可取得的地区/语言等证据与预期的一致程度 | 每个点击者都符合完整用户画像 | 数据覆盖、未知占比、地域推断误差；不能只靠 IP 证明精准人群 |
| 导流效率 | 同一可解释观察单元内的点击与暴露机会关系 | 任意来源点击 / 全平台播放即可称标准 CTR | 入口和分母定义；频道主页不得伪装成单条 Shorts 归因 |
| 万粉账号 | 单账号达标记录与合格存量 | 真实变现、目标受众质量或可出售价值 | 首次达标累计、期末存量、退出、重新达标分别计数 |
| 人工负荷 | 常规审核、异常、素材和复盘耗时 | 只看审批用时就代表全部运营成本 | 按工作类别、账号/任务量及值守时间统计 |
| 单位成本 | 约定成本范围 / 对应有效产出 | 总预算可直接视为单位获客成本 | 直接运行成本与分摊成本分开；分母为零时不填零成本 |

**G-05=A 已确认**：完整合格试验与可信复盘可以验收第三月的优化闭环，无须强制产生改善结论；闭环能力、策略有效、业务目标达成及扩大权限分别记录。无改善/证据不足的候选不能据此推广，原增长目标不取消。

试验模板：业务问题与主目标 → 主要假设 → 主指标及分子/分母 → 平台与比较单位 → 账号/内容范围 → 基线与候选方案 → 主要变化 → 素材差异及其他混杂 → 来源/授权/归因粒度 → 观察窗与采集计划 → 最低证据和完整性要求 → 排除规则 → 停止/改善/继续条件 → 成本与人工 → 结果、限制及后续授权。

以上字段及阈值依据须在启动前明确，不能事后选择有利指标或持续以“待定”代替。原 10%–20% 分组、7–14 天、15% 提升及统一加权分不再是通用标准；每个项目按主目标与可用证据选择适当方案。早期 2/12/24/72 小时采集若不足覆盖所批观察窗，须补充后续采集或明确本轮未完成，不能用前三天代替全窗证据。

同源不同切片、账号冷启动阶段、受众地区、发布时间和来源变化都可能影响比较。当前独占原则下可以匹配不同素材进行探索，但不能把内容差异消除不了的结果称为严格因果证明。频道主页短链由多个内容共享时，实验必须采用能支持其归因粒度的设计，或放弃该单条指标。

数据来源与指标口径变化须显示并分段核对，不静默改主指标。真实零值、尚未到采集时间、来源延迟、无权限、指标不提供、故障及内容不可访问分别记录；无法支持原比较时停止作出胜出判定。主指标不得被不可比的公开加权分替代，不能通过换算法消除素材差异或小样本不确定性。

| 评价情形 | 闭环验收 | 策略与后续 |
| --- | --- | --- |
| 必要执行、采集、质量核对与评价完整，满足预定改善及约束判据 | 可按完整案例验收 | 仅在证据支持的范围内认定改善；推广仍须明确授权 |
| 必要工作完整，未见改善或表现恶化 | 可凭可信复盘验收闭环 | 不推广候选，说明保持原策略、调整或停止的理由 |
| 必要工作完整，但样本/不确定性不支持胜出结论 | 可凭透明的证据不足报告验收闭环 | 不宣称有效、不扩大；如需继续取证，按 G-04 批准下一批 |
| 缺必需执行、主指标采集或评价记录，或存在未解决的比较失效 | 未完成/无效，不能以证据不足标签通过 | 补齐或重新设计并批准，不能换指标硬选赢家 |
| 触发停止条件，按批准流程提前停止 | 可核验停止分支正确性，不能单独替代完整实验案例 | 保留原因与影响，暂停相关范围，不为验收强行继续 |

真实零点击可能是有效结果；没有点击采集证据不是零点击结果。来源限制在试验前已知时，应先调整并批准可评价方案，不能明知无法采集仍启动后以“证据不足”验收。

同一客户/阶段内报告绝对值、变化和对应分母；比较双方观察年龄与范围一致，原始计数不掩盖发布量差异。小样本允许方向性观察，不强行作因果或普遍有效结论。平台、目标、关键来源变更时分别报告，不将不同条件的数据拼成统一胜出分。

复盘输出保持、调整、继续取证或停止及其依据；新试验按 G-04 批准。回退只影响未来规则与未执行安排，不能撤销历史发布、曝光、点击或平台处置。G-04a 的未知结果核对与 G-03 的内容一次发布规则继续适用。

## 5. 商业交付、产品能力与运营启用分别判断

保留月度商业目标及经营判定，但不以商业达量限制后续能力设计开发。以下判断实际运营与商业结论，[产品路线](../product-roadmap.md)按能力依赖独立推进；研发进展、真实接入、运营授权和商业结果分别记录。

| 判定层次 | 必须回答的问题 | 建议证据 |
| --- | --- | --- |
| 单平台业务闭环 | 是否从真实目标与合格素材走到公开发布、数据反馈和下一轮决策 | 平台分别提供完整业务案例及边界；真实自然点击与测试点击分开 |
| 持续运营能力 | 是否能连续服务，异常有人处理、结果未知能核对 | 连续观察记录、数据覆盖、暂停恢复、人工负荷及库存 |
| 托管资格 | 哪些范围已经验证，什么情况下立即撤回自动授权 | 适用规则与案例、值守安排、停止和恢复记录 |
| 优化闭环能力 | 获批方案、真实执行、必需数据及质量核对、评价与下一步决定是否完整 | G-05 允许合格试验得出无改善/证据不足；必需工作未完成不能通过，两个平台分别验收 |
| 策略证据 | 改善是否有可比较依据，结论适用于哪里 | 事先定义的判据与真实结果；不将闭环通过当成改善已证实或推广授权 |
| 客户价值 | 是否支持所约定的业务目标 | 目标受众、表现和有效点击；不可观测结果明确为空缺 |
| 扩容或新业务 | 增加范围是否具备内容、账号、数据、服务和投入依据 | 就绪清单、成本/人工/库存余量、前一阶段问题及退路 |
| 合作结束或年度复盘 | 哪些能力可复用，哪些结果未证明，资产如何交接 | 各业务分别的结果、支出、未完成项与客户退出记录 |

每项验收记录均填写：适用范围、证据对象、观察起止、分子/分母、完整性要求、候选阈值及依据、实际结果、判定、遗留项、判定人和日期。

数值阈值不能用“待定”长期替代决策，但也不能凭空写 95%、14 天或 15% 作为通用标准。先选择代表性观察范围，明确用哪些数据校准阈值、由谁决策；校准之前不开放依赖该阈值的自动晋级。验收中的“未通过”“依赖未满足”和“证据不足”分别记录。

## 6. 文档治理与同步清单

当前业务以最新用户决策、需求及已同步规格为准；产品路线管理能力发展，月度/预算管理商业承诺。年度访谈与原审计保存历史，已替代条款不再构成当前限制；Handoff TASK/DONE 不因文档修订自动变为实现完成。

| 责任 | 维护内容 |
| --- | --- |
| 业务负责人 | 最终目的、商业承诺和优先级，不用数量代替产品边界 |
| 客户/资产授权方 | 账号、内容、目的地、数据与交接范围的授权事实 |
| 运营人员 | 规则/试验批准、内容核对、暂停恢复、入口与退出记录 |
| 产品 | 流程、术语、能力依赖、历史替代及文档同步 |
| 研发（后续任务） | 按能力依赖拆分实现并记录开发/接入状态，不按商业数量硬编码产品范围 |

职责可由现有人员兼任，不新增岗位或多级审批。变更保留内容、依据、范围、生效时间和责任；缺责任人则列待办，不以本会话编辑者代替实际授权方。
