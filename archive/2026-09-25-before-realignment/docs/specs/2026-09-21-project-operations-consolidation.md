# 运营项目统一流程与 Agent 账号接入

## 确认范围

依据用户对十项 Web 运营问题的讨论及“认可，继续推进”确认实施。沿用 Artemis 原生 App、FB/YT、纯真机、同机同平台唯一账号、内容独占与结果未知不重发。此文补充现有业务基线，不将新 UI 当作真实发布验收。

日常路径：运营项目 → 账号档案与项目授权 → 核验或创建 Page／频道 → 保存已核验绑定 → 批量素材准入与独占分配 → 策略模板 → 明确批准及排期 → 一次正式发布任务 → 任务中心接收人工协助及结果。

预检是独立可选模式。普通发布不要求先跑一次预检，再重新批准第二个任务；正式发布内部的准入、身份和权限检查不可跳过。

## 领域与表单收敛

| 对象 | 本轮处理 | 保留的边界 |
|---|---|---|
| 运营项目 | 自营／客户代运营，URL 保存项目上下文；项目详情统一链接账号、素材、策略、任务 | 客户与项目不合并；跨项目总览仍可使用 |
| 账号授权 | 自有账号一次确认，代运营选择已有授权主体并填写凭据，数据范围枚举 | 不保存密码；不声称声明等同平台权限；跨客户共享仍须独立依据 |
| 素材 | 项目保存默认来源、权利、语言；最多 30 文件原子批量登记，计算 SHA-256，读取视频元数据 | 每文件故事说明、独立内容确认、准入及分配保留；未知/发布后不可重发 |
| 策略 | 日常切片、连载、导流、小规模试验四种模板；自动引入内置规则 | 模板是确定性组装，不冒充外部 AI；连载仍逐条排期，试验仍需 G04 批准 |
| 规则 | 内置身份、独占、权利、人工协助规则；自定义规则进入高级入口；ruleKey 独立版本 | 同类别并存；已有草案保持历史引用；内置规则正文由服务端固定 |
| 三种 URL | 身份地址在账号接入，导流目的地在导流管理，帖子地址在回执 | 普通模板无须目的地；导流模板必须有有效目的地；登记不证明可达 |
| 任务及异常 | 同一任务视图：真实事件终端、准备快照、回执、截图与人工输入；异常只是过滤视图 | 事件不是模拟进度；诊断入口移到接入状态；任务完成不等于公开成功 |

## 单次账号接入任务

`POST /onboarding` 仅对已登录 Web 操作者开放，校验项目、账号授权、指定真机、设备接管和在途任务。已有绑定不能通过创建模式增建另一身份。

- `verify`：必须提供完整预期 ID，Agent 观察类型、准确名称、完整 ID 和管理权限。不能从 `profile.php` 字样推断是 Page。
- `create`：明确确认本次操作依据，提供所属登录账号唯一标识、名称及 FB 类别；Agent 必须先核验父登录身份一致，才允许创建一个 Page／频道。不能创建个人／Google 登录账号、轮换登录身份或发布内容。
- App 缺失走已批准的可信安装目录；缺密码／验证码走原有专用临时凭证协助；普通资料走原任务内人工协助，回复后重新观察。
- 只有 scoped onboarding 策略允许一次 `create_identity` 类动作；普通人工同意不扩大权限，通用 assistance 会话入口不能申请创建权限。
- 不确定、取消或重启不自动再次创建。存在未决创建时只能先核验已有身份，不通过重新发起任务重置创建预算。
- 成功要求结构化事实符合平台 ID 格式、名称、身份类型、管理权限、无发布，并实际归档真机截图。缺失任一条件记 unknown，不能自动建立绑定。
- `POST /onboarding/bind` 仅接收已核验任务，24 小时内重新确认当前授权；不覆盖另一身份的已有绑定。创建、核验、绑定、发布是不同事实。

Agent 负责 UI 理解和决策；运行时负责授权、期限、互斥、幂等、保密和证据校验。按钮文字护栏不能证明对所有 App 版本具有完备语义识别，须真机覆盖实际路径，未验收不推广为全场景成功。

## 验收及未完成能力

统一用 Playwright 操作真实 Web。`scripts/verify-operations-consolidation.mts` 从表单创建测试项目，登记授权、真实选择上传视频、确认分配、生成无导流草案、验证规则并存、任务空态与移动布局，再经 Web 退出测试项目；不通过 API/数据库写入绕过界面。

单元／运行时测试覆盖原子批次、规则独立版本、可选导流、账号创建边界与证据缺失，不能代替真机验收。真实 Page 创建及 YT 频道核验须以指定合法身份、管理权限及平台事实为依据；不创建未指定的测试资产凑验收。

外部 AI 策略提供方、自动语义剧情去重、完整连载自动排期、自动指标采集、在线短链仍非本轮已完成能力。参数录入简化不消除这些外部接入边界。
