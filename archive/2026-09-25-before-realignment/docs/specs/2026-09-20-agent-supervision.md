# Agent 主导的统一 Web 执行闭环

用户已确认的开发目标：Web 下达目标 → Artemis 判断执行 → 必要时反馈与人工介入 → 重新核验 → 成功、失败、未知、取消或过期。状态记录和安全工具不替代 Agent 的页面规划。

## 合同与规则

- 业务任务与执行 trace 分离；任务固定设备、平台、预期身份、内容版本、授权范围、策略版本和期限。恢复不得绕过原授权、排期与发布防重复。
- 人工协助支持 password、otp、content、approval、manual、clarification。密码／验证码仅一次领取、短时内存保存，不进入模型参数、普通日志或 SQLite；非机密回复进入协助单审计。
- 一个任务可以顺序提出不同协助单，但不允许并发协助、不允许以新待办重置凭证次数。每张协助单绑定证据、trace、账号和期限。
- 等待、人工接管、取消、失败、过期、重启均禁止 Agent 修改设备。人工回复后进入重新核验阶段，不直接标成功。运行时不可达时拒绝动作。
- Agent 可解释失败并请求帮助，不能通过通用 Shell／ADB、辅助 Agent 或未纳管扩展绕过控制入口。
- 可信 APK、素材字节校验是基础工具；Agent 决定是否需要。素材／文案变更需重新审查，不替换已经批准的正式发布内容。
- Page／频道初始化需明确归属、名称和创建授权；错配纠正需单独批准，不允许运营轮换或封禁换号。法定条款、敏感权限、CAPTCHA 按人工处理边界执行。
- 发布后超时、进程退出或缺少结构化结果记 unknown，不重发。任务 completed、输入成功、登录成功、身份通过、发布成功是不同事实。

## 最小落地与验收矩阵

1. 失败后硬停止，运行时离线拒绝动作，原始执行出口受控，敏感凭证不进入日志。
2. Web 多轮协助：密码→验证码；补充资料→重新观察；人工接管→交还→重新核验；取消、过期、重启与迟到回复。
3. Web 保留策略快照、任务时间线与结构化诊断；未知结果不得显示成功，纯观察任务不启动应用、不登录、不发布。
4. 单元与 HTTP 覆盖错设备、错身份、重复消息、次数预算、审批与回复不自动扩大权限。
5. 真实 Web 发起只读任务，真实 Agent 请求人工协助，Web 回复，原实例继续观察并结束；不对真实账号制造封禁、重复错误登录或公开发布。
6. 安装、创建、错配纠正、发布结果未知等破坏性或外部影响场景先用受控替身验证；真机凭证／验证码、账号归属等不具备时记录阻断，不虚报通过。

实现进度与真实证据另见本批验收报告；本规格不是完成声明。持久化跨进程自动续跑、自动收取邮箱／短信、自动申诉和生产公开发布不因本批诊断入口而视为已接入。
