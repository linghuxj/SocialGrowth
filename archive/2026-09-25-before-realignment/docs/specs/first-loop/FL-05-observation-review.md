# FL-05：观察与基础复盘

状态：受控观察与基础复盘实现及自动化验收已完成；真实供应商字段、权限、粒度与延迟仍待对应接入证据。

## 问题陈述

演示报表和综合评分不足以证明真实数据可得或原目标改善；主指标缺失、来源切换和无改善需要可解释的结果，不能一律填零或强选赢家。

## 解决方案与完成标准

- [x] 观察记录保留来源、单位、范围、时间窗和目标/策略版本，区分真实零、缺失、延迟和无权限。
- [x] 来源变化对用户可见，核对原比较是否成立；不静默换主指标或按公开互动评分宣布原目标胜出。
- [x] 基础复盘区分必需工作未完成、合格试验无改善/证据不足及有证据的限定改善。
- [x] AI 分析引用实际可得事实和限制，人工确认后续动作；新的试验回到草案/批准，不自动扩大。
- [x] 目标变化后旧报告仍引用原目标与来源；受控数据明显标记，不混入真实经营指标。

## 用户故事

1. 作为分析人员，我希望区分数据零值和缺口，以便判断哪些结论可信。
2. 作为运营人员，我希望无改善或证据不足时也有如实的复盘与下一步，以便不被强制赢家误导。
3. 作为项目负责人，我希望历史数据保留原目标和来源，以便变更后仍能查验当时的判断依据。

## 实施决定

以 G-05 的事前主指标、观察窗、可比条件和证据判据为准；复用 design-v1 服务边界及 F 样例。数据适配器在其公开输出边界统一可用性，不假定供应商能提供全部私有指标。基本复盘属于首批，系统化试验管理仍是后续深化。

## 测试决定

覆盖 C-07/10/12、F-01～06；基于适配器/评价公开输出断言缺失不填零、来源切换可见、必需工作缺失不通过、完整无改善不自动推广。真实供应商要另附字段/权限/定义/粒度/延迟的实际证据，合成样例只验证内部语义。

以上为待执行的应用验证计划；此前通过的文档/样例结构检查不能替代。本任务完成记录应附实现提交、实际测试命令与结果、受控及真实接入范围。
