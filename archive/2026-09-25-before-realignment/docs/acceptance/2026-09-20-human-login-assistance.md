- 运行时新增认证的人工待办、截图、一次性密码提交／领取、取消、过期、结果截图和重启中断处理；密码不进入 SQLite 或既有 WS 消息日志。

- Artemis Operator 增加 `human_password_input`。这是本项目维护的下游小补丁，不是上游原生能力；密码不进入模型参数和结果。页面判断、聚焦、登录点击和结果判断仍由 Agent 完成，不是 Facebook 坐标导航脚本。

- 修复 Artemis 嵌套 result 的解析；无法解析不补造成功事实。单任务途中异常仍保守记 unknown，不重发。
- 记录 `input_completed` 和最终 `LOGIN_REJECTED` 等结果为两个独立事实，不把输入成功当成登录成功。

## 当前阻断与处理

1. **认证阻断**：Facebook 已因错误密码要求验证码。后续由账号负责人用有效凭证和平台要求的验证完成认证；不再尝试随机密码。不应把真实密码发到聊天或 Git。
2. **验证码能力边界**：目前安全输入扩展仅处理原生受保护密码字段，2FA／验证码／CAPTCHA 转人工停止；验证码字段输入与同任务恢复尚未实现，不能宣称所有登录挑战全自动打通。
3. **业务账号边界**：本次是个人 Profile 诊断，业务发布仍要求正确 Page／频道及真实授权。不得通过伪造权限记录绕过准入。
4. **下一次成功链路验收**：在正确业务账号和有效认证条件具备后，以新任务验证同任务登录恢复、身份核验、素材／文案／参数准备和发布前停止；最终内容提交仍需独立授权。

扩展部署和维护见 `integrations/artemis/README.md`；真实验收脚本为 `scripts/verify-human-login.mts`，禁止未经授权重复运行登录测试。
