# @socialgrowth/ai-engine

SocialGrowth 核心 AI 策略生成与规则推理中枢。

---

## 一、 服务定位

作为独立的服务层（Service），将 LLM 模型调用与业务逻辑解耦，独立承载前 3 个月系统的四大核心智能处理职责：
1. **Tag-to-Profile 智能匹配与独占锁控制**：
   - 先核验权利、版本/独占归属、语言、剧情与目标账号资格，再对合格内容按题材和受众匹配排序；无合格候选时形成素材缺口，不选不合格的最高分内容；
   - 按 [G-03 系列业务规则](../../docs/handoff/2026-09-19-business-flow-proposal.md#8-逐项确认与整改记录)区分内容独占归属与发布结果：语言版本共用归属，同一内容只选一个版本发布一次，已有发布历史后原账号也不得另发一条；审批后取消、全部版本均未提交且无发布历史、旧安排失效时可释放，新分配重新审核；进行中、已提交或结果未知不释放。G-03c 允许主体不同的必要少量剧情衔接，经人工核对并记录依据后才可按不同内容分别发布，不能自动按重叠秒数放行。此处为业务要求，文档更新不代表已实现；
2. **AI 运营策略拟定与排期节奏**：
   - G-04 已确认：仅在已验证规则及有效授权范围内自动处理日常安排；新策略先生成小批试验草案，记录假设、范围、发布量/成本、期限及停止条件，经人工批准后执行。启动批准不等于策略已验证或可扩大；
   - 按受众时区与实际执行时间生成排期草案，遵守获批的账号整体频次及滚动窗口；内部试点频次不是官方安全上限，过期计划重审，不自动补发；
   - 针对选定切片生成差异化文案、挂载短链、时段与互动评论策略；
3. **经验规则引擎**：自然语言经验的结构化解析、三级规则冲突检测（官方规则/内部规则/假设）与版本管理；
4. **数据可用性与策略评价（G-05）**：按获批主指标、比较单位及观察窗评价，来源变化和缺失原因可见；无改善或证据不足可形成完整复盘，必需工作缺失不算闭环通过。不静默改主指标或以统一加权分强制选赢家，闭环验收、策略有效与推广授权分别处理。

## 二、 目录结构

```
services/ai-engine/
├── prompts/              # 系统级提示词模板 (策略生成、规则解析、标签提取)
├── src/
│   ├── types.ts          # 数据契约定义 (包含第三方数据接口与锁状态)
│   ├── matching-engine.ts# 切片与账号标签加权匹配与独占锁管理
│   ├── rule-parser.ts    # 经验规则结构化与冲突检查
│   ├── ab-evaluator.ts   # A/B 策略评估与公开互动降级打分算法
│   └── index.ts          # 统一服务导出 (含批次预生成与审核流)
└── package.json
```

## 三、 成本核算与独立优势

- **预算隔离**：本服务所有对外 API 调用（如通义千问、DeepSeek、Claude 等）均由月度 2–5 万元的“产品 AI 调用”专项额度核销；
- **免除 UI 耦合**：Web 控制台通过 REST/gRPC 调用本服务，保证核心策略逻辑的高内聚与可测试性。
