# Web 运营可用性审计：从受控验证转向实际业务工作台

日期：2026-09-20。核查版本：`9951400`。状态：**已完成首轮整改与 Chrome 复验；部分生产接入项继续待办。**

## 2026-09-20 整改标注

本轮已将运行时收敛至首批闭环状态，删除旧静态数据库、旧成果总览及账号矩阵、素材、策略、短链、风控、Artemis、实验、数据库和研究演示视图。新导航按运营任务组织，并补入当前项目、账号选择、显式授权有效期、逐草案批准条件、排期、数据可用性、复盘完整性和审计时间线。页面持续标示本地受控数据及外部执行器未配置，不再提供可伪造设备或发布成功的操作。

状态说明：UX-01、02、03、04、05、06、08、11、12、13、14、15 的本地 Web 问题已修复并通过本轮 Chrome 复验；UX-07 已改善身份、版本、权利和归属显示，但媒体预览及重叠审核仍待接入；UX-09 已补批准、排期和 unknown 边界，真实执行、恢复和退出操作仍待外部链路；UX-10 已保留输入并提供页面顶部错误摘要，就地逐字段错误和跨刷新草稿仍待优化；UX-16 仍是生产阶段门槛。未将这些剩余项误标为完成。

## 结论与口径

当前 Web 尚不能作为真实运营管理平台验收通过。需要系统调整导航、项目上下文、统一数据源、审批信息、执行异常处理和复盘界面；保留并复核已有领域规则、执行契约、测试及基础 UI 组件。没有证据支持推倒整个技术栈或重新讨论已批准商业目标。

用户已说明没有真实接入环境，并询问能否模拟真实账号与内容。因此本次采用“真实业务情境、明确标记的演练数据”的评估方式：现场操作实际 Chrome 页面，核对当前源码和已批准业务规则，没有把演练账号、文件引用、历史样例或按钮成功文案当作外部真实证据。

本轮实际新增并激活了 `【演练】星河短剧｜英语受众首发` 项目；执行了一次缺参批准拒绝、一次旧设备演示 Ping、素材搜索和未保存输入的跨页面切换。没有真实账号登录、公开发布、供应商调用，也没有创建整套多客户演练库存。后文场景矩阵是下一轮验收设计，不能计作已经执行通过。

本轮截图均重新采集于 Chrome，已逐张打开检查；证据保存在[截图与逐步报告](../../artifacts/reports/2026-09-20-web-operations-audit/README.md)。浏览器中旧测试记录只用来验证当前页面是否能检索它们，不沿用上一轮测试结论。

## 需要调整到什么程度

建议进行 Web 产品结构和数据接线的整体调整，按业务链分段替换。具体包括：

- **重做**：默认首页、项目上下文、跨模块对象导航、审批决策摘要、执行与异常处理、观察复盘、演练/正式环境呈现。
- **改造复用**：账号/素材表格、搜索和筛选、详情面板、状态标签、基础按钮/输入组件；绑定新统一模型并补缺项。
- **保留并复核**：已批准 G-01～G-05、内容身份与归属、发布事实、版本失效、unknown/迟到回执、状态审计及已有自动化用例。保留不代表已经适合生产，需要覆盖本轮新发现。
- **归档或停用**：旧成果大屏、写死运行日志、假成功操作、与当前决策冲突的自动晋级公式。不能只在侧栏挂“旧演示”而允许其充当正常操作入口。

推荐导航：运营首页 → 项目与授权 → 内容库存 → 策略与排期 → 执行与异常 → 导流入口 → 观察与复盘。设备诊断、接入设置、审计记录作为支撑功能。项目上下文贯穿全部页面；人员角色按现有权限设计，不新增岗位/审批层级。

## 贴近真实业务的演练资料设计（尚未全量创建或执行）

建议准备 2 个虚构客户/项目、4 个虚构账号（每项目各 1 个 FB、1 个 YT）、2 个模拟设备绑定；这些数字仅用于验证隔离和边界，不是商业规模目标。

准备 6 个内容身份、8 个文件版本：A 的两语言未发布身份、A 的两语言已发布身份、A 的权利过期身份、A 的剧情重叠待核对身份、A 的发布结果未知身份、B 的独立可用身份。使用自有/获准的测试媒体或明确合成的短片，实际文件生成真实校验值。没有媒体时只可验收元数据输入，不能标记视觉内容审核通过。

准备 2 个客户入口及历史版本、固定基准时间、UTC 与业务时区、项目范围内审批记录和模拟回执。数据及文件统一标记 sandbox，禁止把虚构用户名映射到真实社媒账号。演练适配器应走同一业务接口和状态机，不另写只更新绿色标记的展示逻辑。

## 整改顺序与交付检查

1. **先纠正可信性**：停止旧假成功路径，统一数据源与演练标识，对齐指标/推广语义；核对同对象在页面、服务、统计、导出的一致性。
2. **形成一条可操作的业务链**：从项目选择到素材审核、批准排期、执行异常和复盘，逐段完成操作与证据呈现。通过 S-01～12，不以组件截图代替业务任务。
3. **再优化运营效率**：列表筛选/排序、批量逐项结果、草稿恢复、稳定 URL、键盘与缩放、长列表及日志检索，按实际工作量验证。
4. **真实接入验收**：取得授权项目、测试媒体、真机/Agent、真实入口与指标后，验证实际回执与公开证据，记录真实操作人和数据时间。正式启用前单列验收。

本轮已完成首轮结构整改并保留原始审计证据。生产接入、媒体预览、异常恢复、退出和真实数据场景仍须按编号继续记录提交及复验结论，不能用本地 Chrome 通过覆盖外部验收状态。
