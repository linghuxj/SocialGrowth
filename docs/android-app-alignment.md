# 设备提供者 Android App：设计、规范与业务流程对齐

更新：2026-09-29。状态：核心方向已确认、按模块进入实施交接，依据当前基线 R-001～R-156；AND-001～AND-009 已确认。本文件区分已确认业务、由其推导的设计建议和待确认选择。页面细化见[Android 页面与交互规格 0.8](android-app-page-spec.md)，尚未实施客户端或完成实机验收。

## 1. 范围与依据

本 App 服务受邀设备提供者，帮助其接入专用执行手机、处理本人需要配合的事项、逐台暂停／请求恢复／永久退出，并查看本人基础分佣。不是内部运营工作台，也不是媒体发布任务编辑器。

- [需求基线](current-requirements-summary.md)：尤其是 R-121～R-130、R-133，以及 R-120 的基础分佣边界。
- [业务流程](business-workflow.md#设备接入)：首次接入、恢复及退出的既定行为。
- [技术设计](technical-design.md)：实现建议及待验证条件，不自动成为产品确认项。
- [业务术语](../CONTEXT.md)：统一用户、设备、协助和恢复的含义。
- 使用 grill-with-docs 所引用的 grilling 与 domain-modeling 方法：调查事实、逐项讨论有实际影响的取舍，确认后同步记录；不重新询问已解决事项。

根目录 DESIGN.md 当前专用于 Web 运营工作台。Android 的页面结构、视觉与组件规格单独形成，不直接套用桌面表格、导航或尺寸。视觉方向已按 AND-006 选定，见[Android 设计规范](design/android/DESIGN.md)；客户端技术栈和支持机型仍未在本轮锁定。

## 3. 管理入口与执行手机（AND-001 已确认）

2026-09-28 用户选择“允许日常手机仅管理：登录不会自动接入执行；专用手机分别完成授权”，业务确认同步为 R-134。提供者可以在日常 Android 手机上登录同一个 App，集中查看本人设备和分佣，并逐台暂停、请求恢复或永久退出。

| 选项 | 使用方式 | 取舍 |
| --- | --- | --- |
| A，已选择 | 同一个 App 可仅用于管理；明确选择并完成本机接入后才成为执行手机 | 便于多设备日常管理，减少为查状态而触碰运行中的手机；需要明确管理登录、设备接入和跨设备操作对象 |
| B | 首期仅在专用执行手机使用；可查看本人全部设备，操作仅针对本机 | 缩小操作入口；暂停或恢复其他手机时需使用对应手机，故障手机上的自助能力受实际状态限制 |

该选择不表示日常手机参与执行，不改变“执行手机必须专用”，也不授予提供者远程屏幕操控或内部运营权限。仅管理的手机不因登录而要求执行用途的 Tailscale 或调试授权；新增执行手机须单独进入接入流程。管理入口的实际网络可达性仍须验证。

由此细化：本人设备列表与“本机是否接入”分开表达；跨设备操作始终显示目标设备；另一台手机发出的控制请求不能代替目标手机已停止或已恢复的确认。登录与执行资格分开，新增设备按 AND-002 扫码关联。

### 新增执行手机采用管理手机扫码关联（AND-002 已确认）

2026-09-28 用户回复“按照建议”，选择新执行手机展示关联码，由已登录的管理手机扫码确认提供者归属；业务确认同步为 R-135。相较每台执行手机重复登录，该流程减少用户凭据的重复输入，日常管理入口与执行接入继续分开。

扫码只完成用户与设备的关联，不代替本机必要授权、条件检查、运营分配及初始化核验。首期不因本次确认自动增加“每台执行手机直接登录”的备用流程；扫码不可用的处理路径待实际设计与验证，不擅自绕过关联校验。

根据该决定形成以下交互细化建议，无须把每个按钮重新作为业务选择：

| 步骤 | 执行手机 | 已登录的管理手机 | 反馈与继续条件 |
| --- | --- | --- | --- |
| 1. 准备关联 | 明确选择“将本机接入执行”，展示本机信息及关联码 | 在本人设备入口选择“添加执行手机” | 显示接入的是专用手机；仅安装或打开 App 不自动关联 |
| 2. 扫码核对 | 等待关联确认 | 扫码后展示目标手机识别信息、当前提供者身份，由用户确认 | 扫描成功不等于已经关联；确认前可取消 |
| 3. 确认结果 | 显示关联进展及实际结果 | 以同一关联结果新增设备记录 | 未取得结果时显示待确认，不提前显示成功或创建第二台设备 |
| 4. 本机准备 | 引导配套安装、必要授权和设备检查 | 展示“已关联，待完成接入”及进展 | 系统授权在目标手机按实际允许的方式完成，管理端确认不能代替 |
| 5. 运营与初始化 | 按所需事项配合 | 显示等待运营分配、初始化及核验的事实 | 全部执行条件满足后才显示可接任务 |

关联码建议短时有效、单次消费；过期可重新生成，已消费的码不能关联给另一提供者。重复扫码或响应丢失后重试应返回已有结果，不重复建设设备关系。已有关联的设备不得凭新码直接覆盖归属，永久退出后的再次加入仍走既定重新接入与授权流程。具体期限、校验机制和设备识别方案由后续设计确定并验证，不把上述设计要求描述为已实现能力。

设备关联码与邀请凭证、系统调试配对码分别命名和呈现：关联码解决“这台手机属于哪个提供者”，不能代替用户受邀资格或中心调试授权。执行手机完成关联也不意味着它获得提供者完整的管理登录会话；执行端本机暂停已按 AND-008 明确，恢复和永久退出仍在已登录管理手机处理。

### 邀请码与链接注册（AND-007，按 R-152 修订）

2026-09-28 的 R-138 原为逐人一次性邀请；2026-09-29 用户明确选择同一邀请可供多人注册，次数上限与有效期可配置，不预绑定手机号、不增加逐次人工注册审批。邀请码与链接共用同一份邀请的额度；用户验证自行选择的手机号，凭未撤销、未过期且有名额的邀请完成首次注册。

系统验证邀请持有资格及所填号码，不核验是否为原计划受邀自然人；被转发的有效邀请也可能被其他持有人使用。注册成功才消耗一个新提供者名额，最终注册与扣减保持原子一致；重复提交、响应丢失、已有身份登录及新增设备不重复消费。运营可查看名额及注册进展，撤销或重新发放；邀请失效不撤销已注册身份或设备状态，各提供者保持独立权限范围。

注册来源及创建运营逐提供者记录，分配前联系人沿用 R-143。具体参数与发送通路在实现时落实；本轮仅更新设计，没有生成可用邀请或发送短信。

### 首页设备与协助优先（AND-003 已确认）

2026-09-28 用户选择“设备与协助优先：先处理设备问题，分佣单独查看”。默认首页优先展示本人设备状态及需要本人配合的事项，分佣放在独立入口；该选择不改变分佣口径，也不新增需要用户逐条审批的执行任务。

相较分佣概览优先，该安排便于先发现掉线、待授权等问题，并明确本人需要做什么。处理后待复核、等待运营等进展应与需要本人行动分别表达，避免反复催促用户处理无权解决的问题。

根据该选择，建议主导航采用“设备／分佣／我的”，设备首页按需呈现本人协助、处理后进展及设备列表；具体导航标签、卡片与视觉样式为设计建议，未单独确认。页面内容、控制反馈、跨端核对与可访问性要求已写入[页面规格](android-app-page-spec.md)。

### 手机号＋短信验证码验证本人（AND-004 已确认）

2026-09-28 用户选择“手机号＋短信验证码：同一手机号对应提供者身份，需要接入短信发送服务”，业务确认同步为 R-136。该方式用于受邀注册、日常登录以及仍能使用原手机号时更换管理手机的本人验证；邮箱验证码方案未采用。

手机号验证不代替邀请资格，未受邀不能自行注册；已有提供者在新管理手机验证同一身份后访问原有设备及记录，不另建提供者。登录不把新管理手机接入执行，也不自动解除原设备的暂停或退出。

邀请方式按 AND-007／R-152 已确定为多人可用、次数及有效期可配置的凭证，不预绑定手机号。原手机号不可用按 AND-009 人工核验后换绑；主动更换仍可用号码的流程、短信服务及支持发送范围尚未确定；不凭新手机号直接迁移旧设备或分佣。验证码失效、重发和错误提示等交互建议见页面规格，不将具体限额和供应商写成已选方案。

### 原手机号不可用时人工核验后换绑（AND-009 已确认）

2026-09-28 用户选择“运营人工核验后换绑：保留原身份，需人工处理”，同步为 R-140。首期从联系原邀请运营开始，先核验原提供者身份，再验证新号码并换绑，回到原设备与分佣记录。

不把新手机号验证当作原身份证明，也不让提供者重新注册后直接认领旧设备。人工核验材料和受控办理方式仍需落实；帮助页只说明流程，不能因打开页面便显示“已提交申请”。旧号码尚可用时换管理手机继续沿用原号码短信登录，不要求走人工找回。

## 4. 共用业务流程及页面反馈建议

### 执行手机无需再次登录即可暂停本机（AND-008 已确认）

2026-09-28 用户选择“允许本机暂停；恢复和退出在管理手机处理”，同步为 R-139。已关联执行手机的现场人员可以直接打开 App 暂停本机，不要求再次验证完整管理身份；用户接受能解锁并打开该 App 的人也可触发停用的取舍。

本机身份只用于接入、本机必要状态与协助及本机暂停，不扩展为管理其他设备或查看分佣。恢复、永久退出及完整管理继续由已登录管理手机处理；不因已扫码把用户会话复制到执行手机。

本机暂停复用既有控制记录和停止边界，不创建自动解除的新“本地维护模式”。离线时本机可以记录请求，但中心是否受理、手机操作是否停止须按证据分别呈现；断网强停能力不由本次选择推定。暂未确认停止时不提示可以开始现场处理，重连和旧恢复结果不覆盖更新的暂停。

### 用户自助暂停后现场处理（AND-005 已确认）

2026-09-28 用户选择“用户自助暂停并处理：明确停止后现场操作，处理完主动请求恢复”，业务确认同步为 R-137。正常流程为“开始现场处理 → 请求暂停指定手机 → 等待停止确认 → 本人现场处理 → 明确请求恢复 → 系统复核”。

不将每次现场协助交由运营预先协调或审批。用户可以直接停止使用并处理必要事项，运营仍处理超出本人权限的问题；不能把打开 App、返回页面、提交说明或网络重连当作恢复同意。

“开始现场处理”是既有临时暂停在协助场景下的明确入口，不另外建立绕过暂停、授权和同机互斥的新执行模式。用户完成处理后主动请求恢复，通过复核且没有其他阻断才恢复日常任务；查看或保存处理事实本身不解除暂停。

断网、撤权或远程接管尚未交还时，按实际证据表达待确认和协调状态，不伪记已取得独占操作条件。系统不能保证阻止实体手机被直接操作；发生未确认的现场操作后，须以实际手机状态及未决结果复核，不沿用旧进度盲目接续。

以下业务结果来自既定基线；页面命名、分组和文案为设计建议，按已确认入口继续细化。

| 流程 | 进入与推进 | 页面应表达的事实 | 完成条件 |
| --- | --- | --- | --- |
| 首次接入 | 邀请校验及注册 → 专用手机关联 → 配套及授权 → 自动检查 | 当前手机、已完成步骤、未完成原因、下一步由本人还是运营处理 | 检查、运营分配和初始化核验均通过，才可接日常任务 |
| 新增手机 | 执行手机展示关联码 → 管理手机扫码确认 → 本机授权及检查 → 运营分配与初始化核验 | 已有设备与新增设备明确分开；关联成功不等于就绪，也不继承另一台的授权 | 该手机独立符合条件 |
| 等待运营 | 手机检查后等待首次项目与账号分配 | 等待运营处理；不把用户无权处理的分配问题包装成“继续授权” | 运营确认后进入初始化，不直接跳为就绪 |
| 本人协助 | 问题要求本人处理网络、授权或必要现场步骤 | 具体手机、要做什么、如何检查以及处理后的进展；仅展示必要信息 | 系统复核通过；用户提交“已处理”不等于成功 |
| 临时暂停 | 用户针对指定手机提出暂停 | 请求记录、中心受理、执行端停止确认和未决情况分别表达 | 停止手机业务操作得到确认；未知发布事实仍保留 |
| 恢复 | 用户请求恢复 → 有效授权内核验 → 按结果接续 | 正在检查、需本人配合或等待运营；不使用瞬间切换成功的开关反馈 | 复核通过且没有其他阻断，才继续有效日常任务 |
| 永久退出 | 用户自行退出 → 停止使用 → 运营交接清理 | 退出已受理、旧端停止是否确认、清理是否完成；退出不等于删除平台内容 | 不再恢复日常派发；未决结果与未完成清理分别跟进 |
| 分佣查询 | 查看本人记录及核对依据 | 账号标识、承接期间、收入依据、适用比例和金额状态；缺失显示待核对 | 查看或核对不触发付款，不把未知金额当作零 |

首次接入中断后建议允许回到已完成步骤继续，但旧检查结果是否仍有效需重新核对。进入系统设置或配套 App 后返回，不仅凭用户点击“已完成”判定授权成功。引导的具体路径及可自动检查内容按支持机型验证。

## 5. 状态表达规范草案

### 首页采用第 1 版行动提示布局（AND-006 已确认）

2026-09-28 用户对首页三版视觉候选回复“1”，选择聊天中第一张生成结果，即[首页行动提示原稿](design/android/home-action-v1.png)。映射以已保存的实际显示顺序为准；未选择第 2 版设备行内展开或第 3 版协助进展布局。

保留浅色背景、上方浅琥珀协助提示、下方白色设备列表、蓝色主动作及设备／分佣／我的底部入口。协助区与列表分开，首页仍服务于本人设备与协助优先；不因选择图片扩大任何运营权限。

后续以该方向修正“确保正常运行”等过度承诺文案、让现场操作提示先指向停止确认，并将分佣图标改为记录语义。颜色、字号、间距和组件规则沉淀在[Android 设计规范 0.5](design/android/DESIGN.md)，数值为设计建议，不以生成图片冒充精确实现或验收。设备详情及现场协助页沿此方向展开；后续修订图仍须接受业务与视觉核对。

不使用单一“在线／离线”承载全部业务结论。页面可以给出一个主要提示，但详情须保留彼此独立的事实：

| 事实 | 示例 | 不能推出的结论 |
| --- | --- | --- |
| 接入进度 | 待授权、待检查、待运营分配、初始化核验中 | 已注册或已分配不能推出可执行 |
| 连接与授权 | 管理连接、调试授权、所需业务网络的实际检查及时间 | 网络连接正常不能解除提供者暂停 |
| 提供者意愿 | 参与、已提出暂停、已请求恢复、已永久退出 | 恢复意愿不能补回已撤销授权 |
| 操作执行进展 | 请求已记录、中心已受理、等待停止确认、停止已确认 | 中心受理不能代替旧端停止证明 |
| 当前阻断 | 本人需配合、运营处理中、系统正在核验 | 用户无事项可做不代表设备已就绪 |
| 信息新鲜度 | 最近确认时间、当前无法更新 | 缓存中的正常状态不能当作当前事实 |

建议动作使用“暂停这台手机”“请求恢复”“永久退出此设备”，在确认与反馈中持续显示设备名称和稳定识别信息。恢复反馈用“正在检查，暂未恢复日常任务”；失联时表达最后已知事实与待确认部分，不承诺立即停止成功。

界面还须区分“我的全部设备”与当前操作目标；针对单台的动作不默认变成批量操作。颜色辅助说明状态，文字同时给出原因、下一步及处理责任。首页层级、导航和组件起点已记录在页面规格与 Android 设计规范，具体数值待原生验证。
