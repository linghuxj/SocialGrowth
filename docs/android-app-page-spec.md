## 1. 页面结构与使用边界

提供者日常在自己的管理手机上发现问题、查看进展和发起逐台控制；专用执行手机承载本机接入、授权与必要现场协助。一个 App 支持两种使用情境，登录、关联本机和取得执行资格分别处理。

建议登录后的主导航为“设备／分佣／我的”。默认进入设备首页，本人协助直接放在首页及对应设备详情，不另建一个空泛的消息中心。“我的”只承载本人身份、接入说明及必要账号帮助；采用手机号＋短信验证码及按 R-152 配置次数及有效期的邀请，原号码不可用按 R-140 由运营人工核验后换绑；按 R-141 不继续扩展完整 App 内找回能力。

| 页面 | 要回答的问题 | 主要动作 | 进入与返回 |
| --- | --- | --- | --- |
| 首次使用方式入口（AND-010） | 我要管理设备，还是将这台专用手机接入？ | 管理我的设备 → 注册／登录；接入这台执行手机 → 接入说明 | 无既有使用身份时独立显示；未登录不展示其他设备、分佣或运营资料 |
| 设备首页（AND-013／023／025） | 哪台需要我处理，其余设备怎样？已退出的设备如何查看？ | 处理本人协助、查看设备、添加执行手机、展开已退出设备折叠区 | 默认入口；返回保留列表位置与筛选；无多余退出登录按钮（收拢至“我的”） |
| 添加设备／扫码确认（AND-014／015） | 正在把哪台手机关联给谁？支持手动输入吗？ | 扫码或手动输入设备关联码、核对身份与选填备注名、确认关联 | 管理端设备首页进入；结果关联到目标设备详情 |
| 本机接入引导（AND-015／016／018） | 这台手机还缺哪一步？如何开始参与？ | 展示二维码与手动关联码、逐步引导前往必要设置、重新检查、单次确认开始参与 | 执行端明确进入；中断后按真实进展接续 |
| 本机状态与暂停进展（AND-018～020） | 这台手机当前是否在使用、已准备好还是停止？ | 查看粗粒度使用状态、点击“暂停本机”并在底部确认层二次确认、查看受理和停止事实 | 仅本机身份；无独立参与开关；恢复与永久退出前往已登录管理手机处理 |
| 设备详情 | 当前事实是什么，我能做什么？ | 处理协助、暂停、请求恢复、查看退出入口、修改备注名 | 首页或协助入口进入同一设备详情 |
| 本人协助详情（AND-021／022） | 我具体要做什么，处理后是否通过？ | 查看问题与进展、按引导去执行机处理、自动检查通过后直接在管理端“请求恢复”或“暂不恢复” | 始终保留设备标识；执行机展示步骤与直达按钮，管理端免去手动提交表单 |
| 控制请求与进展 | 暂停／恢复／退出到了哪一步？ | 发起明确动作、查看后续事实 | 从指定设备进入；退出不混用暂停确认页 |
| 分佣列表及详情（AND-024） | 哪笔属于我，依据和处理状态是什么？有总金额吗？ | 仅查看预估参考区、筛选逐条记录、查看核对依据；不显示汇总金额，不触发付款 | 独立入口；不相加为余额 |
| 我的与必要帮助（AND-025） | 当前是谁、怎样登录及接入？如何退出登录？ | 查看本人身份、接入说明、人工帮助方式、退出管理登录（不影响执行手机） | 管理端底部一级导航直达；子页通过底部导航切换，免除冗余“返回设备”按钮 |

### 首次使用方式入口（AND-010 已确认）

2026-10-03 用户选择独立入口方案。首次安装且既未管理登录、也未建立本机接入身份时，先显示“管理我的设备”和“接入这台执行手机”，再分别进入管理认证和执行手机接入说明。用户不必先填写管理注册表单才能找到执行手机路径。该页不将登录、归属关联、系统授权和执行资格合并。

页面内容：顶部品牌与“选择这台手机的使用方式”；管理入口说明“查看本人设备、处理协助事项和查看分佣”；执行入口说明“将这台专用手机接入平台执行”；下方以中性文字解释管理登录不会将本机接入执行。两个入口按 Q-AND-P01-02／AND-010 补充确认采用同等醒目的白色卡片，纵向排列、同样大小，管理在上、执行在下，各含用途说明与进入箭头，整卡可点。画布和强调色沿用既有浅灰与蓝色，具体字句和间距为沿该选择的设计细化。

交互与接续建议：

- 点击用途入口直接进入对应下一页，有轻量按压反馈，不增加选择后再点继续的步骤；下级页面在尚未建立身份时可返回重新选择。
- 首屏展示无需网络请求；不在选择用途时索取手机号或系统权限。需要联网、创建身份和系统授权的动作在对应后续页面说明并办理。
- 有效邀请链接直接进入受邀注册；有效管理会话进入本人设备首页；已有本机接入身份接续原接入进展或本机状态，不每次重新选择。
- 身份过期、验证失败或服务不可用在原身份流程反馈，不通过回退选择页隐式清除身份、解除暂停或恢复参与。
- 不显示管理端底部导航，也不在用途选择页提供已有执行身份与管理身份的切换功能。

以上入口结构与视觉主次已确认，基础交互按既有身份边界细化；尚无该页独立 AI 图稿或原生实现，真实视觉、读屏、字体放大和交互仍待对应阶段验证。逐页访谈进入受邀注册页。

### 首期页面合并与返回约定

按 R-141，以上是页面职责，不要求每个进展对应独立路由。实施分组及完成标准见[当前对应说明](current-implementation.md)。页面实现建议如下，不增加业务能力：

| 共用视图 | 包含的既有状态 | 返回与重新打开 |
| --- | --- | --- |
| 注册／登录表单 | 邀请校验、验证码发送与验证、处理或失败 | 受邀注册与已有账号登录清楚区分；成功到设备首页，空列表可添加专用手机 |
| 管理端关联确认 | 识别、待确认、请求中、结果未知、成功或冲突 | 确认前返回不关联；提交后返回不撤销已受理结果；成功进入原目标详情 |
| 执行手机接入／本机状态 | 关联码、准备、检查、等待运营、初始化、可接任务及本机暂停进展 | 重开按已有归属与实际进展接续；已关联后始终可达本机状态及暂停入口 |
| 管理设备详情及进展区 | 条件明细、暂停待确认、已暂停、恢复复核、退出后的停止与清理 | 从首页与协助进入的是同一设备；返回保留列表位置，重开刷新同一请求结果 |
| 设备协助 | 停止待确认、可现场处理、已提交说明、待主动恢复或复核 | 始终标明目标设备；返回不视为处理完成，重开不重复提交或自动恢复 |
| 明确动作确认 | 请求恢复、永久退出等已有确认内容 | 确认前返回不发送；提交后返回不撤销请求；每次核对目标与最新可用动作 |
| 分佣与我的 | 本人记录列表／详情、身份及必要帮助 | 分佣返回保留筛选；帮助按来源返回；完整账号找回参考图不扩展为首期必做流程 |

加载、空数据、请求处理中、失败和结果未知均在对应视图反馈，不新建“异常中心”。执行端不复用管理端完整底部导航；两端查看同一设备时可以有不同信息范围，但不能对同一请求给出相互矛盾的成功结论。

执行手机扫码关联后仅获得设备侧接入身份，不自动显示本人全部设备及分佣。按 AND-008／R-139，本机入口可无需再次管理登录而请求暂停本机；恢复和永久退出仍在已登录管理手机处理。扫码确认不复制用户完整登录会话，本轮不增加执行手机解锁完整管理入口。

| 能力 | 已登录的管理手机 | 仅具关联身份的执行手机 |
| --- | --- | --- |
| 设备与协助状态 | 本人全部设备，逐台进入 | 仅本机必要状态与协助 |
| 确认新增设备归属 | 扫码后核对并确认 | 展示本机关联码，不代管理端确认 |
| 系统授权与配套准备 | 查看目标进展，不能代开目标机系统权限 | 在本机按系统允许流程操作 |
| 暂停 | 可逐台请求暂停本人设备 | 无需再次管理登录，只能暂停本机 |
| 请求恢复／永久退出 | 在指定设备内明确发起 | 提示前往已登录管理手机，不发起请求 |
| 本人分佣 | 查看本人基础记录 | 不展示 |

未关联的执行手机只进入接入说明和本机关联流程，不因知道设备编号而取得控制权限。以上区分是访问与动作边界，不能仅靠前端隐藏按钮实现。

### 手机号注册与登录（AND-004 已确认）

管理入口使用手机号＋短信验证码，登录后进入同一提供者身份。首次注册按 AND-007／R-152 另外校验运营发放的邀请码／链接及剩余注册名额，不预绑定手机号或增加人工注册审批。页面流程建议：

1. 输入手机号码并明确发送对象；支持的号码范围与区号规则在短信方案落实时确定，不预设全球可用或只支持某一地区。
2. 主动点击获取验证码，展示真实发送结果。已请求发送、已发送和用户收到分别理解，发送失败不显示验证成功。
3. 输入并提交验证码，通过后才建立管理登录会话。验证码错误、过期或请求受限分别给出可执行的下一步，不在普通日志、反馈或证据截图中保留原始验证码。
4. 已有提供者进入原身份和设备列表；新用户仅在邀请校验也通过后完成注册，不能仅凭号码验证开放公众加入。
5. 更换管理手机但仍能使用原号码时，重新验证后查看原设备，原暂停、退出、分配及历史记录保持不变；新管理手机不自动接入执行。

重发间隔、尝试次数、会话有效期及旧验证码失效规则由认证设计明确，当前不编造默认值。验证暂时不可用时保留重试和帮助入口，不自动建立新用户。原号码不可用按 R-140 人工核验本人后再验证新号码，保留原身份及历史；不得用输入新号码直接转移旧设备或分佣。退出管理登录按 R-142 不影响执行手机，结束相应管理访问，保留设备原状态与已受理控制请求。

### 受邀注册的页面与异常（AND-007，按 R-152 修订）

2026-10-03 按 AND-011 确认同页组织：顶部返回、品牌和“受邀加入”标题；同一表单依次为邀请输入／状态区、手机号、短信验证码与获取按钮、蓝色“注册并进入管理”主动作；下方显示“注册不会将本机接入执行”及“已有账号？手机号登录”。手动入口支持填写／粘贴邀请码，邀请链接自动带入同一邀请区，仍需真实校验后才显示通过。不增加独立邀请校验页面。

点击获取验证码前核验当前邀请及手机号；邀请错误在邀请区、验证码错误在验证码字段附近反馈。发送和注册请求分别显示处理中并防止重复点击，网络失败在当前表单处理。最终注册仍重新校验邀请名额与有效性；注册成功进入本人设备首页，空设备时显示添加执行手机入口。此处为已选页面组织及沿既有业务规则的交互细化，尚未更新原生实现和 AI 图稿。

运营创建次数上限及有效期可配置的邀请 → 用户从链接进入或填写邀请码 → 校验有效性及剩余名额 → 自行输入并验证手机号 → 最终注册并扣减名额 → 进入本人设备首页。同一份邀请可供多人注册，链接与码共用额度。链接如何带入 App、安装后如何接续及具体发送渠道由实现方案验证；不假设打开链接必然静默安装或自动登录。

建议邀请入口明确区分“受邀加入”和“已有账号登录”。尚未注册时不显示本人设备、分佣或公司资料；已有账号使用手机号登录回到原身份，不要求为新增手机再次注册。邀请和验证页面返回保留非敏感进度，验证码及邀请凭证不进入普通日志、截图或 AI 输入。

| 当前情况 | 页面反馈／动作 | 不能推定的结果 |
| --- | --- | --- |
| 邀请尚未校验 | 正在核对或需要填写邀请，提供已有账号登录入口 | 不能只因页面打开就标记已受邀或已注册 |
| 邀请有效，手机号未验证 | 邀请已校验；填写手机号、获取验证码、注册并进入管理 | 邀请通过不代表手机号已验证 |
| 邀请过期或已撤销 | 无法用此邀请加入；联系原邀请运营重新获取 | 不继续使用旧邀请，也不将所有登录都禁止 |
| 邀请名额已耗尽 | 无法再注册；已有账号可正常登录，新用户联系邀请运营 | 不展示其他使用者资料，不阻止原有身份登录 |
| 已有人注册但仍有名额 | 有效期内仍可供另一新提供者验证手机号后注册 | 不因首次消费就把整份邀请标记失效 |
| 验证码发送失败／受限 | 显示可核对原因及允许的后续动作，保留非敏感输入 | 不视为验证码已送达或验证通过，不虚构倒计时 |
| 验证码错误／过期 | 在字段附近反馈，按实际规则重新验证 | 不通过前不创建管理登录会话 |
| 最终提交时邀请失效或名额耗尽 | 保留说明并重新核对邀请，不完成首次注册 | 不沿用之前页面上曾显示有效的旧检查 |
| 注册响应丢失 | 核对同一次注册结果，必要时通过已验证身份进入原账号 | 不要求重新邀请来创建第二个提供者 |

邀请生成／发放、校验、名额使用及注册结果分别留痕。按 R-152 不绑定预期号码、不增加注册审批；持有有效邀请并验证自选号码即可注册，因此转发的有效凭证也可能被他人使用。最终提交原子核对过期、撤销及剩余名额，注册成功才扣减；最后一个名额只允许一个新提供者成功。重复请求返回原结果，已有身份登录及新增设备不扣名额，各提供者记录来源和创建运营并保持数据隔离。

表单点击提交时先就近指出缺失或格式错误的字段，输入条件满足后才发送注册请求；客户端输入检查不代替服务端邀请和验证码核验。请求处理中避免重复提交，响应丢失时核对原结果。

注册成功页或初始设备首页只提示“可以添加专用执行手机”，不能直接显示“设备已上线”。具体有效期、验证码参数、服务商和发送资源待落实，不由静态稿中的示例决定。

### 手机号登录与默认管理入口（AND-012 已确认）

未登录且没有邀请链接时，点击“管理我的设备”默认进入手机号登录；新用户通过“收到邀请？受邀注册”进入注册，有效邀请链接仍直达注册。已有有效管理会话直接回设备首页。

登录页沿用注册表单视觉，建议依次显示手机号、短信验证码与获取动作、“登录并进入管理”；“原手机号不可用？”从未登录页进入人工核验帮助，按 R-140／141 说明联系原邀请运营，返回原登录页，不新增完整找回流程。建立有效管理会话后才进入本人设备首页。

切换注册与登录不自动发码或提交，验证码及验证凭证不跨用途复用；手机号可在同一前台认证流程保留供核对。错误靠近对应字段，请求中防止重复提交。登录不改变执行手机的参与、暂停、退出及归属，也不将管理手机接入执行。以上交互为既有边界下的设计细化，尚未表示客户端已实现。

## 2. 设备首页（AND-003／013／023／025 已确认）

首页顺序为“需要本人配合 → 处理后的进展 → 参与中设备列表 → 已退出设备折叠区”。分佣通过独立一级导航进入，不以金额占据首页主区域。设备正常且无协助事项时直接呈现设备概览，不用空白待办遮住设备。

按 AND-013，原有手机故障与新手机首次接入同时需要本人处理、都具备可行动条件且无更紧急风险时，首页主提示优先原有手机故障；新手机仍保留进度及继续接入入口。用户主动暂停、等待运营及仅有数据过时不因此成为需要本人修复的故障。点击提示进入对应协助详情，查看本身不发起控制，现场操作及恢复仍遵守原有确认边界。

按 AND-023，主设备列表只展示参与中的设备；已永久退出的设备收进列表底部的“已退出设备 · N”折叠区，点击展开可查看历史设备详情、交接与清理进展。若某台已退出设备的登录清理需要本人配合，该设备作为待办出现在首页顶部的“需要你配合”行动提示中。折叠不删除设备记录，也不把清理未完成误标为成功。

按 AND-025，首页移除原代码中的“退出管理登录”按钮，统一收拢在“我的”页面底部；导航采用底部“设备／分佣／我的”，页面内不保留多余的返回按钮。

| 区域 | 显示内容 | 交互规则 |
| --- | --- | --- |
| 顶部 | 我的设备、添加执行手机入口 | 添加是管理端扫码或手动关联入口，不默认把管理手机接入执行 |
| 需要本人配合 | 事项说明、设备标识（优先展示备注名）、当前影响、本人下一步 | 点击进入该设备的协助；不把等待运营分配列成本人待办；清理需配合的已退出设备在此提示 |
| 处理后进展 | 待复核、暂停待确认、恢复检查、退出后的未完成事项 | 不因用户点击已处理就从首页消失；不将等待过程反复标为需操作 |
| 参与中设备列表 | 备注名／型号／识别信息、业务状态、连接事实、最近确认时间 | 点击查看详情；必要时显示“本机”，避免同型号设备混淆 |
| 已退出设备（AND-023） | 底部“已退出设备 · N”折叠卡片，展开后呈现历史设备行 | 默认折叠，展开后点击进入历史详情与清理追踪；不参与日常任务派发 |
| 无设备 | 尚未关联执行手机、添加入口及专用手机说明 | 不虚构正常设备数，不强迫将日常手机接入 |
| 数据暂不可用 | 最近可得信息、更新时间与刷新入口 | 缓存可保留但标明过时；不能将未知状态计作正常 |

同一事项从首页和设备详情进入应共享处理进展。只有部分设备数据不可用时局部表达，不让整个首页只剩失败提示。刷新不改变当前用户读到的位置，也不因状态重排使手指下的操作对象突然变化。

设备列表采用逐台卡片或列表，不照搬 Web 多列表格；长设备名和状态说明换行。首期不增加“一键全部恢复”或批量退出，避免将已确认逐台操作扩大为批量授权。

## 3. 扫码关联与本机接入

### 管理端扫码与手动输入

1. 从“添加执行手机”进入准备页，说明先在目标专用手机打开接入入口。
2. 用户主动扫码时再申请与扫码有关的权限；拒绝后保留返回、说明与再次处理入口，不声称已关联。具体系统行为按机型验证。
3. 识别成功后展示目标手机的可核对标识、当前提供者身份和“确认关联”。仅识别到码不提交业务确认。
4. 确认后等待实际结果；成功进入该手机详情，标明“已关联，待完成接入”。失败说明原因；结果不明先查询该关联结果，不直接新增第二条设备关系。

码过期、已使用、已撤销或归属冲突分别说明；实际有效期限及凭证机制待实现设计，不编造倒计时。关联码不包含公司媒体账号密码或可复用的网络管理权限。

按 AND-015，首期支持手动输入执行手机显示的设备关联码，作为扫码的备用方式。添加／扫码页提供“无法扫码？输入设备关联码”，输入后点击“核对设备”进入与扫码相同的目标核对页，仍须明确确认。该路径不要求相机权限，也不要求先扫码失败；登录身份、归属及授权规则与扫码一致。

二维码及手动码指向同一目标及有效关联会话，切换方式不新增设备关系。错码、失效、撤销、尝试受限和网络不可用就地反馈，不显示虚假的目标或关联成功；码制、有效期与尝试限制待实施设计。重新获取凭证前核对原关联结果，失效凭证不能继续使用。输入设备关联码不接受注册邀请码或系统调试配对码作为替代。

### 关联核对页与关联结果（扫码／手动输入共用）

扫码结果页展示当前提供者身份及脱敏的验证手机号、目标执行手机识别信息、关联后的必要接入步骤和“确认关联”主动作。管理手机与目标手机分开标识；扫码识别成功不是关联完成，页面不预先把新手机加进就绪列表。

按 AND-014，扫码核对页支持选填设备备注名，留空也可关联；关联后可在本人设备详情修改。首页、协助提示与设备详情优先显示备注名，同时保留型号及稳定识别信息；未设置时用型号及标识显示。备注帮助本人辨认手机，不作为设备身份或归属依据。

交互细化建议：核对页依次放目标手机型号／标识、可选备注名、本人身份、后续准备说明及确认动作。关联前输入为草稿，返回不提交关联；允许重名但保留稳定标识以防混淆。关联已成功而备注保存失败时单独提示并允许稍后修改，不要求重新关联；修改失败保留输入，不能提前显示保存成功。当前 AI 核对稿需补充备注输入，静态稿及现有实现不视为已经支持此能力。

| 情况 | 应有反馈 | 后续动作 |
| --- | --- | --- |
| 已识别关联码 | 核对关联设备，等待本人确认 | 确认关联或重新扫码；返回不提交 |
| 确认请求正在处理 | 保留目标身份与请求进展 | 防止重复提交，允许返回查看同一结果 |
| 已关联，接入未完成 | 目标手机已关联，待完成本机准备 | 执行手机继续授权与检查，管理端查看进展 |
| 请求结果暂不明确 | 关联结果待确认 | 核对原请求，不重新建立第二台设备 |
| 已属本人 | 进入原设备及实际接入进度 | 不重复准入、不重置暂停／退出 |
| 已有其他归属／交接未清 | 不能覆盖关联，说明需运营处理 | 不显示强制绑定或通过换码绕过交接 |

确认页的后续授权、检查和运营准备步骤为说明行，不提供绕过当前确认的跳转箭头。

图稿中的设备编号和脱敏手机号均为示例；真实设备识别字段要由实现方案可靠取得，不将生成图中的编号规则直接变成物理设备主键。

### 执行手机的关联码页

从首次入口明确选择“将本机接入执行”，先说明仅用于专用手机及后续所需授权；日常管理登录不会走此页。本机通过可达接入入口取得关联会话，展示本机可核对标识、二维码及按 AND-015 新增的可手动输入设备关联码，提示“请用已登录的管理手机扫码，或输入下方设备关联码”。二维码与手动码对应同一有效关联会话，具体形式待实施设计。未完成组网不能成为获取关联码或首次关联的循环前置条件，实际接入入口仍需验证。

本机仅展示“等待管理手机确认”，不提供“我已扫码”作为完成证明。服务端确认目标与当前会话一致后，再进入本机准备清单；管理端确认回执丢失或本机离线时接续同一关系，不重建第二条设备。扫码关联码与注册邀请、Tailscale 入网凭据、系统调试配对码分开，图稿只有不可用于真实接入的示意码。

| 关联情况 | 本机反馈 | 处理约束 |
| --- | --- | --- |
| 未取得有效会话 | 无法显示可用关联码，给出实际原因及重试 | 不将缓存或占位图当成有效凭证 |
| 码有效、尚未确认 | 等待管理手机扫码或输入设备关联码后确认 | 只显示必要本机标识，不公开其他提供者资料 |
| 会话过期或被撤销 | 此关联码已失效；按真实条件重新获取 | 不编造默认倒计时；重新获取时核对旧会话是否已关联 |
| 已关联本人但响应不完整 | 正在核对关联结果，随后接续原设备进度 | 不因重试重置授权、暂停或退出 |
| 原归属或交接冲突 | 关联无法完成，需运营处理 | 不允许生成新码覆盖归属、跳过清理或重新激活退出资格 |

### 本机准备：先说明用途，再进入实际授权

准备页标题持续显示本机标识，列出当前所需步骤及事实。默认主动作指向首个本人可处理项，并按 AND-016 在可跳转时直接打开相应处理界面；依赖条件没完成的行显示原因，不要求用户反复进入无效设置。管理手机只能查看对应进展，不能在管理手机代开目标机的系统权限。

按 AND-016，首次准备采用“整体进度＋当前一步重点引导”，仍可查看完整清单。当前步骤默认以清楚文字说明用途、在哪台手机处理、具体动作及完成后的检查；必要说明不隐藏在帮助折叠区，不能只给图标或按钮。页面按“本机标识与总体进度 → 当前步骤与文字说明 → 处理入口 → 检查结果及下一步”组织，依赖未满足时说明原因，离开后保留进度。

**能跳转时必须提供可点击的处理入口。** 对系统设置、Tailscale 官方下载／安装、打开配套 App 或其特定页面，按支持环境实际能力提供尽可能直接的入口；已可直达时不能仅提供文字路径。按钮准确命名实际去向，如“打开 Wi-Fi 设置”“前往下载 Tailscale”“打开 Tailscale”；未验证特定 App 页面可达时，不用按钮名称暗示已经支持。未安装与已安装分别引导至可信官方安装来源或实际应用。

只支持打开上级设置／应用首页时，同时给出后续手动步骤；无法跳转或跳转失败时说明限制并保留适用的手动路径及当前进度。具体机型路径须核验，不能用虚构菜单填补适配缺口。需要在执行手机处理时，管理端明确告知使用目标手机，不打开管理手机自己的系统设置冒充操作。

用户返回后接续原步骤，自动检查可核验条件并展示实际结果，必要时提供重新检查；仍未完成就保留本步及可执行的后续动作，无法确认则如实说明。打开页面、安装 App、点击授权或返回本 App 均不直接判定整体通过；实际所需条件成立后才引导下一步，系统批准仍由用户在相应界面完成。

按 AND-017，首期不增加“需要帮助”主动求助入口、提交表单或对应进展流程。无法继续时保留当前步骤、必要排查文字、可用处理入口及重试；人工帮助沿用已有联系渠道，系统识别的异常仍按既有规则进入运营待办。后续页面以核心业务为范围，常规状态复用现有页面，不为辅助场景扩展独立功能。

| 准备事项 | 提供者需要理解和处理的事 | 系统或运营必须核实的事 |
| --- | --- | --- |
| 现场 Wi-Fi | 在本机连接可用的现有 Wi-Fi | 连接、可达性和后续稳定性分别验证，不以已连 Wi-Fi 证明所有网络通过 |
| 官方 Tailscale 配套 | 按受控引导安装官方 App、完成所需连接授权及已分配网络配置 | 凭据与指定手机、实际网络节点关联；入网许可及中心可达性，不能要求提供者获得公司网络管理账号 |
| 所需业务网络 | 按已分配方案使用业务出口；配置未就绪时等待运营处理 | 管理连接与所需平台网络分别检查，不以选中出口或 VPN 图标证明业务可达 |
| 本机调试授权 | 先说明用于批准范围内的手机操作，再按支持机型进入系统设置完成必要授权 | 实际中心执行路径获准、连接到正确手机；开启开关、本地端点发现与中心可控制分别确认 |
| 运行条件 | 仅在支持环境确实需要时说明相应系统设置与影响 | 不默认索要全部权限，不把省电设置或通知允许当作后台永不掉线的保证 |

按 R-148／R-151，受邀资格、设备归属和必要授权核实后，先显示“正在核验入网”，此时只可连接独立核验服务，不显示正式入网或业务就绪；资格、设备与实际网络节点关联核验通过后自动准入，不增加正常路径的“等待运营批准入网”。只有关联不明、冲突或核验异常进入对应待办和“等待运营处理”；原有首次项目／账号分配仍由运营确认。准入通过只更新网络事实，不将调试或业务就绪一并标为通过。

网络步骤说明应区分“在手机上使用指定出口”和“把手机设为出口”，本方案不要求提供者将本机作为公共网关。不得在新 App 内伪造 Tailscale 或 Android 系统授权弹窗，普通说明页不把点击“下一步”当作系统批准。官方配套 App 打开或设置深链不可用时，保留当前进度并提供已核验的手动定位说明；尚未落实机型路径时明确待适配，不提供虚构固定菜单。

调试授权不是手机号验证码或关联码。具体首次中心配对方式仍须在无现场电脑的环境证明；不把“管理手机扫码成功”当作调试主机配对完成，不要求把真实配对码、私钥或密码贴入普通反馈。资料核查及实现依赖见接入引导核查（历史来源已移除，见[清理记录](engineering/delivery/records/documentation-cleanup-20261006.md)）。

受限连接、节点核验通过、正式网络准入分别显示实际进度；失败或超时后提示“接入未完成”，回收待处理时保留该事实及运营事项，不将排队回收显示为已完成。受限阶段不提前开放 ADB 配对入口，不因 Tailscale 显示连接就跳过节点核验。具体超时数值来自实际配置，不使用图稿固定倒计时作为已确认要求。

### 系统配对码与多台同时配对

按 R-149，执行手机打开 Android 系统的配对码页面，提供者在已登录管理手机该设备的专用配对页输入；保持执行手机系统配对服务有效，支持机型具体路径须实测。配对码仅交实际中心的本次配对尝试，不进入普通协助反馈或 AI 输入，正常操作不要求发送配对截图。必要端点由本机发现并经核验关联，不让用户从同网设备列表猜目标；无法可信识别时明确阻断及处理事项。

配对页持续展示设备名称、稳定识别信息和目标确认提示；多个设备卡片各自显示“等待输入／正在配对／配对通过、连接待核验／需重新配对／结果待核对”。切换设备清除当前敏感输入，不把码带到下一台；已提交会话仍在原设备上追踪，返回页面不取消其他手机。配对码不回显在设备列表、历史记录或后台快照中。

不同手机可同时等待输入或在中心配对。一台失败只在其卡片处理；同机另一管理入口已有会话时接续原状态或显示冲突，不能静默另开。重复提交等待原结果，响应丢失先查询；明确重开时旧会话失效，迟到回执不使新会话显示成功。配对通过与实际连接分别显示，不能批量更新所有手机。原授权仍有效的端口变化自动更新及重连，不要求反复输入配对码。

### 条件检查：谁能处理、检查了什么、结果何时有效

检查页各行分别显示未检查、检查中、已通过、未通过或无法确认，以及最近实际核对时间。推荐分行：现场 Wi-Fi、管理连接、调试授权与中心连接、所需业务网络；支持机型与运行条件按实际方案补充。不同检查可以并行，页面顺序不锁定技术实现顺序；有依赖时说明为何尚未检查。

“重新检查”只在有效授权内刷新必要事实，不静默安装、授权、改业务出口或进行试发布。新接入可以进行获准检查；已暂停或退出的设备则继续受暂停／退出边界约束，不能借重进接入清单或检查按钮恢复手机业务操作。依赖端点变化后原检查过时，页面应回到待核对而非沿用旧绿勾。

| 情况 | 主要状态与下一步 | 不应显示 |
| --- | --- | --- |
| 只有 Wi-Fi 或 Tailscale 连通 | 对应条件通过，其他项继续检查 | 已可执行 |
| 系统调试已开但中心尚未获准 | 调试授权与中心连接待确认，查看对应步骤 | 一键授权完成或全就绪 |
| 网络节点／业务出口尚待运营配置 | 等待运营处理，本人无需反复授权 | 强迫重新注册、邀请或自选公司节点 |
| 返回 App 后拒绝／取消了系统授权 | 原步骤未完成，说明影响和再次进入方式 | 已通过或自动弹窗循环 |
| 检查超时、仅有缓存 | 无法确认，保留最后检查时间 | 把超时当成确定失败或刷新为最新正常 |
| 本机准备通过但还未分配 | 等待运营准备 | 可接日常任务或开始产生分佣 |

### 端点变化与恢复提醒

按 R-150，正常端口变化显示本设备实际的重新连接进展，成功后更新状态及最近核验时间，不弹出逐次变更提醒，也不要求重复输入有效授权下的配对码。恢复失败或明确需重新授权等本人操作时，展示原因、目标设备及具体协助入口；其他运营事项显示对应待办进展，不强迫用户反复设置。

发现端点、上报受理和中心连接结果分开显示；完全离线时保留最后确认时间及未知部分，不能显示手机已成功发送通知。已有暂停／退出继续保留，重连成功不将其改成可执行；一台恢复不批量更新其他设备。提供者外部通知渠道沿用现有待落实范围，本条不新增渠道。

### 等待运营、初始化与本机状态（AND-018～020 已确认）

按 R-143，分配前需要运营处理的接入问题对应全局待办，由邀请运营作为初始联系人；提供者只看本人所需的进展，其他运营可代办。不能仅显示等待却缺少实际运营事项。

本机条件检查通过后进入“等待运营准备”，进展分为本机准备、运营首次分配、初始化与身份核验；显示已完成、待处理或进行中，不显示用户无权决定的项目／公司账号选择器。等待期间没有本人事项时说明无需重复设置，不承诺排队时长或尚未确定的通知渠道。按 AND-018，“开始参与”作为本机准备流程的最后一步由用户进行一次明确表达，之后由系统保持；不再在状态页展示独立的参与确认/撤回参与开关。

运营完成分配后进入初始化；需要本人提供必要现场配合时转为具体协助，不能要求提供者在普通文本框填写公司账号凭据。初始化检查、实际身份和执行能力核验通过，并且当前无暂停、退出或其他阻断，才显示可接任务。早先通过的本机条件失效时，保留已发生事实并更新缺口，不因为到了后一步就继续用旧结果。

执行手机返回“本机状态”只查看本机接入、必要协助与运行／控制进展，没有管理端“设备／分佣／我的”完整导航。页面呈现规则按 AND-018～020 统一收敛：
1. **顶部粗粒度使用状态（AND-020）**：页面顶部持续显示“系统正在使用本机，请勿操作”或“当前空闲”及确认时间，无法确认时如实显示“无法确认”；执行期间系统通知栏常驻同步提示。不展示平台、账号、内容、任务明细或实时画面；现场操作仍须先暂停并等待停止确认。
2. **单一“暂停本机”控制（AND-018）**：已关联后提供持续可达的“暂停本机”入口，不藏在网络设置里，也不要求再次管理登录；移除历史实现中的“确认当前参与／撤回本机参与”独立按钮。
3. **恢复与退出去向**：明确说明恢复或永久退出前往已登录的管理手机操作，执行端不开放恢复或退出入口。

### 本机暂停与离线进展（AND-008／019／R-139）

现场人员从本机状态点击“暂停本机”时，按 AND-019 先弹出底部确认浮层，核对本机标识并提示“停止接新任务，当前操作会尽快停止；恢复需要在管理手机上申请”。用户点击浮层中的“确认暂停”后正式发起暂停，点击“取消”不产生任何请求；不额外要求手机号验证码、运营审批或必须填写理由。已暂停时显示原记录和当前停止事实，重复点击不建立另一套维护流程。未关联的手机不获得控制其他设备的权限。

1. 本机记录请求并尝试提交后，立即进入暂停进展页并显示能证明的进展；保存失败则明确未记录，不补造本地成功。
2. 中心确认受理且已停派发后才显示相应事实；目标手机侧实际业务操作停止按独立证据确认。本机发出请求本身也不证明已停止远程控制或平台提交。
3. 离线示例显示“本机已记录暂停请求／中心受理尚未确认／手机操作停止尚未确认”，不能出现“已安全停止”或“可开始现场处理”。若本机确有受验证的停止证明，只更新该项，不补推中心已受理。
4. 返回、重启或重新连网不能清掉尚未核清的暂停意愿；恢复连线时先同步并核对同一控制请求及在途事实。实现须验证本机与中心如何阻止旧任务接续，不仅验证 UI 标签。
5. 停止确认和控制交还满足现场条件后才进入正常人工处理；完成后仍须在已登录管理手机主动请求恢复并通过复核。仅本机身份不得提交恢复或永久退出，来自旧管理页的更早恢复回执不能覆盖新暂停。

打开本机 App、离开平台 App 或锁屏不是暂停完成证据，查看状态不自动请求截图或执行任务。现场人员可直接操作实体手机的限制仍按 R-137 处理；本机入口提升发起暂停的便利性，不承诺断网下可即时强停所有既有远程通道。

## 4. 设备详情与可用动作

详情固定显示目标设备身份。主体按“当前情况 → 需要谁处理 → 条件明细 → 控制及处理进展”组织；仅展示提供者所需的信息，不显示项目策略、发布内容、逐条任务或手机实时画面。

| 当前事实组合 | 主要提示 | 合理动作 | 禁止的误导 |
| --- | --- | --- | --- |
| 关联成功，尚未授权 | 接入未完成 | 查看本机待完成步骤 | 显示可接任务 |
| 检查通过，未分配 | 等待运营准备 | 查看进展；已关联设备保留暂停入口，管理端可进入永久退出 | 让提供者选择项目或公司账号，或必须等分配才可暂停 |
| 条件满足，没有任务 | 可接任务 | 暂停这台手机 | 显示正在执行或承诺即时收益 |
| 网络在线，提供者已暂停 | 已暂停；连接仍在线 | 请求恢复 | 在线自动覆盖暂停标签 |
| 暂停已受理，旧端未确认 | 正在停止，等待设备确认 | 查看进展 | 显示手机已停止全部操作 |
| 目标手机失联 | 当前状态无法确认，显示最后确认时间 | 仍可提交暂停／退出请求并追踪结果；提供必要协助 | 因离线隐藏停止使用入口，或虚报已停止 |
| 恢复检查中 | 正在检查，尚未恢复日常任务 | 查看需配合项与检查结果 | 一次点击后立即显示运行中 |
| 手机条件正常，另有运营阻断 | 等待运营处理；如有本人暂停则同时保留 | 查看可披露进展；仍可表达本人暂停 | 让本人恢复按钮解除项目／账号暂停 |
| 已永久退出，清理未完成 | 已退出参与，登录清理待处理 | 查看交接与必要协助 | 显示普通恢复或把清理记成成功 |

表中的状态不是一个互斥枚举。提供者暂停、失联、未知业务结果可以同时存在：主提示突出停止使用意愿和当前待确认事实，详情保留其余阻断。永久退出入口独立呈现，不能紧贴普通刷新或伪装成删除列表项。

## 5. 暂停、恢复与永久退出

| 操作 | 提交前说明 | 受理后的反馈 | 真正完成／后续状态 |
| --- | --- | --- | --- |
| 暂停这台手机 | 目标设备；停止新任务，当前操作在可确认节点尽快停止；暂停期间不使用该手机采集 | 请求已记录／中心已受理／等待停止确认；断网时如实表达尚未送达 | 已确认停止；未决平台结果单独保留，不改成失败或取消 |
| 请求恢复 | 目标设备；允许在现有授权内检查条件及未决结果 | 正在检查，必要时提示本人配合或等待运营 | 通过且无其他阻断后可接日常任务；未通过保留原因 |
| 永久退出此设备 | 目标设备；停止参与，普通恢复不可重新启用；历史、账号和平台内容保留 | 停止派发、旧端停止确认、交接及清理分开显示 | 设备不再接日常任务；未完成清理继续标明，重新加入须重新接入 |

暂停／退出不要求填写理由或等待运营批准。页面说明和本人确认用于辨认对象与影响，不引入审批。退出提交前保留明确返回入口，尚未提交时返回不发起退出；已受理后返回不撤销退出，也不显示一键撤销。不得以预计损失、扣罚或夸大收益劝阻。

反复点击只追踪同一次请求；超时先核对请求是否已受理。来自多个管理入口的新状态以权威记录更新，不允许旧页面把另一入口的暂停覆盖为运行。返回上一页、关闭弹层或退出页面不撤销已经受理的控制请求。

若管理手机本身断网，只能说明请求暂存或尚未送达，不能表示系统已停止派发；中心已受理但目标手机离线，则说明已停新派发、旧端停止尚待确认。两类离线文案不能混为一谈。

### 永久退出确认页

从指定设备详情进入，持续显示目标设备标识及最近已知状态。说明仅停止这台手机参与，其他设备按各自状态继续；停止派发、手机停止确认和登录清理分别推进。暂时停用仍用原暂停入口，不将永久退出藏在“移除卡片”或退出 App 登录中。

按 R-146，确认页说明“系统受理退出并停止新派发后，对应账号承接期间结束”；不以实际停止回执或登录清理时间延后分佣终点。进展中可查看已确认的承接终点，请求未确认送达时不能显示承接已结束；受理响应丢失后核对原请求与原受理时点。

确认页给出四项必要影响：停止新任务及尽快停止当前操作、普通恢复不能重新启用、运营在有效授权内处理交接与清理、保留历史记录及分佣依据。退出不删除公司媒体账号或平台内容，也不承诺手机已立即清理或自动完成全部权限撤销。

主按钮为“确认永久退出”，次要按钮为“返回设备详情”。不新增必须填理由、验证码、收费或运营预审批；本人确认属于页面操作设计，不是额外审批流程。提交过程中锁定目标并防止重复请求；发出后结果未知时查询同一请求，不用“失败”掩盖可能已受理的退出。

### 退出后的进展与返回

| 事实组合 | 页面主要反馈 | 可提供的下一步 |
| --- | --- | --- |
| 管理手机断网，尚无中心受理证明 | 请求尚未确认送达，不宣称已停派发 | 保留原请求进展；联网后核对是否已受理 |
| 中心受理并停止新派发，执行手机离线 | 退出请求已受理；手机停止尚未确认 | 查看事实和必要协助，不显示恢复或退出成功总勾 |
| 手机已确认停止，登录清理尚未完成 | 已确认停止；登录清理待处理 | 查看运营处理进展；需要本人配合时才给出协助入口 |
| 权限撤销、无法远程清理 | 清理未完成及具体缺口 | 保留未完成状态，不能静默恢复授权或重启日常任务 |
| 停止和清理均已核验 | 对应事项分别显示已确认 | 返回设备记录，历史及未决业务结果继续可追踪 |

进展页始终区分“提供者退出意愿”“新派发已停止”“旧端实际停止”“登录清理”；不能把它们压成一个成功状态。手机停止或清理完成也不代表在途发布结果已核清，提供者只看必要处理进展，逐条发布与账号迁移操作留在运营端。

已退出设备在本人设备记录中保留可达入口，清理未完成时详情与需要本人配合的事项可继续查阅；不靠删除列表行来表现完成。返回或关闭页面不撤销已受理退出。旧页面的恢复动作、旧复核完成回执及自动重连均不能覆盖更新的退出状态。重新加入须另走接入及授权流程，不能用刷新或重新扫码重置未清交接。

退出前产生但迟到账的广告收益仍按已确认承接期间及比例处理，不因退出删去本人历史依据。按 R-147，退出后确认无人承接期间产生的收益不计本人或其他提供者分佣，后续有人承接也不追补；本人端说明分佣范围，不展示公司空档收入或他人资料。资料缺失、跨边界无法划分的收入仍待核对，不将未知归属直接判为公司收入，不在确认页承诺持续收益、固定付款日期或自动结清。

## 6. 本人协助与现场操作（AND-021／022 已确认）

协助页包含目标设备、问题及影响、当前处理者、最近进展和下一步。运营能够处理的问题留在运营端，提供者不承担策略确认或公司账号管理。

按 AND-021，现场修复实行**两端明确分工**：
- **管理手机**：协助页只展示设备标识、故障原因、停止确认进展以及“请在目标执行手机（如 SG-021）上打开 App 按提示处理”。停止确认后管理端等待执行手机检查事实，不让管理端用户在屏幕上看长篇步骤去脑补操作另一台手机。
- **执行手机**：停止确认后，执行手机的本机状态页自动展开对应的修复步骤，直接复用「本机准备」的逐步引导、默认文字说明与可用直达跳转按钮（AND-016）；现场人员完成操作后，执行手机就地自动重新检查。

按 AND-022，**彻底移除“提交处理结果”手动表单步骤**：
- 执行手机就地自动检查通过后，服务端即时同步事实；管理手机协助页与设备详情直接变为“现场条件已检查通过，设备仍保持暂停”，并提供“请求恢复”与“暂不恢复”按钮。
- 未通过或无法确认时如实呈现缺口并支持重试；不引入让提供者填写自由文本说明的手动提交表单。
- 自动检查通过绝不等于设备自动恢复，仍必须由提供者在已登录管理手机上主动点击“请求恢复”，并通过后续系统复核（R-137）。

| 阶段 | 管理端展示 | 执行手机展示 | 衔接与流转 |
| --- | --- | --- | --- |
| 待本人配合 | 说明需恢复哪项条件及原因，按钮“暂停并开始现场处理” | 保持当前状态；如需停止则展示待停止 | 沿用设备记录；点击表达暂停意愿，不代表已可现场操作 |
| 停止确认中 | 显示请求送达、中心受理及执行端停止进展 | 显示本机暂停进展，等待中心与操作停止确认 | 等待实际停止确认；同机互斥未交还前不开放操作 |
| 可以现场处理（AND-021） | 提示“已确认停止，请前往执行手机按引导处理” | 自动展开具体修复步骤与直达入口，提供者现场操作 | 执行端就地检查，管理端实时监听检查结果 |
| 检查通过（AND-022） | 显示“现场条件已检查通过，设备仍保持暂停”；提供“请求恢复”与“暂不恢复” | 显示“本机检查已通过，请在管理手机上请求恢复” | 不设立文本提交表单；未点击请求恢复前设备保持暂停 |
| 恢复复核中 | 显示复核检查项进展（授权、身份、未决结果）及处理者 | 保持暂停，提示“正在复核恢复条件” | 用户主动请求后触发；不重复发起请求，不显示即时运行中 |
| 复核完成 | 全满足显示“可接任务”；部分通过显示剩余阻断 | 同步更新为可接任务或保留剩余阻断提示 | 所有阻断全解除后才恢复派发；有一项未过仍保持暂停 |

“开始现场处理”复用原设备临时暂停和记录，不再新增一套互不关联的维护状态。流程退出后仍保留暂停及处理进展；用户没有请求恢复时，运营提交已处理也不能替代本人恢复意愿。

若设备原已因提供者暂停，仍核对停止事实及当前控制归属，不重复启动或恢复再暂停。若原本只是故障阻断，不能把这项阻断当成已确认所有手机操作停止。重复发起或返回协助页接续原记录，避免出现两套相互覆盖的请求。

无法确认停止时显示具体缺口，不给出“可安全开始”的保证。断网下若发生必要物理处置或用户直接操作，记录实际事实，重连后先核对当前手机状态及未知结果，不自动继续旧进度。具体离线现场指引按支持环境落实，不承诺远程一定能取得停止确认，也不承诺系统能阻止触碰实体手机。

提醒的送达渠道及权限策略尚未选定，不把运营侧优先邮件的决定套用为提供者通知方案。不论是否收到通知，App 中实际协助记录及其进展始终可查；已读不等于处理完成。

请求恢复只授权既有有效范围内的必要复核，不授权修复被撤销的权限、新发布或扩大业务范围。核验不使用未经许可的手机操作。等待页不展示虚构百分比、保证完成时长或无限自动重试的承诺。

复核期间用户仍可从设备详情再次暂停；新的暂停按现有停止确认规则生效，旧复核结果不能解除它。关闭页面不取消已经受理的恢复请求，与主动再次暂停分别处理。复核失败也不允许对未知发布直接重发。

## 7. 基础分佣

R-144：在未永久退出或交接、原账号承接关系仍有效时，临时暂停或掉线不打断承接期间，期间广告收益仍归原提供者参与分佣；不得显示按暂停／离线小时扣减的金额，也不把收入归属显示成设备已恢复。仍按实际到账、核清归属及适用比例展示，首次承接按 R-145 从对应账号初始化、真实发布身份核验通过且具备执行条件时开始，不追溯至分配，不等待首次任务；具体起点可追溯。永久退出按 R-146 在系统受理并停止新派发时结束对应承接，不等待旧端停止或清理。

独立页面分别呈现预估收益、可结算佣金及已付记录，保留口径、币种、适用区间和更新时间。预估平台收入与提供者佣金不是同一种金额，不拼成可提现余额；无可靠数据时显示暂无数据或待核对。

记录详情只给出本人核对所需的 Page／频道标识、设备及承接期间、本人可归属收益、适用比例与生效区间、佣金和实际付款处理事实。涉及多人共同覆盖的收入来源时只展示本人可披露依据，不开放其他提供者明细或公司全部财务资料。

不同币种不直接求和；没有明确的跨币种口径时分币种显示。筛选与查看不改账，不添加提现、绑卡、自动付款或复杂争议工单。缺少收入或比例只影响对应分佣结果，不阻止设备接入主流程。

### 分佣列表：收入依据与佣金记录分开（AND-024 已确认）

从“分佣”导航进入本人记录，保持“设备／分佣／我的”一级导航；查看详情后返回原筛选和列表位置。默认以收益所属期间组织记录，币种随每个金额明确显示，不以到账月份替换收益所属期间。月份仅为图稿举例，不新增按月结算规则。

按 AND-024，**分佣列表顶部不显示任何汇总或合计数字**。页面上方仅保留“平台预估收益”作为独立参考区，标明本人可归属部分、平台口径及所属期间，提示“预估收入，不是可结算佣金”；只能取得账号总额而无法确认本人部分时显示待核对，不把全账号收入当作本人金额。下方“佣金记录”按账号标识、设备／承接关系、收益所属期间、金额及付款事实逐条进入详情。不设置任何“可结算总额”“累计佣金”等统计卡片，防止提供者误将核对数据理解为可提现余额。

| 数据事实 | 展示方式 | 不允许的推导 |
| --- | --- | --- |
| 只有可靠的本人可归属预估收益 | 预估标签、币种、期间、来源及数据时间 | 不按预估提前标可结算，不混入佣金合计 |
| 收入未到账或归属未核清 | 待到账／待核对及具体原因；未知佣金不填零 | 不按当前设备归属、设备数量或均分补算 |
| 到账与归属通过，适用比例缺失 | 比例待确定，佣金待计算 | 不用图稿比例或当前最新比例代填 |
| 到账、归属及适用比例都明确，尚无付款事实 | 可结算·未付款及佣金金额 | 不叫可提现余额，不许诺到账日期 |
| 有实际付款完成依据 | 已付，详情给出对应金额与付款事实 | 仅创建、审核或保存一条记录不能标已付 |
| 明确的零收入／零佣金 | 对应口径的零值及依据 | 不与数据缺失混为一谈 |

收入状态和付款状态不是同一个连续进度条；同一收益从预估变成核实收入，不把两份金额重复计入。部分记录缺数据时保留其他可用记录，不显示虚构汇总。真实发生的金额或付款结果不一致须如实待核对，不展开新的退款、抵扣或付款流程。

### 分佣详情：只给本人核对需要的依据

详情展示平台及 Page／频道可辨认标识、设备和本人承接期间、收益所属期间、本人可归属的到账广告收益及到账日期、适用比例和生效区间、计算结果、实际付款状态及可披露依据。来源时间与最近核对时间分别保留，不能把打开页面的时间当作收入更新时间。

计算说明沿用“可归属到账广告收益 × 收益产生期间适用比例”，不另扣运营成本。收入跨越交接或比例生效点且无法可靠拆分时显示待核对，不均摊、不编造精确值。历史记录从旧设备进入时仍显示当时归属，不能按当前绑定覆盖；退出、换机或比例更改不重写已确认历史。

仅展示本人核对所需的来源摘要和标识，不开放公司全量财务、其他提供者记录或包含凭证的原始资料。页面动作限定为查看和返回，不提供“标记已付”或代运营修改金额的入口。真实比例和付款安排仍按 R-120 在实际需要处理前落实，本轮不新增分佣业务选择。


## 8. 我的与账号帮助：首期最小范围（AND-025 已确认）

按 R-141 与 AND-025 收敛：我的页面按参考图 profile-v1（过期示例或演示已移除） 组织为最小管理范围：
1. **身份展示**：仅展示本人名称与脱敏登录号码（如 `登录手机号 +86 138****0000`）。
2. **说明与帮助入口**：提供“设备接入说明”与“账号与登录帮助”两个次级入口。
3. **退出管理登录**：作为独立次级按钮放置在页面下方，紧随说明文字“退出管理登录只撤销此管理会话，不暂停或退出已关联的执行手机”（按 R-142）。首页原有的退出登录按钮予以移除。
4. **导航联动**：“我的”与各子页内不再设置“返回我的设备”等冗余跳转按钮，统一由底部“设备／分佣／我的”一级导航完成平级切换。设备问题回到设备页，不新增独立账号设置中心、会话列表或找回工单。

原号码仍可用时，换管理手机继续用原号码短信登录。原号码不可用时，按 R-140 联系原邀请运营，经人工核验本人后再验证新号码，将登录号码换到原提供者身份；设备关联、历史和原控制状态保留。运营受理、人工核验通过、新号码验证、换绑生效分别核对，未核实不能显示成功；新号码已关联其他身份时不能直接合并。办理方式与最小核验依据在实际需要提供该能力前落实，不用直接改库替代受控办理。

[我的与找回参考稿](design/android/README.md)已保存，但完整 App 内换绑表单与进度流不列为当前必做；帮助说明可沿既有联系渠道处理，不假设已有客服系统或自动发出申请。任何换绑办理都不能自动恢复设备执行或补回授权。

按 R-142，“退出登录”只结束相应管理登录，不影响执行手机的参与意愿、授权、分配或原控制状态；已受理的暂停／恢复／退出请求继续按原事实推进。退出后回到登录入口，管理资料缓存及失效请求按身份方案处理，不通过旧页面继续管理。再次登录取得同一提供者及最新设备事实，不自动恢复手机，也不重复提交原控制请求。具体会话失效与请求失败反馈由实现设计落实，当前不增加多端会话管理页面。

## 9. 通用交互与可访问性

以下作为规格草案采用的通用要求；AND-006 已选定首页视觉方向，颜色、字号、间距和组件起点见[Android 设计规范](design/android/DESIGN.md)。图稿不代替原生渲染验证，生成偏差不成为产品要求。

- 可点击控件触摸区域至少 48 × 48 dp；正常正文与背景对比度至少 4.5:1，大字按官方定义至少 3:1。图标提供表达操作用途的可访问名称，列表动作包含可辨认的设备上下文。[Android 官方可访问性指导](https://developer.android.com/guide/topics/ui/accessibility/apps)，核查日期 2026-09-28。
- 文字可随用户字体设置变化，设备名、原因和按钮不得因放大丢失；状态同时使用文字与视觉标记，不只靠红绿颜色。
- 输入错误贴近对应字段；跨页返回保留尚未提交的非敏感输入。接入码过期、授权变化及设备状态更新后核对真实事实，不盲用旧页面。
- 主动作说清目的：“确认关联”“查看接入步骤”“暂停这台手机”“请求恢复”。避免用“完成”“确定”同时表示提交请求和实际执行完成。
- 短暂提示仅补充反馈；暂停待确认、复核中和清理未完成等持续状态必须在详情中保留。
- 设备状态时间与页面刷新时间分开。日期跨时区可能歧义时显示具体时区；手机当地时间不改写项目或收入的统计区间。
- 查看已有状态不发起手机截图、读取平台内容或远程操作。仅管理入口不要求本机执行用途的授权。

## 10. 跨端一致性与验证准备

| 检查场景 | Android 应看到什么 | 运营／执行侧应保留什么 |
| --- | --- | --- |
| 邀请已校验但注册前被撤销或名额被占用 | 邀请失效，不能完成首次注册；已有账号可正常登录 | 最终提交重新核验，不消费失效邀请或创建新提供者 |
| 注册响应丢失后重试 | 核对原结果，不要求重新注册第二个身份 | 一次性消费与成功注册一致，重试取得原结果 |
| 恢复复核期间再次请求暂停 | 展示新的暂停请求及停止确认进展 | 旧复核完成不能覆盖更新的暂停意愿；复核操作仍需确认停止 |
| 三台设备中只暂停一台 | 明确目标及该台进展，其余按各自条件显示 | 仅对应设备停派、停止及未决事实 |
| 扫码后网络中断 | 关联结果待确认，恢复后可取得同一结果 | 不重复归属、不重复创建执行资格 |
| 扫码成功但调试未授权 | 待完成接入 | 不派发依赖任务、不误记初始化通过 |
| 执行手机未入网，正在展示关联码 | 关联入口可达或如实说明连接阻断 | 不要求先完成尚依赖关联的网络准入，不伪造有效码 |
| 本机授权页返回但授权被取消 | 保留未完成步骤及原因 | 不以页面返回、开关状态或自报已完成作为中心授权证明 |
| 本机准备通过但未分配／初始化未完成 | 等待运营准备或核验进展 | 不开始日常任务，不要求提供者选择公司账号 |
| 仅设备身份尝试恢复／退出或访问其他设备 | 无对应操作与数据，提示管理入口 | 实际拒绝越界请求，不仅隐藏按钮 |
| 离线本机暂停请求已保存 | 本机记录、中心受理及停止分别显示 | 重连先核对控制意愿，旧恢复结果与任务许可不能覆盖新暂停 |
| 设备离线时暂停 | 中心受理与旧端停止分别表达 | 待确认事实保留，旧心跳不能解除暂停 |
| 请求恢复时项目仍暂停 | 设备核验进展及仍有运营阻断 | 不因设备恢复启动被暂停发布 |
| 用户提交协助已处理 | 待复核 | 原阻断仅在核验通过且符合边界时解除 |
| 现场协助处理完但未请求恢复 | 仍保持暂停，可查看处理事实 | 不因保存说明、返回 App、重连或运营操作而恢复 |
| 开始现场处理时已有远程接管 | 等待控制交还，不显示已可现场操作 | AI 停止不等于运营已交还；保持同机互斥 |
| 退出后清理无法连接 | 退出意愿成立，清理未确认 | 不重新派发、不伪记已清理、不删除历史 |
| 退出受理后旧恢复回执到达 | 保留退出进展，不能跳回可接任务 | 更早的请求结果不能重新启用已退出设备 |
| 管理手机提交设备永久退出后响应丢失 | 查询同一退出结果，不提前显示完成 | 区分未送达与已受理，无重复业务副作用 |
| 已退出设备有旧收益迟到账 | 原归属历史及待核对／可结算事实 | 按收益产生期间归属与比例计算，不因退出抹除历史 |
| 同一列表含预估收入、可结算及已付佣金 | 口径、所属期间与币种分开，详情可核对 | 不相加成余额，不重复计佣，不把记录生成当作付款 |
| 收入跨交接或比例生效点且无法拆分 | 待核对，不展示确定佣金 | 不均摊或用最新比例重算整段 |
| 切换提供者身份 | 只显示当前本人可访问信息 | 旧缓存、旧深链及请求不能跨用户取数或控制 |
| 分佣缺数据或比例 | 待核对／未配置，区别于真实零值 | 不补造金额或付款事实 |


按 R-141／R-156 收敛核心页面、状态与跨端动作，首批依[身份与设备归属契约](first-delivery-flow.md)实施；组件及失败分支随开发落实。停止逐项扩展账号功能和提醒渠道；退出登录按 R-142 不影响执行手机，原生接入与停止能力在对应模块开发中验证、交付前补齐证据，不能用图稿代替。
