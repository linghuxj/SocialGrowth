# SocialGrowth 首条业务闭环产品规格

日期：2026-09-19。状态：产品行为与交接规格已细化，实现状态未核验、未进行实测。对应[阶段推进计划第一批](handoff/2026-09-19-product-stage-plan.md) PG-01 至 PG-10。业务规则以[已确认决策与流程](handoff/2026-09-19-business-flow-proposal.md)为准，本文解释运营人员如何使用这些能力，不另立技术方案或商业验收阈值。

## 用户与完整任务

首期使用者为内部运营人员。一次完整任务是：明确为谁实现什么目标，准备有权使用的账号/素材/入口，审阅 AI 的策略与理由，形成有效执行安排，理解结果和限制，再决定保持、调整、继续取证或停止。客户资料可以由运营代录；不要求客户门户、多级审批或新增岗位。

起点可以是新接入，也可以是已有服务继续运营。已有资料可复用，但检查当前有效性；不能因账号曾经发布成功，就忽略本次客户关系、素材或批准已经改变。没有数据时可以形成假设，不能编造过去有效的依据。

## 信息如何关联

以下是用户需要理解的信息关系，不是数据库字段或接口定义。

| 业务对象 | 需要说明的内容 | 关联与变化 |
| --- | --- | --- |
| 运营项目 | 服务客户、当前阶段主目标、受众、期限、约定与责任 | 账号、素材及报告均能回到所属服务范围；客户可有不同目标的项目，不以客户名称当统一主目标 |
| 账号服务关系与定位 | 账号所有方、授权方、服务客户、期限、动作/数据权限、地区/语言/人群 | 共享是有记录的例外；定位或目标变更影响尚未开始安排 |
| 内容身份与版本 | 来源、剧情、语言成品、权利范围、重叠关系、归属及发布历史 | 文件版本不增加独立库存；已发历史与撤下、账号退出分别保留 |
| 入口与目的地 | 客户、剧集/内容、语言、实际查找路径、使用/维护权限 | 共用入口须解释旧内容如何找到相应目的地，不能伪分摊账号级点击 |
| 规则与策略版本 | 目标、引用规则、候选内容、文案、动作、排期及假设 | 每次修改可解释差异；生成或保存不等于批准 |
| 试验和执行批准 | 批准人、指定版本、范围、期限、发布量/成本与停止条件 | 新策略先批准；条件失效只重审受影响安排，不能让旧草案继续下发 |
| 发布安排与结果 | 目标账号、内容/版本、目的地、计划时间、实际动作和证据 | 尚未提交、处理中、明确未发布、已公开、未知、撤下分别解释；一次操作失败不等于没有发布 |
| 观察与复盘 | 来源、时间、范围、定义、缺失原因、与目标的关系及下一步 | 已有观察不被新目标覆盖；真实零、缺失与不确定分别呈现 |

“运营项目”沿用已确认的客户/阶段服务单元，只统一称呼，不新增商业计费单位、固定账号配额或客户门户。

## 工作区与动作

这些是功能区域，可合并在同一页面或详情中；不是要求建设八个独立页面。统一展示当前项目、账号/平台范围和影响对象，避免用户在不知所属客户的情况下批准或恢复。

| 工作区域 | 用户看到什么 | 可以做什么 | 缺资料或条件不满足时 |
| --- | --- | --- | --- |
| 项目与接入 | 主目标、受众、账号关系、权限期限、入口及责任 | 新建/补充简报，确认目标与定位，查看接入缺口 | 保存待完善资料，说明缺什么及影响哪一步；不锁住全部项目整理 |
| 素材与库存 | 内容身份、语言版本、权利、适配、归属及发布历史 | 补充、核对重叠、形成合格候选或缺货需求 | 显示不能用于哪个账号/目的及原因；不靠重导入或换语言重新取得资格 |
| 规则与策略草案 | 有效规则、匹配理由、假设、文案、入口、排期和观察计划 | 录入经验，审阅 AI 草案，调整并比较版本，要求重新生成 | 无经验标待验证；规则冲突待处理；不选择不合格素材填满排期 |
| 审阅与安排 | 批准版本、内容/账号/入口、时间及时区、范围与停止条件 | 批准、驳回、修改、暂停或取消尚未开始的安排 | 逐项解释不可批准或需重新批准的原因；部分安排失效不把整批默认为通过 |
| 执行与人工待办 | 当前动作状态、证据、影响范围、待核对事实和责任 | 查看、暂停、提交核对依据，按权限确认恢复 | 未知结果进入待核对；通知不等于已接管，设备在线不等于允许恢复 |
| 导流与入口维护 | 真实受众路径、目的地版本、关联历史内容和故障 | 查看路径、经授权调整、处理旧链接/维护约定 | 没有对应内容或入口不可用时说明问题；不换成无关页面假装恢复 |
| 观察与复盘 | 发布事实、社媒与短链来源、缺失、原目标及假设 | 阅读 AI 分析，记录保持/调整/取证/停止，返回策略草案 | 未接入显示缺口；无改善可以记录，必需工作未完成不能宣称闭环通过 |
| 变更与退出 | 变更影响、未开始/执行中/历史内容、权限和链接维护责任 | 确认变更、处理相关待办、记录交接或无法处理的原因 | 无权修改外部内容时记录例外；不假装全部删除或移交完成 |

日常入口应帮助运营看清“现在需要我处理什么”。待办按业务影响和排期时效组织，至少区分待审、待补资料、结果待核对、暂停待恢复和到期/退出事项；不承诺未经验证的每天固定处理时长。确认同一影响范围后应能看到关联安排，避免逐条处理却漏掉同源问题。

## 从草案到下一轮的操作过程

1. **建立或选择项目**：运营确认主目标与账号服务关系，列明内容和入口。信息不完整可保留草案；真实操作需要的授权单独显示。
2. **准备候选内容**：核对内容身份与权利、语言/剧情及目的地适配，再匹配目标账号。有重叠先人工核对主体不同；缺货形成需求并回到素材补充，不自动花费生产内容。
3. **生成策略**：AI 引用当前定位、规则及可得证据，给出候选安排和理由。没有运营数据时展示假设；草案说明准备观察什么，而非保证得到改善。
4. **审阅并批准**：展示本次版本、适用账号/内容/动作、排期时区及试验边界。批准前再核对归属、授权和入口；修改后明确旧批准对受影响安排是否已失效，保存不直接执行。
5. **发布前复核及执行**：到执行时核对批准、权限、内容资格、排期和资源条件。无法执行则显示原因与去向；已进入执行的结果不能通过取消或设备复位抹掉。
6. **记录结果与导流**：展示可核对的发布事实及来源。回执丢失先待核对；已公开后撤下保留发布历史。入口、短链响应与实际到达分别解释，不把未观察到的环节填成成功。
7. **观察与复盘**：按原计划展示数据与限制，AI 给出有出处的分析。运营根据权限确认下一步；新试验返回批准流程，不能因这次效果好自动扩大。
8. **始终可处理变更**：任一步收到目标/授权/素材/目的地变更，都定位影响范围并走下表。客户退出停止新增，历史内容、未知结果及链接维护仍分别处理。

首条流程就包含试验假设、批准范围和基本观察/复盘记录。后续 PG-12 深化比较和迭代管理，不是到第二批才开始遵守 G-05；PG-11 深化托管，不能提前取消本批人工边界。

## 变更与异常的具体去向

| 触发场景 | 产品应呈现与允许的动作 | 保留的不变事实 |
| --- | --- | --- |
| 内容已被其他安排占用 | 当前候选不能继续沿用旧库存结果；重选或先依规则取消原安排 | 两份草案不能都因各自曾可用而获得执行许可 |
| 仅修改草案措辞 | 展示修改后版本并审阅；已批准内容发生变化时复核批准适用性 | 草案修改本身不等于发布过，也不增加发布计数 |
| 目标或定位改变 | 未开始的受影响安排暂停重审；执行中/未知结果另核对 | 已完成发布与数据保留原目标、定位和规则依据 |
| 目的地变化 | 展示全部关联的旧/新内容，按授权及内容对应关系处理 | 不能把老客户入口自动改给新客户，旧预览可能未同步 |
| 授权撤回或素材失效 | 停受影响新动作，核查执行中结果与历史处置权限 | 无权限不承诺下架，历史发布事实不被删除 |
| 已批准、确定全部版本未提交且无发布历史，需取消 | 撤销旧安排及其批准效力，留核对依据后可释放重新分配；新分配重审 | 取消不是通用释放，已提交或未知不适用 |
| 已提交、明确从未发布的失败 | 核对平台依据和仍在处理的可能，经人工确认当前条件后允许原账号新的恢复安排 | 失败恢复不是已有发布历史重发，也不自动取得跨账号释放资格 |
| 执行超时或失去回执 | 标出未知及相关暂停范围，等待核对，保留证据 | 超时不是未发布证明，不能直接再次提交 |
| 平台确认已有发布，后续删除 | 显示已发与后续撤下两个事实 | 原账号及其他账号均不能另发同一内容取得新资格 |
| 非值守遇到人工挑战 | 形成待办并暂停受影响及关联范围，无关联且有效批准的继续 | 挑战过期重新处理，进入值守时间不自动恢复过期安排 |
| 数据来源延迟/变化 | 展示缺口与来源变化，检查原比较是否仍成立 | 不填零，不改主指标硬选赢家；原观察保留来源 |
| 合作结束 | 停新增，核对未开始/未知结果，按约定保留内容及继续/停用链接，记录交接 | 客户退出不自动释放已发身份，不转给其他客户 |

## 用于文档走查的案例

案例仅定义产品应如何表现，不是已执行的测试或真实商业数据。

| 案例 | 输入与经过 | 应得到的业务记录 | 覆盖项 |
| --- | --- | --- | --- |
| C-01 无历史数据的正常流程 | 建立客户/目标、有效账号与现成素材；AI 按已核查规则给出待验证策略，人工批准后记录发布、观察与下一步 | 每一步关联同一项目/目标、内容身份和版本；没有历史依据明确标出 | PG-01 至 PG-09 |
| C-02 合格库存为空 | 现有素材都不满足授权或语言，匹配分即使很高也不发布 | 缺口、原因、责任与补充/加工请求；不制造空任务或新内容费用 | PG-02/04/10 |
| C-03 两份草案选择同一内容 | 草案甲先获批准；草案乙随后送审 | 乙显示归属冲突并重选；取消甲须满足 G-03a 才可重新审核分配 | PG-02/04/05 |
| C-04 目标切换时有不同状态的安排 | 一条尚未开始、一条结果未知、一条已公开 | 分别重审、核对、保留历史；不批量重发 | PG-01/05/06/10 |
| C-05 失去回执后找到公开帖子 | 执行中断，核对后得到已有公开发布的证据 | 登记已发并关联原安排；不再次提交、不释放素材 | PG-06/10 |
| C-06 共用入口与多部内容 | 多个内容共用一个可用入口，客户改了目的地 | 展示查找路径和全部受影响内容；统计只到实际归因范围，不编造单条点击 | PG-07/08/10 |
| C-07 零值与缺失同时存在 | 一项有真实零值，另一项无采集权限 | 两者分别呈现；若必需主指标缺失，复盘显示未完成/需重新设计 | PG-08/09 |
| C-08 已发布客户退出 | 有已发内容、未提交安排及未到期链接维护约定 | 停新增，取消/核对待发，按权限保留历史并履行链接约定 | PG-01/06/07/10 |
| C-09 非值守挑战 | 某账号需人工验证，同设备另有安排 | 标出已确认影响与不能排除的关联范围；不将通知发送当作已接管 | PG-05/06/10 |
| C-10 合格试验无改善 | 按批准计划完成必要执行、采集与评价但未达改善判据 | 可记录完整复盘，策略不标有效、不扩大；继续取证另批 | PG-05/08/09 |
| C-11 同一内容跨语言与剧情重叠 | 导入字幕版和配音版，又导入主体不同但有必要衔接的新片段 | 前两者共用身份且只选一版发布；后者待人工核对并记录依据才可独立分配 | PG-02/04/05 |
| C-12 尚无真实接入 | 产品人员用明确标记的样例贯通上述关系 | 样例不计真实发布/经营数据；显示哪些运行步骤待接入，其他规划可继续 | PG-01 至 PG-10 |

## 首批交接应带走什么

交接包含项目简报、内容/版本与权利记录、策略草案及批准范围、发布结果与异常处置、入口对应关系、观察与复盘，以及上述场景的产品行为。记录形式由后续设计决定，不要求重复填写多份表单；共同信息只维护一次，变更保留必要历史。

本规格已能支持后续信息结构、交互和工程拆分。真实授权、账号功能、供应商指标和具体服务时段仍由实际项目补充，仅约束依赖它们的运行步骤；本轮没有选模型、定接口、修改代码或设商业数量门槛。
