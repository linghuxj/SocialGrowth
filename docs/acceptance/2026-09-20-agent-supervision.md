# Agent 主导的统一 Web 执行闭环：本批开发与验收报告

日期：2026-09-20（Asia/Shanghai）

## 总结

已完成核心协作机制开发，并真实跑通“Web 发起 → Artemis 观察 → 截图待办 → Web 回复 → 原任务重新观察 → 结构化结果回传”。另外通过真实 Web 按钮验证了任务取消。

**这不是 FB／YT 全场景自动运营已全部完成的声明。** 自动创建 Page／频道、账号错配纠正、跨进程续跑等仍有待开发项；真实密码／验证码登录到发布前的成功链路尚未重新通过。本轮不使用真实密码、不发送验证码、不公开发布。

## 1. 文档与实现

- 采用领域建模规范明确运营执行任务、任务人工协助单、执行授权、设备错配纠正，写入 CONTEXT.md；同步 CLAUDE.md 的“禁止运营轮换”与“独立授权纠正”边界。
- 新增 docs/adr/0001-agent-led-supervised-execution.md、docs/specs/2026-09-20-agent-supervision.md、docs/engineering/agent-supervision-guide.md。
- 复用 execution-runtime、现有 SQLite 和 Web 执行记录页，没有另建服务或多 Agent 编排系统。
- 新增策略快照、动作冻结、次数预算、事件时间线、普通协助单及重新核验阶段。
- 协助类型：密码、验证码、内容资料、审批请求、人工操作、问题确认。普通回复不能扩权；机密输入保持独立通道。
- 密码和验证码各一次；创建待办前先登记预算，清空／输入失败即冻结动作。补充遮罩长度检查与密码眼睛按钮防护，拒绝输入未核实就继续点击登录。
- Operator 限制未纳管的通用 Shell／ADB、任意执行和委派工具；ActionSession 序列化出口在动作真正发出前检查运行时权限。运行时不可达、等待人工、重新核验、取消、失败、过期均拒绝修改动作。
- 已停止控制状态主动终止 Artemis，不依赖模型自行收尾；Web 增加停止按钮；取消与重启分别保留 cancelled／interrupted。
- 可信 APK 安装接入 ensure_trusted_app：Agent 决定调用，任务限定设备和包名、服务端验证批准目录，最多一次；安装期间冻结其他动作，失败或取消后不自动恢复。
- Web observe 模式支持 FB／YT 目标身份格式，禁止设备修改；FB preflight 保留登录至最终发布按钮前的诊断入口。YT preflight 尚未验收，服务端明确拒绝，不伪装支持。
- 保留安全筛选后的 Artemis 检查数量与状态；只读结果工具由运行时检查协助证据，不用空 result 猜测成功。
