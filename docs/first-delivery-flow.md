# 首批业务流程与最小契约

更新：2026-09-29。依据[需求基线](current-requirements-summary.md)至 R-156，落实已确认首批顺序。本文是开发交接草案，接口名称及具体参数随实现细化；不新增业务选项或代表已开发、已验收。

首批实施对应[WP-00～07](engineering/delivery/work-packages.md)，跨端交接使用[CT-01～04](engineering/delivery/contract-checklist.md)，真实验证按[AC 矩阵及分批范围](engineering/delivery/acceptance-matrix.md)。本文件保持业务与最小契约依据，实名任务状态统一维护在[开发台账](engineering/delivery/delivery-tracker.md)。

## 交付目标

运营创建限次限期邀请，提供者通过邀请码／链接及短信验证完成注册，在管理手机逐台扫码关联执行手机，运营与提供者看到同一份真实关联结果。成功出口为“已关联，待完成接入”；继续接入时沿用原设备记录，不要求重新邀请或注册。

账号管理只保留登录、账号列表、开通和停用。首个运营账号由部署初始化；密码恢复先走受控维护处理，保留操作记录，不扩展完整自助找回页面。停用只撤销运营访问，保留项目、设备、历史及原责任信息；其他运营在现有全局待办代办，需要调整负责人时使用既有编辑入口，不增加自动转移、审批或交接页面。账号开通／停用不挡住邀请主流程的设计和开发。

## 正常流程与失败接续

| 步骤 | 操作与成功依据 | 失败或中断后怎样继续 |
| --- | --- | --- |
| 1. 运营登录 | 已开通账号输入账号密码，服务端认证成功后进入工作台，操作关联实际人员 | 认证失败留在登录页；账号停用后旧会话也不能继续操作。密码恢复走受控维护 |
| 2. 创建邀请 | 运营填写注册人数上限及有效期，得到同一邀请的邀请码与链接；可复制发给提供者 | 创建响应丢失查询同一请求结果；生成／复制不标记为已送达。可撤销、另行创建邀请，不自动发送消息 |
| 3. 提供者注册 | 输入有效邀请，验证自选手机号；服务端最终核对邀请有效性和剩余名额，注册与扣减成功后进入本人首页 | 验证码错误／过期留在验证步骤；邀请失效或名额耗尽提示获取有效邀请。失败不扣名额；已成功但响应丢失接续原身份，不再次扣减 |
| 4. 已有身份登录 | 原手机号验证后回到同一提供者，无需再次邀请 | 不因邀请耗尽／撤销另建人；原号码不可用沿用既定人工找回原则，不凭新号码接管旧身份 |
| 5. 执行手机展示关联码 | 用户明确选择将本机接入执行，取得本机关联会话，显示目标标识和有效关联码 | 获取失败如实显示无法连接；会话失效可重新获取，先核对是否已有成功关联。入口不依赖 Tailscale 已准入 |
| 6. 管理手机扫码确认 | 已登录提供者扫码，核对目标手机后确认；中心在同一事务内记录唯一归属和本次结果 | 扫码成功未确认不关联；异主归属／交接未清拒绝覆盖；响应丢失查询原结果，同机多次提交只对应同一关系，多台结果各自显示 |
| 7. 两端查看结果 | 管理端看到本人设备，执行端只看到本机状态，运营看到提供者及设备归属；显示已关联、待完成接入 | 离线或状态未知显示最后确认事实，不能虚报在线或可执行。刷新和重试不改变暂停／退出或重复建设备 |

运营发送邀请先采用复制链接／码、通过现有沟通方式自行发送；本批不建设邀请邮件／短信自动发送模块。提供者登录所需的真实短信验证码通路仍要落实，两者不能混同。邀请人数上限为正整数，到期时间必须有效，具体默认值和验证码参数由实现配置给出，不再单独拆成业务选型。

## 最小数据与约束

这些是业务记录职责，不要求一行一张表，也不建设通用事件平台。

| 记录 | 必需信息与约束 |
| --- | --- |
| 运营身份 | 稳定人员标识、登录标识、密码校验信息和启用状态；不共用固定操作者，密码不明文保存。首个账号初始化幂等，禁止通过并发停用导致最后一个有效运营账号消失 |
| 邀请及注册来源 | 邀请标识、创建运营、凭证校验信息、名额上限、已用名额、到期时间及撤销状态；码和链接指向同一额度，各成功注册提供者可追溯来源 |
| 提供者与管理会话 | 稳定提供者标识、已验证且规范化的唯一手机号、管理会话；短信验证结果绑定号码和用途，短信发送不等于验证成功 |
| 设备与本机身份 | 稳定业务设备标识、所属提供者、本机安装身份及实际状态；本机身份只授权本机必要入口，不获得完整管理权限；网络 IP 或端口不是设备主键 |
| 关联会话与结果 | 会话标识、目标本机身份、到期／失效状态、确认人及关联结果；单次关联凭证与多人注册邀请分别处理，不能混用其次数规则 |
| 请求与操作记录 | 关键写入的请求标识、操作者、目标与结果，用于重复请求接续及最小追溯；不存密码、验证码或邀请凭证原文到普通日志 |

注册事务同时处理手机号唯一性、最终邀请校验、提供者创建和名额消耗；同一号码的竞争不能创建两个人，最后一份名额不能分给两个人。已有身份登录不扣名额、不改变邀请来源。关联事务同时处理会话有效性、目标归属及会话消费；迟到结果只能返回原会话结果，不能覆盖新会话或新归属。

App 重启接续已保存的本机身份；重装或清除数据后无法证明旧关系时，不自动认领旧设备或清除暂停／退出。关联不明复用现有运营处理入口核对，先保留待完成接入，不建设专用重装恢复产品；进入执行前仍须按接入模块核实实际设备及未清交接。

## 最小接口职责

| 调用方 | 必需能力 | 权限及结果 |
| --- | --- | --- |
| 运营 Web | 登录／退出、列出／开通／停用运营账号 | 服务端验证有效运营身份；停用后拒绝其新登录和旧会话操作 |
| 运营 Web | 创建／查询／撤销邀请，查看注册及关联进展 | 配额及失效以中心记录为准，返回可追溯结果 |
| 提供者管理 App | 请求短信验证、受邀注册、已有身份登录／退出 | 首次注册校验邀请和额度；仅取得本人管理范围，退出不停止执行手机 |
| 执行手机 App | 建立／查询本机关联会话，取得关联后的本机身份与状态 | 未关联只开放本机关联准备，不能查询其他设备；过期会话不提升权限 |
| 提供者管理 App | 查询关联目标、确认关联、查询本次结果、列出本人设备 | 扫码后明确确认；按当前会话和提供者权限执行，不接受任意目标覆盖归属 |
| 运营 Web／两类 App | 查看各自范围内的同一设备事实 | 运营、本人全部设备、本机三种读取范围；由服务端校验，未知值不填成功 |

接口采用共同业务状态含义和明确的成功／失败／结果待确认返回。具体路径、类型和会话期限随首批编码落实；暂不增加消息中心、会话管理中心或通用权限配置页面。

## 完成判据与后续接续

- 从实际 Web 创建邀请，经真实短信完成提供者注册，在 Android 真机完成扫码确认，Web 与 App 能核对同一归属。Web 部分使用 Playwright，原生部分保留实际操作证据。
- 覆盖同一邀请供多人注册、邀请码与链接共享配额、并发争抢最后一个名额、撤销／过期、注册及关联响应丢失后的接续；失败不造成功状态。
- 覆盖一人多台设备、另一提供者的访问隔离、同机重复确认及归属冲突；资源不足明确未验证，不以模拟短信、接口预置成功或直接改库替代真实验收。
- 成功只证明身份与归属闭环。随后在同一设备记录上完成授权、受限核验、Tailscale 准入、ADB 配对和连接检查，按已确认安排在模块开发中验证；再接续运营分配及初始化、受控任务执行、平台核验和反馈。
- 实际短信服务、号码发送范围、安装分发入口及多机测试资源在使用前落实；不阻塞不依赖它们的工程与数据实现。核心暂停／退出与未知发布处理不因简化辅助能力而删减。
