# 独立任务队列采用 Redis 与 BullMQ

2026-09-28，用户在 ADR-0006 的独立队列组件对齐中选择 A：采用 Redis＋BullMQ。该组合与已确认的 TypeScript／Node.js 中心后端配合，利用队列的延迟、重试及并发管理能力；由执行适配层消费任务，再调用独立 Artemis 引擎。相比采用 RabbitMQ 通用消息通信方案，当前优先匹配手机任务调度需求，代价是维护 Redis 持久化与恢复，并实现 PostgreSQL 到队列的可靠投递。

PostgreSQL 继续保存任务、尝试、暂停、控制权与结果等权威业务事实。队列重试不得直接重做结果未知的发布，不得重置既定业务恢复预算；队列锁、任务完成和消息确认不能代替设备互斥、实际停止或发布结果核验。执行适配层必须按当前业务事实校验许可并处理重复、迟到及过期消息。

具体 Redis／BullMQ 版本、部署方式、持久化和内存策略、可靠投递机制及故障恢复判据在对应实现前落实；本次不选择付费扩展，不配置真实服务或重放历史任务。真实并发容量与恢复能力须在开发中验证。
