# 手机任务派发采用独立队列

2026-09-28，用户在首期手机任务派发方案对齐中选择 B：增加独立任务队列，PostgreSQL 继续保存权威业务事实。相较直接依托 PostgreSQL 队列表派发，此方案可利用所选队列组件的调度、并发和恢复能力，代价是增加运行组件及数据库与队列之间的可靠衔接工作。此轮只确认独立队列方向；后续组件已按 [ADR-0007](0007-redis-bullmq-task-queue.md) 确认为 Redis＋BullMQ。独立组件不等于必须使用独立物理服务器。

队列投递或处理完成不等于手机任务实际完成或平台发布成功。执行前仍须核对当前授权、分配、暂停及控制权；不同手机可并行，同一手机的所有界面操作统一互斥。领取超时不证明旧执行已停止，未知发布结果不得自动重发，重投递不得重置既定恢复预算。业务写入与待投递记录同事务保存、再可靠转交队列的具体实现仍须落实，并验证重复投递、进程崩溃、队列故障和恢复后的处理；本次不部署队列或重放 Demo 任务。
