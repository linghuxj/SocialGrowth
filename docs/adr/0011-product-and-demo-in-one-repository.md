# 正式实现与 Demo 保留在同一仓库并分目录维护

2026-09-28，用户在仓库组织方式对齐中选择 A：继续使用当前仓库，正式 Web、NestJS 后端、执行适配层和 Android 客户端分目录维护，保留现有 Demo 与历史证据。相比另建正式仓库，此方式便于需求、接口和跨端变更共同审查，代价是明确新旧入口、依赖和数据环境，避免误用验证代码或旧数据。

Android 保持独立构建体系；同仓库不意味着所有组件使用 pnpm，也不改变独立执行进程的运行边界。正式 TypeScript 包沿用仓库统一 pnpm 与唯一锁文件规范，具体目录见技术设计的工程布局草案。本决策不移动或清理 Demo，不迁移、重放历史数据，也不创建新仓库或指定 Git 分支；工程脚手架在进入实现时建立。
