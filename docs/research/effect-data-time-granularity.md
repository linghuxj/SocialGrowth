# 效果数据时间粒度与观察窗口核查

核查日期：2026-09-27。状态：官方资料核查，未调用真实账号数据。已确认需求见 R-087、R-088、R-092 至 R-094；用户已选择允许另设完整统计日窗口，具体指标可用性尚未验证。

## 官方资料确认

- YouTube Analytics 的日期范围参数使用日期，日维度按太平洋时间自然日汇总，夏令时切换日可能不是 24 小时。[时间维度说明](https://developers.google.com/youtube/analytics/dimensions#Time_Periods)
- 查询最多返回到所请求指标均有数据的最后一天，请求结束日期不保证是实际返回截止日期。接口要求授权；收益指标有对应的货币报表授权范围。[查询接口说明](https://developers.google.com/youtube/analytics/reference/reports/query)
- 本轮未成功取得 Meta Insights 参考页内容，FB 各指标粒度与可用性保持未验证，不从 YT 规则外推。

## 对当前需求的影响（推论）

1. 日汇总不能直接拆分成任意精确的发布后小时窗口。例如视频在平台统计日中途发布，某个精确 72 小时窗口的末端可能切在另一天中间，整日总量不足以确定该时刻累计值。72 小时仅为例子，不是已配置值。
2. 反复请求相同的日汇总不会增加小时粒度。每日采集与窗口结束，只证明发起过查询和时间经过，不证明已有完整可比数据。
3. 项目时区可用于调度和业务周期，但不能把来源日汇总直接改为项目日汇总；应保留实际统计区间。涉及夏令时的整日窗口也不能自动当成固定小时数。
4. 查询多个指标时，应检查实际覆盖日期；研究建议按必要口径组织采集和评价，避免将滞后的指标与较新的指标标成同一截止时间。具体实现未定。

## 已选择的处理方式（R-094）

- 已选方案：允许按来源支持的完整统计日另配观察窗口。例如发布后的首个完整平台统计日开始取连续若干天，首个不完整日单独观察。明确实际区间及其与发布时间的偏差，与精确小时窗口分开比较；这会排除最初不足一整日的区间，属于用户已接受的口径变化。同统计日数不保证相同发布后年龄或实际小时数，仍需检查可比性。
- 未选方案：始终坚持精确发布后窗口。允许替代窗口不代表全部指标都有可用数据；替代窗口也无法获得充分数据时，仍暂停该项内容比较，继续采集、项目汇总及不依赖该数据的原批准计划。

不得悄悄用整日汇总、比例摊分或抓取时刻的旧累计值冒充精确窗口结果。能否通过其他获准来源获得足够粒度的数据需另行验证，不承诺手机后台或第三方必然补齐。

## 验证准备

取得实际频道授权后，逐指标记录可查询维度、数据范围、原始时区及更新截止日期；对照不同发布时间的真实内容，验证窗口能否覆盖且可比。FB 同样逐指标核验。当前仅形成研究约束，未将数据接入或观察窗口验收记为通过。
