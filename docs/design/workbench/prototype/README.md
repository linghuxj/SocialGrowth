# 工作台可点击设计原型 0.1

2026-09-27。延续 UI-012 的首页并列布局与 UI-014 的浅色设计方向，将主要页面、确认和返回路径串联。属于设计演示，不是产品实现；新增局部布局也不冒充用户逐项确认。

直接在桌面浏览器打开 [index.html](index.html)，无需启动服务。页面顶栏持续标明演示数据；右上角可重置。示例操作与草稿保存在本机浏览器，浏览器限制本地存储时仅当前会话保留。请勿输入真实密码、验证码或令牌。

## 建议走查顺序

| 场景 | 入口与操作 | 应看到的区别 |
| --- | --- | --- |
| 核实未知发布 | 工作台 → 第3集 → 查看关联任务 → 设备协助 | 同一原任务，不提供重发按钮 |
| 人工介入 | 申请接管 → 展开“原型演示控制” → 授予独占 → 提交说明 → 交还 | 申请、独占、记录、交还、平台核验及设备复核独立反馈 |
| 项目筹备 | 项目 → 短剧出海·二期 → 素材 / 方向摘要 | 保存资料不发布；确认方向保留初始化与入口阻断，无第二次启动 |
| 周期修改 | 运行项目 → 设置 → 保存，下周期生效 | 当前周期保持不变，生效点用两地时区表示同一时刻 |
| 暂停与恢复 | 运行项目 → 暂停 → 演示停止回传 → 概览 → 恢复并检查 | 请求受理不等于停止完成；恢复不补发过窗任务 |
| 正式结束 | 运行项目 → 查看正式结束影响 → 返回或确认 | 可以从运行态直接结束；取消仅作用于确认未提交，未知仍核实 |
| 基础分佣 | 提供者与分佣 → 收入与分佣依据 → 保存说明 | 收入、佣金、已付分开，缺比例保持未计算 |
| 输入连续性 | 任一表单输入后切换页面，再返回或刷新 | 继续编辑 / 保留草稿离开 / 放弃当前输入；其他表单草稿不丢失 |

所有“演示回传”按钮都是测试设计状态的辅助控件，不属于最终产品，也不代表外部执行成功。已处理记录保留用于追溯，首页同时区分待办数和记录数。手机浏览器仅阅读，输入与处理动作禁用；返回桌面宽度可继续操作。

## 覆盖与限制

本版连接 17 个视图，包括首页、两种项目状态、发布安排与详情、设备列表与协助、单条素材资料、方向确认、设置、效果、复盘、提供者、分佣以及项目控制。运行项目与二期筹备项目是两个虚构对象；原型不会从运行项目素材标签跳到二期冒充同一项目。筹备页资源入口进入全局列表，二期真实资源分配尚未展开。

本版优先检查路径和语义，未实现完整批量上传/关联、真实证据预览、首次新建、邀请、资源分配、并发协作、局部请求失败、断线重连、过期版本冲突、服务端草稿与审计、自动收尾定时执行。主流程之外的完整设计仍以[页面规格](../../../workbench-page-spec.md)及静态图稿为准。单页 JS、示例数据和本地存储不构成最终技术选型、权限控制或服务端状态机。

当前在 1500 / 1100 / 390 像素宽度检查代表页面，桌面截图已目视核对；手机部分表格暂用横向滚动，没有完成全部页面的移动阅读优化或完整无障碍审核。示例时间不随真实时钟推进；参数、身份、收益与核验回传都不是实际批准或证据。

## 可复现的原型检查

从仓库根目录执行单次命令：

```sh
pnpm exec tsx docs/design/workbench/prototype/verify-prototype.mts
```

脚本用 Playwright / 本机 Chrome 从本地 HTML 入口填写表单、点击导航与对话框，并通过显式演示控件查看外部回传状态；不直接注入业务成功状态，不启动服务、不请求 HTTP、不操作手机。浏览器回调只用于页面错误收集和读取布局/焦点证据。

- [检查脚本](verify-prototype.mts) / [机器检查结果](checks/result.json)：9 组原型场景，包含状态分离、输入保护、错误对象跳转防止及手机只读。
