# 账号发布身份准备与执行库编排

2026-10-02 创建，2026-10-04 按 R-159 更新登录目标；依据 R-158／R-159 及当前需求基线。此文区分已实现组件与后续正式系统接线，不把 Demo 或纯组件测试当成真实创建验收。

## 策略与执行库的职责

策略／计划选择“让指定手机、已申请账号及发布身份具备执行条件”等业务任务，并在批准范围内引用执行库。执行库保存操作范围、输入、完成事实和停止条件；系统读取当前可信事实、选出下一步并验证许可；Google Artemis 观察真机并决定具体界面动作。不是由库提供固定坐标或固定手机点击步骤。

Page／频道准备无需切片素材，不消耗内容分发名额。创建个人 Facebook／Google 登录账号不在该库中；公司预先申请账号的常规登录按 R-159 由 Artemis 通过受控通道填入系统加密保存的凭据、提交并核验，验证码、双重验证及异常确认交人工，密码不进入模型对话、截图或普通日志。此为目标能力，正式凭据消费与填入通道尚未接线。新 Page／频道的名称、FB 类别与简介、YT 标识名来自真实业务资料，不由模型猜测。平台跳转移动网站／系统登录时必须遵守实际已接线的界面范围；未支持的路径交人工，不仅修改提示词就宣称已支持。

## 登记的操作与条件

| 操作 ID | 作用与条件 | 需要的完成事实 |
| --- | --- | --- |
| `inspect_app` | 检查指定平台 App，检查本身不安装 | 目标包、已安装／缺少、是否可用及依据 |
| `ensure_trusted_app` | 缺少且安装范围允许时使用可信签名安装源 | 安装来源、包与签名核验、应用可用 |
| `verify_parent_login` | 核验指定既有登录身份 | 准确父登录标识及依据，不只显示名 |
| `assist_existing_login` | 未登录时在有效范围内协助登录已申请账号；R-159 目标为受控自动填密及提交，必要验证交人工 | 重新核验准确父登录身份；不注册、不轮换；当前正式填入消费者仍未接线 |
| `inspect_publishing_identity` | 检查准确目标 Page／频道 | 已有候选、确实缺少或歧义；加载失败不视为缺少 |
| `create_facebook_page` | 父登录已核验、缺少已核实、有创建范围及名称／类别时创建一个 | 至多一次创建提交观察；还需独立回读 |
| `create_youtube_channel` | 同上，使用确定的名称及标识名 | 至多一次创建提交观察；不越出界面范围 |
| `verify_publishing_identity` | 核验已有或刚报告创建的身份 | 完整平台 ID、类型、准确名称、管理权及真实证据 |
| `browse_feed` | 策略可选、指定身份及内容范围内有限时长浏览 | 实际观察、耗时与停止原因；不自动授予互动权限 |

浏览的时长、内容范围和停止条件必须由实际任务提供，Artemis 在范围内判断和变化浏览动作。此阶段仅登记其能力定义，没有新增自动浏览调度器、固定养号算法或互动任务。

## 按事实推进，不能一次无条件执行全部动作

`planAccountPreparation` 每次只选择一个下一步。当前分配或父登录不符交人工；设备未决或原创建结果不明先核实原操作；已有绑定不得通过创建替换。App 未知先检查，缺少才安装；父登录未知先核验，未登录才协助。身份未知先检查；已有复用，报告创建后须回读，确实缺少且范围允许才创建。

每步观察须绑定原任务、设备、账号、平台、事实版本及证据来源。执行后记录新事实并重新编排，不依赖旧快照一次完成全部步骤。`reported_ready` 只是组件基于所给事实的分类；证据可信性、当前有效性与绑定激活仍由中心系统验证，不能从该返回开始计佣或解锁发布。纯选择器的 `executionAllowed`、`publicationAllowed` 恒为 false。

真实派发还需要中央持久 Task／原请求去重、当前项目与账号分配、设备参与和单机独占控制、每次底层读／动作的物理许可以及真实回执。执行库的输入和提示词不是这些许可。暂停、掉线、退出、接管及旧操作结果未知时复核原事实，不新建请求键重复创建；恢复初始化不自动恢复发布队列。

## 当前实现与验证边界

- 正式代码：`product/contracts/src/execution-library.ts` 提供独立版本的类型、严格输入结构与九项操作定义；共享下一步选择器位于 `product/contracts/src/account-preparation-plan.ts`，executor 提供 Artemis 操作指令与显式注入的会话适配。没有改写已有发布协议、CT-06 或首批 Android／Python 合同，也没有把 HTTP 调用者提供的布尔值当许可。
- Demo 已有 Web“手机初始化”→运行时 `identity-onboarding.ts`→Artemis／人工协助→身份核验的参考路径。保留原实现，没有因新增库而放宽已有绑定、未决任务或设备控制检查。
- 正式 Web 项目设置已接入初始化检查表单、原任务读取与重新检查。中央 PostgreSQL Task、原请求去重、检查历史和审计持久保存；资源未分配时保存真实阻断。后续只能附加当前项目中央预留且父登录标识一致的资源，不能改写原目标或替换既有绑定。未知响应须接续原请求，不能另起键重复准备。
- 已接入“核验执行条件”与中央不可变核验记录：读取当前任务／资源版本、实际预留、设备暂停、入网记录、控制日志及原未决操作；未实现的本机参与、准确 ADB 授权、每动作保护和可信消费者如实阻断。这是执行准入核验，**不创建 dispatch／任务队列**，也不改变原任务版本。丢响应接续原键；较早任务或资源版本的记录不能成为当前许可，最新记录按中央提交序号排序。
- Artemis 会话适配及 PostgreSQL 启动意图 journal 已实现内部端口：先持久记录原操作，再调用一次 `mobile_run_task`；原 trace 不可替换，启动结果不明、旧操作未决和暂停时先核实原操作。该端口没有注册到正式 worker／dispatcher，没有取得物理许可；模型报告仍是待核验观察，不能激活身份。
- 正式 Web 已可只读查看中央保存的原启动意图、绑定 trace 和最新回执状态／证据引用数量。读取不调用 Artemis／ADB、不产生新截图；服务核对任务／分配／父登录／目标／操作及摘要，损坏或越界回执拒绝展示。`reported` 仍是“执行端报告完成，证据待核验”，未接入独立证据解析或人工反馈消费，不授予身份就绪和发布权限。
- 内部控制日志已增加 `acquire_holder`：只有确认停止、当前内部授权与新 holder 一致时才能取得控制权，授予与不可变范围、命令和审计原子保存。重放返回当前状态，不是新的动作许可；原 holder 不可跨设备或停止后重用，后续事实不能扩大原动作范围或延长原租约。此接口不对 HTTP 开放，真实权威事实加载器尚未接线。
- 执行侧已增加私有 SQLite 逐动作 fence：同一物理序列号不能换逻辑设备，持久动作意图先于受保护 transport 的同步交接；交接与暂停共用写锁。读屏同样需要新的中央动作许可，中央重放不放行；在途／unknown 跨进程重建保留，停止核实还要求实际路径封闭、控制交还及目标静止的可信证据。按原动作核实结束和回执重放均不能重新开启控制。该组件只保护通过其端口的调用，**尚未包住真实 Artemis 的 raw ADB、读屏、人工补图等所有路径**，不得据此开放 worker。
- 尚未接线：实际资源分配到该页面的完整流程、每次底层动作的物理许可实现、正式派发与消费者组合、可信证据解析与绑定激活、可信安装及登录安全人工协助。正式手机执行入口仍保持关闭，不能把 Web 保存请求解释为已触发真机操作。当前原任务范围不可变，变更范围／结束任务的后续协议也未实现。
- 真实验收须由 Playwright 从实际 Web 填表、检查、触发，Artemis 自主观察手机，必要反馈仍由 Web 提交。分别验证已有复用、缺少创建、App 缺少、父登录不符、创建确认丢失、暂停与恢复、两平台及网站／系统界面边界；最后核对平台真实身份和管理权。纯组件测试只验证编排约束，没有创建 Page／频道、模拟业务成功或发布内容。
