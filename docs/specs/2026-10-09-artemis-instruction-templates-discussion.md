# Artemis 指令存储与在线维护讨论

日期：2026-10-09。用户要求保存本次讨论，待核心业务链路稳定后再调整。本文件是后续方案记录，**本轮不开发模板库、不迁移现有指令、不开放运行中指令修改**。不据此改变既有业务范围、动作权限或验收结论。

## 已核对的执行方式

正式业务入口形成任务，系统核对账号、手机、授权及占用，拼装任务描述与业务参数，再通过 MCP 调用 Artemis `mobile_run_task`。主要输入包括 `task_desc`、`device_serial`、`locked_app_package`、`expected_output_desc` 和 `verification_level`；返回 `trace_id` 后，由原任务通过 `mobile_manage_task` 查询状态。

Artemis 根据任务目标、手机实际屏幕、界面结构与历史观察规划操作，执行点击、滑动等动作后继续观察，并按配置核验及输出结果。业务流程和停止条件可以在指令中说明，具体手机动作仍由 Artemis 判断，不用固定坐标脚本替代。系统另行核对实际结果；模型报告或提示词本身不授予权限，也不自动构成业务成功。

当前操作说明位于 [execution-library.ts](../../product/contracts/src/execution-library.ts)，完整任务描述还分布在 [identity-onboarding.ts](../../product/executor/src/runtime/identity-onboarding.ts)、[web-verification.ts](../../product/executor/src/runtime/web-verification.ts) 等入口。[Artemis MCP 客户端](../../product/executor/src/runtime/artemis.ts)负责连接及调用。现有 PostgreSQL／SQLite 保存任务、原操作与回执，尚未接入可在线编辑的指令模板库。

## 稳定后拟采用的最小方案

复用中央 PostgreSQL 存储业务指令模板，后台维护；任务启动前读取有效版本，加入真实业务参数和代码中的固定约束，保存下发快照后再调用 Artemis。主要调整现有任务拼装入口，不要求修改 Artemis 核心，不新增流程设计器或通用工作流引擎。

| 内容 | 拟采用的处理方式 |
| --- | --- |
| 业务目标、操作说明、观察要点、异常处理指引 | 允许在线修改模板 |
| 浏览时长、等待时间等参数 | 允许在线配置，代码限制范围 |
| 账号、手机、身份、素材版本及文案 | 读取实际任务和业务记录，不写死于模板 |
| 发布权限、设备互斥、未知结果不重发、凭据处理及成功校验 | 保留代码约束，模板不能覆盖 |

拟实施的开发范围：

1. 模板保存操作标识、平台、版本、正文、启用状态和修改记录。
2. 简单管理页面提供读取、编辑草稿、预览、启用与回退旧版本；沿用现有运营认证，记录修改与启用操作。
3. 现有任务拼装入口读取模板，校验适用操作和输入，再传给 Artemis；模板不能执行任意代码或扩大工具权限。
4. 任务保存模板标识、版本、实际下发内容及摘要，结果关联原 trace，便于复现；密码、令牌及验证码不进入模板或指令快照，仍经受控通道处理。

在线修改默认仅影响后续启动的任务。排队任务在准备启动时绑定版本；已经绑定或运行中的任务继续使用原快照。启用旧版本只影响之后的任务，不改写历史，不重新执行未知操作。

Artemis 固定上游源码提供 `mobile_manage_task(action="inject_instruction")`，可在下一轮规划／执行循环补充指导。此能力与模板编辑分别处理：更改数据库模板不会自动改变运行中任务。项目目前没有通用 Web 注入入口；首期拟不接入，后续如需使用再讨论目标、授权、审计及原任务边界。

## 实施时机与验证

先完成[核心流程开发清单](../engineering/delivery/core-flow-development-checklist.md)中的账号身份、素材、执行回执等衔接并稳定现有业务入口。之后先选择一个已有身份核验流程接入，验证在线启用／回退、新任务读取版本、在途任务不变化、快照可追溯以及固定约束不被模板覆盖，再按实际需要扩展。

本文件没有将讨论方案登记为已实现功能，也不将模板迁移作为当前线上验证前置条件。具体字段和生效规则在实施前按届时实际任务系统复核。
