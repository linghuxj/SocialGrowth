# 手机初始化业务模板

## 业务范围

手机初始化是内容运营之前的准备模板，不是第五种内容发布策略，不要求上传切片或先生成发布排期。模板按“指定真机 + 一个指定平台 + 一个授权账号”执行；FB 与 YT 分别初始化，结果分别记录，不将其中一个平台的成功视为整机全部就绪。

Artemis 在一次任务内自主判断并处理：设备与应用可用性 → 必要的可信 APK 安装 → 指定账号登录及人工密码／验证码协助 → 已有 Page／频道核验，或明确授权下创建一个缺少的身份 → 完整身份、管理权限与现场证据。此顺序描述业务依赖，不实现固定坐标或逐屏操作脚本。

## Web 操作

1. 在运营项目中登记账号档案、真机设备编号和项目授权。账号档案可以先存在于本系统，平台 Page／频道尚未创建。
2. 账号详情 → 接入 Page / 频道 → 手机初始化（当前平台）。策略草案入口亦有指向账号管理的说明。
3. 填写 Page／频道准确名称、所属登录账号唯一标识、操作授权依据。密码和验证码不得填写在这些普通表单中。
4. 身份处理默认“只接入已有”。未绑定时完整 Page／频道 ID 可留空，由 Agent 在核验父账号及管理权限后读取；歧义交人工。已有绑定必须填写原完整 ID。
5. 若确需新增，明确选择“确认缺少时，授权创建一个”。填写创建资料，FB 类别必填。已有发布绑定不开放创建另一身份；已指定存在的 ID 不能同时授权创建。
6. 提交后先通过已有设备接管流程暂停该设备发布队列，再启动初始化。正在执行／检查的设备不被抢占；初始化结束或阻断后保持暂停，不自动恢复积压发布任务。
7. 在任务中心处理人工待办；Agent 在原任务内复核后继续。初始化通过后核对截图并保存发布绑定，再在任务中心恢复设备。正式发布仍要求素材准入、独占分配、明确批准和即时核验。

## 约束与结果

- 仅安装可信目录中已校验的 APK；不使用商店、任意下载源、卸载、清数据或恢复出厂设置。
- 只登录人工分发的既有个人／Google 登录账号，不自动注册新的登录账号；缺少账号时交人工分发。Page／频道创建与登录账号注册不是同一权限。
- 已登录非指定账号、验证码无法提供、挑战、封禁或登录失败不得通过换号／重复尝试消除，记录人工待办或阻断。
- 当前安装的 Artemis 安全输入与操作桥只允许目标 App 包。若 Google 登录跳至 Play services 或系统账号页面，必须在原任务中请求人工完成该系统登录并返回目标 App，重新观察身份；本轮不放开跨系统应用的通用凭证输入权限。不能把 YT 全新系统登录描述为已无人值守跑通。
- 创建至少要求先核验父登录身份；新建身份提交至多一次。创建能力的任务只要已经交给 Artemis，后续即使返回 blocked，也必须先核验平台现状，不能换任务类型重置创建预算。
- 成功必须同时具备应用可用、父登录身份一致、准确目标名称／完整 ID／正确类型／管理权限及实际截图。缺失证据保留 unknown，不能保存初始化成功证明或自动修改发布绑定。
- 保存初始化核验结果与保存发布绑定分别处理；成功不是永久可用保证，不免除后续身份及授权检查。

## 验证边界

受控回归覆盖 FB/YT 初始化、默认不创建、显式缺少时创建、父身份及目标校验、缺失证据、幂等、未知／阻断创建预算及不产生发布记录。真实 Web 脚本 `scripts/verify-device-initialization-web.mts` 验证实际表单、模式切换和必要资料约束，不模拟真机结果。

全新手机的真实安装 → 登录／验证码 → 新频道创建尚须指定设备、合法登录账号和明确创建资料才能实测；本轮不因开发模板而创建未指定的平台资产。此前 Artemis 模型连接 Broken pipe 阻断仍需单独实测确认恢复，不能把受控测试当作真机闭环。
