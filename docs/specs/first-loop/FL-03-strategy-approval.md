# FL-03：规则、策略与批准排期

状态：规格已整理，应用实现及验收未完成。属于用户确认的首批开发范围；发布 Issue 不触发代码实现或真实运营动作。

## 问题陈述

当前标签评分和前端批准状态不能证明策略有有效依据、素材可用或已获具体执行批准；保存、修改与批量成功提示可能混淆真实许可。

## 解决方案与完成标准

- [ ] 定位/规则保留来源与版本；外部约束、内部规则和待验证经验分开，冲突可处理。
- [ ] AI 仅从合格候选中生成可解释草案，显示依据/假设；缺资料或库存返回原因，不编造历史效果。
- [ ] 新策略先批准范围明确的小批试验；指定版本、账号/内容/入口、量/成本、时效及停止/观察条件。
- [ ] 批准前重读当前资格，并发或批量操作逐项返回真实结果；修改关键内容或目标使受影响旧批准失效。
- [ ] 排期保留业务时区和有效期；不补发过期积压，也不因账号成熟自动免去新策略批准。

## 用户故事

1. 作为运营人员，我希望看到规则、证据和 AI 假设，以便评估并修改策略。
2. 作为审核人员，我希望批准指定版本且批量冲突逐项反馈，以便没有不合格安排被整批放行。
3. 作为项目负责人，我希望目标或权限变化使未开始旧计划重审，以便执行不沿用过期依据。

## 实施决定

复用 ai-engine 和 web-console 的职责，先把准入与评分分开；提示词/输出不能绕过后端规则。采用 design-v1 批准与策略版本、现有表单规格及执行契约。目标/主指标和数值来自项目批准，不新增全局 SLA/频次/赢家公式。具体 AI 接入复用可得配置，受控输出须标记，真实调用按授权执行。

## 测试决定

覆盖 C-01/02/03/04/10/11/12，T-02/10；验证草稿不执行、版本变化、无候选、并发批准、批量部分失败及过期安排。通过服务提交/读回与关键页面结果判断，不仅断言按钮状态或模型文案。

以上为待执行的应用验证计划；此前通过的文档/样例结构检查不能替代。本任务完成记录应附实现提交、实际测试命令与结果、受控及真实接入范围。
