# FL-06：首批集成与变更退出验收

状态：规格已整理，应用实现及验收未完成。属于用户确认的首批开发范围；发布 Issue 不触发代码实现或真实运营动作。

## 问题陈述

单模块实现和通过文档检查不能证明运营人员完成完整任务；尤其变更、未知结果、部分失败和退出可能在模块交界丢失业务约束。

## 解决方案与完成标准

- [ ] 从项目/素材到策略、批准、执行、导流、观察、复盘形成可重复的完整受控流程。
- [ ] C-01～14 的关键路径及异常分支在实际模块间贯通，页面结果与服务端、存储一致。
- [ ] 目标/权限/内容/目的地变化按影响范围处理；未知核对、历史保留、退出停新增及旧链接责任贯穿各模块。
- [ ] 清除将本地演示变更宣称为真实下发/2FA/恢复的误导性提示，分别呈现受控、未接入和真实证据。
- [ ] 汇总每项代码提交、测试结果、未完成/待接入项及其影响，分别记录受控闭环和真实业务验收。

## 用户故事

1. 作为内部运营人员，我希望通过连续操作完成一次完整任务，以便系统能服务实际工作而非孤立演示。
2. 作为项目负责人，我希望任一步变化或退出都能保留正确事实并停止受影响新增动作，以便跨模块行为一致。
3. 作为验收人员，我希望看到可重复测试与分层接入证据，以便不把页面成功文案或替身输出当成真实业务完成。

## 实施决定

采用已有 C/T/F 场景作为验收基线，复用已实现模块，不新增一套业务系统或测试平台。跨模块通过公开业务入口、HTTP/消息接口与持久化读回核对；关键界面使用可重复的一次性 E2E 方式。禁止由自动化 Agent 主动启动常驻服务；具体执行方式须遵守仓库运行纪律。

## 测试决定

首批覆盖 C-01～14，并核对 T-01～12、F-01～06 是否有对应应用测试或明确未完成记录。至少验证正常闭环、无库存、并发内容竞争、目标切换、回执未知/迟到、共享入口、零与无权限、退出、挑战、无改善、跨语言、未接入、明确失败恢复。失败保留日志与状态证据，不跳过或弱化断言。真实 FB/YT 发布和供应商验证单列。

以上为待执行的应用验证计划；此前通过的文档/样例结构检查不能替代。本任务完成记录应附实现提交、实际测试命令与结果、受控及真实接入范围。

## 不在本次范围

不把受控集成通过认定为生产发布许可；不执行未经授权的上线、生产迁移、真实账号操作、额外商业承诺或后续 PG-11～16 全量功能。
