# FL-01：客户授权与内容准入

状态：受控应用实现与自动化验收已完成；生产 PostgreSQL 迁移、真实账号授权及平台发布仍待对应接入证据。

## 问题陈述

运营无法仅凭当前账号列表和文件级锁判断为谁服务、有什么权限、哪些语言版本是同一内容；并发和历史发布也不能由旧字段完整表达。

## 解决方案与完成标准

- [x] 项目草稿可保存并列出缺口；动作所需授权不足时只阻断对应操作。
- [x] 所有方、服务客户、授权范围/期限及共享批准分别持久化；历史关系和退出记录可追溯。
- [x] 素材准入核对权利、语言/目的地适配、内容身份与重叠依据；无合格库存形成缺口，不自动付费生产。
- [x] 多语言版本共用身份和归属；身份级原子操作保证竞争分配最多一个账号有效，已发历史阻止同账号重发。
- [x] 释放需所有版本均未提交、无历史、旧批准及在途安排失效；未知结果不能释放。

## 用户故事

1. 作为运营人员，我希望建立客户目标和账号授权关系，以便每个动作都能回到有效服务范围。
2. 作为素材审核人员，我希望核查版本、权利和剧情重叠，以便形成真实可用库存。
3. 作为审核人员，我希望冲突分配、未知结果和已有发布被拦截，以便取消或退出不会产生重复发布资格。

## 实施决定

采用现有 design-v1 的项目/账号服务关系、共同内容身份及尝试模型。PostgreSQL 为权威状态源，身份级事务或等效原子保护；缓存锁不能独立决定资格。先实现最小接入/库存操作及服务边界，旧 SQL/JSON 按证据迁移，无法确认的记录保持待核查。共享例外、重叠核对和失败恢复不新增阈值。

## 测试决定

覆盖 C-01/02/03/08/11/12，T-02/03/04/07 的本任务存储部分；在实际存储边界验证竞争分配、回滚、重读和历史保留。对授权缺失、草稿保存及准入失败验证可观察响应；unknown 及旧提交历史不能因重导入释放。

以上为待执行的应用验证计划；此前通过的文档/样例结构检查不能替代。本任务完成记录应附实现提交、实际测试命令与结果、受控及真实接入范围。

## 不在本次范围

不实现客户门户、素材生成、全量托管或真实平台发布；不擅自执行生产迁移。
