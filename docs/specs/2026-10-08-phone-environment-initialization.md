# 连接后的手机环境初始化

范围：手机已通过本机关联、无线配对和中心硬件核验后，自动准备网络客户端并核验 FB／YT。复用现有执行库、Artemis、执行回执和人工协助。首次配对及系统 VPN 授权仍由机主完成。本流程不授予登录、账号变更或发布权限。

## 执行顺序

1. 后端核对当前关联、安装代次、端点和真实硬件；每 15 秒检查一次已连接设备。
2. 为同一安装及归属生成固定请求编号。掉线后查询原任务；失败、未知或进程中断不自动重跑。不同手机并行派发，同机互斥；一台手机慢响应不阻断其他手机。不覆盖人工接管或未决业务。
3. 执行器核验受保护配置、凭据有效期和中心地址。检查官方 Tailscale 的安装状态；不启动第二个 VPN。
4. Artemis 先观察本机状态，在同一任务中调用一次 `prepare_phone_environment` 可信工具，检查 SFA、FlClash、Facebook、YouTube。已有受支持版本保留；缺失应用由手机直接从 OSS／S3 短期下载授权下载；工具先核验目录包的签名、哈希、版本、SDK、ABI 和所需 split，再核对手机下载后的大小与完整 SHA-256，通过本机安装器提交。不卸载或清除数据。
5. 按本次接入生成独立 SFA 节点及持久状态目录。私有文件临时交付到本机，仅供正常导入；不把凭据放进模型文字、Web 回执或日志。完成后删除交付副本；未知停止保留副本供原任务核对。
6. 全流程使用同一个最多 60 分钟的 Artemis 原生准备权限；下载安装校验和私有配置交付均发生在任务内工具调用中，不在 Artemis 启动前预安装。正常导入 FlClash 与 SFA 文件，保留其他配置。FlClash 使用本地 7890 代理、Global、VPN 关闭；SFA 是唯一 VPN，内置 Tailscale。需要系统授权时暂停并提示机主。
7. Artemis 在实际画面分别核验 FlClash 核心、SFA 运行、Facebook 新在线响应、YouTube 播放推进至少 20 秒。四项检查均须通过；缓存页面或成功文字不能代替检查证据。
8. 中心独立核对在线节点、节点密钥、无线端口及原硬件，同时观察反向连接和 Tailnet 连接至少 5 分钟。通过后才交接管理通道。

5 分钟是本次接入检查窗口，不能证明数小时运行、锁屏、重启、网络切换或新手机首次接入已验收。初始化失败保留原回执及接管状态，运营核对后处理；不以联网结果恢复未知业务或发布许可。

## 配置位置

- 后端开关：`SG_PRODUCT_PHONE_INITIALIZATION_ENABLED`，默认 `false`。
- Docker：在生产及执行 overlay 后使用 `product/deploy/compose.phone-initialization.yml`。
- 服务器私有目录：`SG_PHONE_PREPARATION_DIR`，0700，运行用户可读。`initialization.json`、`sfa-template.json`、`subscription.yaml` 为 0600，均不提交 Git。
- `initialization.json`：协议版本、允许的产品设备编号、中心 Tailnet IP、接入密钥到期时间、SFA／订阅文件路径、代理组／批准节点、观察秒数。当前候选只允许现有 Samsung；新增设备须配置允许范围及可信应用包，不能套用另一手机节点或密钥状态。
- `catalog.json`：可信包元数据、签名与 SHA-256，以及本地校验副本路径、对应云端 `objectKey`（`phone-apps/<SHA256>/<file>.apk`）。缺少应用来源或完整包时拒绝安装。
- `app-storage.json`：复用现有云存储配置字段，0600，仅执行器可读。`SG_APP_STORAGE_FILE` 指向该文件。OSS APK 使用官方支持的 Authorization 请求头签名，S3 使用短期签名链接；访问授权和凭据不进入 Artemis 文字、Web 或日志；下载失败或安装结果未确认不自动重发。当前 Samsung 使用系统提供的 HTTPS 下载工具，缺少该工具的其他机型须另行验收，不能视为通用新手机通过。
- 执行器 ADB：`tcp:127.0.0.1:5038`，与后端健康检查使用的 5037 分开，避免健康检查超时断开大文件传输。Artemis 子进程同时接收一致的 ADB host、port 和 socket。两个端口均不向公网发布。

2026-10-09 已在 mh 部署 dev 开发候选并启用自动准备；main 尚未晋级，正式验收暂停，实际初始化尚未完成。实际通过、失败和未验证项见[本轮记录](../engineering/delivery/records/phone-environment-initialization-20261008.md)。此前已成功的共存检查见[既有记录](../engineering/delivery/records/network-preparation-core-chain-20261007.md)。

## Web 验证入口

执行 `SG_PRODUCT_WEB_SCOPE=phone-initialization pnpm test:playwright`，使用 `SG_PRODUCT_WEB_URL` 和受保护的 `SG_PRODUCT_DEPLOYMENT_LOGIN_FILE`。多设备时指定 `SG_PHONE_INITIALIZATION_DEVICE`。`SG_PHONE_INITIALIZATION_RETURN_CONTROL=true` 仅在没有未决业务时，从页面交还现有运营接管；不清除初始化失败的接管。脚本始终查询原任务，等待窗口结束返回待确认，不取消或新建手机任务。人工请求需要机主实际完成，再从 Web 提交确认。结果及截图默认写入 `output/playwright/phone-initialization/`。

## 当前优先范围与多机 Web（2026-10-09）

按 R-176，先暂停测试及账号／发布验收，优先完成手机环境准备。Web 按手机展示原任务、可信 App 检查、配置交付、实际网络配置／核验、至少 5 分钟双通道观察、连接切换、占用及机主待办。步骤来自执行器的持久回执，不从定时器推算成功。人工回复及单机请求不冻结其他手机；设备清单并行核对，已授权手机断开时保留任务卡片，历史网络模式仅供显示，不能视作当前连接授权。人工准备请求按手机和运营会话保留原请求编号，刷新后仍查询该回执。

Artemis 协助客户端同时接收当前产品设备编号和实际远程序列号，禁止使用另一手机的默认值。私有配置、交付目录、节点名和请求编号按当前接入隔离；新增手机仍须在受保护配置中明确授权，不自动套用已有手机的授权范围。

已有初始化可从 Web 执行“核对原停止证据并继续初始化”，没有额外确认弹窗。支持首次模型超时无动作，或 helper 连接／ADB 离线导致的启动失败；后者须核对原引擎 failed、完整初始连接异常栈及归档空 steps、监督会话已结束且没有动作／安装事件；历史 closed 缺少 stopped 时仅允许空启动 trace 的失败，不用于模型超时恢复、无在途任务和人工请求、原占用与时间匹配、全部端点及硬件别名无锁、当前硬件匹配。仅对证据完整的执行前失败交接原占用，保留 UNCONFIRMED 和衔接记录，每个原失败使用固定后续请求编号。后续任务沿用根请求，刷新及响应丢失不增加任务。

当前只有现有 Samsung 在服务器初始化允许范围内。多机代码能力不表示已完成多台真机验收；本轮不运行验收测试，后续另行记录实际初始化结果。

2026-10-09 用户明确授权解除此前初始化占用并重新触发，同时修复恢复缺口。历史任务须从 Web 明确续接；新策略创建的任务若仍在启动前失败，自动派发在停止至少 30 秒后核对同一证据并最多恢复两次，按手机独立处理。手机动作已开始、可信安装／配置状态未确认、进程中断、证据缺失或达到次数上限时保留原任务和占用。Artemis helper 只读探测预算通过 `SG_ARTEMIS_HELPER_PING_TIMEOUT_SECONDS` 配置，初始化默认 8 秒，允许 2–30 秒；变量显式传入 MCP 及其子进程，其他业务网络代理不变。


### 2026-10-09 后续执行修订

初始化收到首张手机观察图后，先调用一次可信准备工具；关联、硬件、独占权由中心验证，模型不重复生成关联审计报告。准备工具执行前禁止导航，避免规划或导航耗尽任务窗口。仅这类任务的 Artemis Planner 每轮最多两次笔记迭代，规划格式校验和动作防护保持。

Web 可显式核对因任务窗口耗尽而停止的原初始化：无安装或配置、进程结束、监督停止、设备锁释放，且 SDK 和监督证据证明零动作或唯一的正式 App“手机准备”页面导航时才能续接。该分支不自动重发，计入最多两次恢复；其他未知操作保留原回执及占用。


### 实测后的配置衔接与时限（2026-10-09）

真实任务在约 14 分钟执行上限处终止，期间已完成可信准备并执行 16 步，但尚未配置完毕。因此手机初始化独立使用 40 分钟执行窗口及额外 5 分钟稳定观察余量；其他检查保留原窗口。

准备后的配置衔接仅由明确 Web 操作触发一次：要求原任务因执行时限停止、可信准备有完整结束记录、全部已授权导航与 SDK dispatched 步数一致、无失败动作／安装未知／业务或协助未决、原引擎和全部锁已停止，且当前硬件一致。新任务先检查已安装 App（禁止再次安装），核验并投递原准备请求的配置，保持原 SFA hostname、状态目录与配置命名空间；Artemis 必须先观察当前 UI，并沿用已经导入的对应配置，不重复创建配置或覆盖其他配置。原 UNCONFIRMED 回执保留；不能凭页面导航、延长时限或续接受理宣称成功。再次失败不自动续接。

### 2026-10-09 VPN 阶段管理通道修复（用户已授权实施）

SFA 排除 FlClash、官方 Tailscale 及 SocialGrowth 管理 App；FB／YT 仍经批准的业务代理。保持原内置 Tailscale hostname、状态目录和中心 ACL。修复配置以 `management-v2` 文件及配置名交付：旧配置保留但不再选用，新配置仅导入一次，续接复用新配置，禁止编辑、读取或导出配置原文。文件投递不能代替应用内导入完成。

先由 Artemis 配置并启动 FlClash（Global、7890、VPN 关闭、批准节点），再通过受任务权限约束的只读检查，用本机 SOCKS 发出无账号信息的 HTTPS 204 请求；未通过不能进行 SFA 操作。SFA 启动后，中心核对 Android 实际活动 VPN 的唯一性、SFA UID、管理及 FlClash UID 不入 VPN、FB／YT UID 仍入 VPN；不能以进程或服务存在代替。四项原生画面检查及五分钟双通道观察仍须完成，观察期间持续核对实际 VPN 和代理。

短暂反向通道失败时，仅探测原硬件和原端点，Web 按手机显示恢复中；连续失败超过 60 秒停止并保留原任务及占用，不自动重新安装、导入或重放点击，不把网络故障误提示为手机需人工打开。系统 VPN 同意等真实机主授权仍须人工完成。

部署后实际 Web 续接发现辅助 capability 仍受 15 分钟限制，在启动 SDK 及准备工具前被拒绝。仅明确手机初始化权限放宽为 45 分钟（40 分钟执行与 5 分钟观察）；登录及其他任务保留 15 分钟。对于此准确错误，须核对无 trace、无 capability／监督事件、父任务已有完整准备与停止证据、原占用、所有设备别名无锁及当前硬件，Web 才可续接一次；沿用原配置与禁止重装策略，不改写失败回执，不扩展自动恢复预算。

Android `NetworkCapabilities` 的 UID 区间集合按实际 ArraySet 花括号格式和既有无花括号格式解析；依然要求完整区间、唯一 SFA 所属、管理排除与业务覆盖，不放宽未知输出的拒绝条件。运行中的 Artemis 不被部署打断，候选构建与现场观察独立进行。

### 2026-10-09 40 分钟实测后的有界配置补完

真实任务已完成 52 步导航且代理 HTTPS 检查通过，但 40 分钟到期时 SFA 仍未形成实际 VPN，未断链。初始化执行窗口修订为 60 分钟、手机初始化 capability 上限 65 分钟；其他业务与登录时限不变。明确要求在 SFA 普通设置选择 VPN 服务模式，Proxy-only 服务及状态栏图标不能代替实际 VPN；必要时仅通过 SFA 正常 UI 停止旧服务以应用本任务的修复配置，保持 FlClash 与 SocialGrowth。

为完成本轮修复后的重测，准备完成后的显式 Web 配置续接上限从一次修订为两次，仍不自动执行。每次均核对原 SDK 取消及进程退出、全部导航与监督许可一一匹配、无失败动作／安装未知／业务或人工待办、原占用、全部设备别名锁及当前硬件。沿用最初 `initializationPreparationRequestId`，不随续接创建新的节点／状态目录，不重装应用；Artemis 首先观察并复用已导入配置。新增持久次数用于跨重启守住两次上限，历史已有准备命名空间的任务计为已使用一次。未满足证据或达到上限继续保留未知回执和占用。


2026-10-09 部署后恢复补充：Android 端点服务对权限拒绝原本设置重新选择通道，却随即 fatal 停止；修正为同一安装身份经当前服务端确认仍关联有效后的一次重核，再重新选择并验证通道。真实撤权、身份变化、重复拒绝或显式暂停仍停止；不修改 VPN／配对／账号、不恢复业务动作。现场此次断线尚缺少手机日志归因，新 APK 未送达前不宣称其恢复能力已真机验证。
