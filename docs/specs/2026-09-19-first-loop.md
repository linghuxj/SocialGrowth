# 首批开发总规格：PG-01～PG-10 完整业务闭环

规格版本：2026-09-20-v2。范围已经用户确认；FL-01～06 的受控实现与自动化验收已完成，未部署，也不代表生产迁移、真实平台接入或运营授权。G 系列业务规则优先，工程细节引用 design-v1，旧审计意见不自动成为新要求。

## 问题陈述

内部运营需要从客户目标、账号和素材出发，形成有依据的策略，批准并执行安排，理解发布和导流结果，再决定下一轮动作。当前产品材料已描述该流程，但旧 TASK 不能覆盖全部首批工作，现有代码仍包含演示数据、文件级旧锁、按平台路由和占位成功回执，不能据其界面或 DONE 标签判断真实业务可用。

本规格把 PG-01～PG-10 转成有依赖、可领取、可验证的开发任务，保留正常、异常、权限与退出行为。商业数量/月份不作为研发开工或产品容量上限。

## 解决方案与完成标准

首批贯通“项目及授权 → 内容准入 → 规则与策略 → 审阅及排期 → 执行与入口 → 观察与复盘”。变更、暂停、结果未知和退出贯穿全程。默认服务内部运营，现成素材优先，真实发布沿用 FB/YT 原生 App 纯物理真机路线。

| 编号 | 可验收结果 |
| --- | --- |
| AC-01 | 可保存不完整项目草稿；需要真实操作的授权缺失时，仅阻断对应动作；所有方、服务客户、权限和共享例外可追溯 |
| AC-02 | 多语言文件引用共同内容身份；准入先核对权利、重叠与适配；并发批准不产生跨账号归属，原账号也不能另发已发内容 |
| AC-03 | 策略显示目标/规则/证据版本与假设；无合格素材返回缺口；保存不是批准，新策略试验先经人工批准 |
| AC-04 | 批准绑定具体版本/范围/排期；修改与目标变化使受影响旧安排重审；批量操作逐项报告结果，不以整批成功掩盖冲突 |
| AC-05 | 任务仅路由到当前绑定账号的设备；技术状态、设备状态及发布事实分开；未知不重发/释放，迟到证据不重启旧安排 |
| AC-06 | 入口与实际客户/内容目的地相符；共享入口说明真实可归因范围；变更或退出按约定处理旧链接，不转给无关客户 |
| AC-07 | 观察保留来源、时间窗、定义和范围；零值、缺失、延迟、无权限分别呈现；来源变化须核对可比条件 |
| AC-08 | 复盘引用原目标及批准判据，区分未完成、无改善、证据不足和有效范围；新试验/扩大范围不自动获准 |
| AC-09 | 目标/权限/素材/入口变更和退出可定位影响；未开始安排重审，进行中/未知结果核对，历史事实保留 |
| AC-10 | 演示或受控数据明确标记；用户界面不把本地状态更新、占位 URL 或验证码录入宣称为实际发布/验证/恢复成功 |

完成状态分层：每个任务交付实际代码和针对性测试证据；首批受控闭环需完成集成和关键界面验证。真实发布、真实供应商采集与运营启用另附对应证据，没有接入的部分明确标记待接入，不能用模拟结果关闭真实业务验收。

## 用户故事

1. 作为运营人员，我希望建立或选择客户项目并明确当前目标、责任和账号授权，以便知道每项安排服务谁、是否有权执行。
2. 作为运营人员，我希望资料不全时先保存草稿并看到具体缺口，以便继续准备，不误把草稿视为有效授权。
3. 作为素材审核人员，我希望识别同内容的语言版本、权利及剧情重叠，以便形成合格库存并防止重复发布；缺货时形成补充请求。
4. 作为运营人员，我希望查看 AI 引用的规则、目标、证据和待验证假设，以便审阅和调整候选策略，而不是接受无依据的自动指令。
5. 作为有权限的审核人员，我希望批准明确版本和边界并看清批量操作中的逐项冲突，以便只有有效安排进入排期。
6. 作为运营人员，我希望执行只使用目标账号的专属绑定设备，以便不会因其他手机空闲而串号发布。
7. 作为异常处理人员，我希望超时或失联时看到未知结果及关联暂停范围，以便核查证据，避免重发、释放或盲目恢复。
8. 作为异常处理人员，我希望明确失败后按当前权限和排期批准原账号恢复，以便保留旧尝试，并且不会重发已有发布历史的内容。
9. 作为运营人员，我希望维护与客户内容一致的入口并理解共享入口的归因限制，以便不误导受众或伪造单条效果。
10. 作为复盘人员，我希望区分真实零值、数据缺失和来源变化，以便按原主指标评价，完整试验无改善时也能如实记录。
11. 作为项目负责人，我希望目标改变或合作结束时处理受影响计划、历史内容和旧链接，以便停止新增而不丢失事实或转用客户资产。
12. 作为验收人员，我希望明确哪些证据来自离线替身、实际设备或供应商，以便分别判断实现正确性、接入和运营可用性。

## 实施决定

**已确认边界**：沿用 web-console、artemis-controller、ai-engine、shortlink-service 的模块职责；PostgreSQL 为核心事实源，缓存/对象存储按既有路线使用。纯真机、同设备同平台单账号、FB/YT 当前范围、内容一次发布及人工边界不变。无须重开 G-01～G-05 访谈。

**design-v1 工程基线**：统一内容身份与多文件版本；账号所有权/授权/客户服务关系分离；独立批准、执行尝试及发布事实；身份级原子并发保护；带版本的执行契约、去重及迟到证据处理；关键表单与离线场景采用已有工程规格。新增关系是实现既定事实，不新增收费单元或岗位。

**开发中落实的技术细节**：先核查现有模块复用与差异，选择单一 WS 或 gRPC 传输适配并统一两端契约；具体服务入口、DDL/迁移和运行时校验随相关任务实现。不得同时建设两套传输，或把这些实施细节包装成新的商业门槛。若要改变已确认技术路线或扩大业务范围，才需要额外确认。

| 开发项 | 范围与 PG 映射 | 集成依赖 | 完成证据 |
| --- | --- | --- | --- |
| [FL-01 客户授权与内容准入](first-loop/FL-01-context-assets.md) | PG-01/02，PG-10 基础关系 | 无；核对现有数据与演示边界 | 持久化、准入/身份、并发及最小接入/库存交互 |
| [FL-02 导流入口与维护](first-loop/FL-02-destinations.md) | PG-07，PG-10 的入口变更/退出 | FL-01 的项目/账号/内容引用 | 入口及版本、访问/过滤/响应记录、真实归因范围 |
| [FL-03 规则、策略与批准排期](first-loop/FL-03-strategy-approval.md) | PG-03/04/05，PG-10 的版本失效 | FL-01；批准完整入口前接 FL-02 | 可解释草案、有效批准、并发及逐项批量结果 |
| [FL-04 执行与异常核对](first-loop/FL-04-execution.md) | PG-06，PG-10 的暂停/恢复 | FL-01/03 的归属、批准与排期 | 精确路由、契约、状态/证据、离线异常测试；真实接入单列 |

| [FL-06 首批集成与变更退出验收](first-loop/FL-06-integration.md) | PG-01～10 集成，PG-10 横贯全部 | FL-01～05 的相关边界 | C-01～14 集成证据、界面及持久化一致性、接入状态清单 |

依赖表示集成时需要的实际成果，不禁止提前以明确标记的契约替身开发。FL-01～05 必须同步实现自己负责的权限/异常/变更行为，不能把基础规则全部留到 FL-06；FL-06 负责跨模块查漏与验证。旧 TASK-01～07 纳入相关开发项；TASK-08～10 不替代产品功能完成。

## 测试决定

复用已有 C-01～14、T-01～12、F-01～06，不重设业务门槛。公共验证边界为：客户端提交/读回的业务结果、服务接口、数据库事务及持久化记录、Controller/Agent 消息、短链 HTTP 响应和指标适配器输出。避免只断言内部函数被调用或设备变 idle。

| 层次 | 计划验证 | 当前证据 |
| --- | --- | --- |
| 模型/服务 | 权限、跨语言身份、并发、版本失效、历史保留；在实际服务/存储边界测试 | Web 领域测试 17/17；浏览器存储重读通过，生产 PostgreSQL 待接入 |
| 执行契约 | T-01～12 的路由、去重、超时未知、迟到、挑战、过期及关联暂停；可控时间、进程内替身 | Controller 5/5；占位成功与模拟器支持已移除，真实 WebSocket Agent 待接入 |
| 数据评价 | F-01～06 的零/缺失/延迟/无权限/来源切换/无改善；基于原批准指标与质量要求 | 受控评价测试通过；真实供应商证据待接入 |
| 关键界面/集成 | C-01～14，通过实际入口操作并读回存储/结果；覆盖批量部分失败、未知无重发和退出 | 跨模块测试 3/3，Web 生产构建通过；人工业务验收待执行 |
| 外部接入 | 真机原生 App 执行、公开证据、真实账号权限、供应商字段及受众入口 | 待真实接入核查；替身结果不能代替 |

不启动常驻后台服务。测试框架和一次性执行入口由对应任务按现有依赖合理选用；遇到需要实际账号/付费调用/生产动作的验证时，先核实已有授权和接入事实。普通离线断言不逐项请求业务批准。测试报告必须保留失败证据，不靠跳过用例或降低断言通过。

## 不在本次范围

- PG-11～16 的完整托管深化、系统化试验、多业务模板、内容生成和新平台扩展；首批所需隔离、缺货返回及基础观察仍保留。
- 客户门户、新收费流程、多级审批、新岗位、新增商业预算/频次/SLA/视频月份承诺。
- 更换纯真机或数据库等既有技术路线、生产迁移/部署、真实账号发布及供应商付费调用的自动授权。
- 把规格发布或 ready-for-agent 标签视为代码完成、商业达标、真实发布或无人值守运营许可。

## 补充说明与依据

任务认领后先记录代码差距与复用范围，完成时附提交、测试命令/结果、受控与真实接入状态。ready-for-agent 表示规格已可供执行者领取，依赖仍以每项说明为准。后续批次不受商业数量框定，可依自身依赖另行细化。

必须补充的外部事实包括真实账号/内容权利、平台许可、设备与 Agent 接入、指标供应商字段和项目具体运行窗口；它们只约束依赖这些事实的动作，不阻止其他开发。暂无需要用户再次选择的首批业务取舍。

当前代码证据：首批工作台实现 design-v1 受控状态和浏览器存储；Controller 已按指定真机/账号精确路由并删除占位成功与模拟器样例；策略生成仍为明确标记的受控输出。生产数据库、真实 Provider、WebSocket Agent、真机原生 App、真实入口和指标供应商均未接入，不得把受控结果当作实际接入。
