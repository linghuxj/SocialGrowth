# SocialGrowth 首期业务流程复核稿

更新：2026-09-26。依据本轮 R-001 至 R-070 整理，属于业务流程复核稿，不是实现设计或验收结果。条目来源以[需求对齐记录](requirements-alignment.md)为准，旧归档不作为当前业务基线。

## 主流程

项目目标与资源准备 → 成品输入与核查 → AI 策略方向确认 → 可执行计划 → 手机发布与核验 → 效果采集 → 周期复盘 → 范围内自修正并执行下一轮。

策略、计划、执行和反馈构成持续闭环。运营人员负责方向和边界、重大问题及必要验证，不逐条审批常规发布。

| 阶段 | 业务处理 | 产出与继续条件 |
| --- | --- | --- |
| 1. 项目准备 | 内部运营为自营或客户业务建立项目，明确阶段目标、范围与现成引流入口；分配公司账号与手机 | 账号和手机同期项目专用，区分登录身份与 FB Page；账号资格按实际证据判断 |
| 2. 设备与账号就绪 | AI 协助已有账号登录、初始化与发布身份核验，必要验证由人工处理 | 正确身份、权限、连接及执行能力可用；凭据不进入 AI 对话、截图或普通日志 |
| 3. 成品输入 | 运营批量上传成品、来源及未发布声明；短剧可提供原创或委托制作证明；检查重复与语言版本归组 | 可用于分发的成品及其约束；疑点转人工，系统不承担剪辑或配音制作 |
| 4. 策略形成 | AI 结合项目目标、账号资格阶段、内容与数据形成策略；未达标账号优先推进分成资格，同时保留引流 | 运营确认初始方向与自主优化范围；策略仍受平台实际能力约束 |
| 5. 计划安排 | AI 选择内容、账号、版本、形式、文案和时段，安排引流路径、并发队列及有效窗口 | 每平台同一内容只选一个账号与语言版本；连载还须满足固定账号和剧集顺序 |
| 6. 手机执行 | 在批准范围内使用真实手机完成发布；人工接管时暂停该手机 AI 操作 | 必须核对平台、身份与内容并保存证据，不能以操作结束代替发布成功 |
| 7. 数据回收 | 取得发布结果及可用的观看、成长、资格、收益、引流数据，记录来源、时间和缺失 | 引流采用过滤后点击；允许账号级统计，不能证明内容来源时保留未知 |
| 8. 复盘修正 | AI 按项目配置周期评价反馈，调整范围内计划并继续执行；重大异常及时处理 | 保留依据与策略、计划版本；改目标、方向或突破范围交运营确认 |

这些阶段存在业务依赖，不强制所有准备工作串行完成。数据不足时不虚构策略效果，也不把所有发布都变成人工审核。

## 产品展示与短剧的分支

产品展示使用已完成素材和业务方现成入口，首期不包含承接页面建设。AI 同时服务账号成长、广告收益及产品引流，按项目和账号阶段作取舍。

连续短剧以整部剧在各平台固定连载账号；每个平台分别检查前一集成功后，才执行后续依赖剧集。独立宣传片可自由排期，但仍遵守发布范围及窗口。

例如 FB 第 3 集失败、YT 第 3 集成功：FB 第 4 集等待，YT 第 4 集可以按计划推进。若两者依赖的同一台手机掉线，则按手机实际影响暂停，不能将平台独立进度解释为设备故障也可忽略。

YT 同时支持 Shorts 与常规视频，按已有成品与目标选择。可点击入口及具体跳转路径尚待验证，不能把填入链接直接当作引流可用。制作来源证明也不能直接替代平台变现资格核验。

## 异常与恢复

| 情况 | 已确认处理 |
| --- | --- |
| 发布结果不明 | 先核实实际结果，不能直接重发；连载后续依赖保持等待 |
| 尚未开始的任务错过排期 | 在批准有效窗口内重排，超窗交运营处理 |
| 需要验证码、授权或人工验证 | 暂停实际受影响范围；其余任务继续，必要时现场协助 |
| 人工远程接管 | 暂停该手机 AI 操作；交还后由 AI 复核，通过才恢复 |
| 账号或设备不可用 | 按实际影响局部暂停；不能自动换号破坏固定连载约束 |
| 主目标数据缺失 | 继续原批准范围内计划，暂停依赖缺失数据的优化并尝试补齐；缺失不记作零 |
| 引流只能归因到账号 | 评价账号整体结果，不推定单条视频的引流贡献 |
| 调整超出批准范围 | 交运营确认新的方向或范围，再落实后续计划 |

## 尚待落实的验证条件

- 真实 Page/频道的变现状态、数据权限、可点击引流入口与适用内容规则。
- 实际国家、语言、复盘周期、观察窗口、统计过滤参数及业务目标值。
- 原厂 Android 的支持型号与版本、代理部署与权限、远程接管及锁屏、后台回收、重启后的恢复。
- 管理连接与业务上网在实际部署地点同时可用；Tailscale 等仍是候选方案。
- 20–50 台管理的容量、并发、完成率、时延与恢复阈值，先实测再确定。

上述未决项不从旧代码或旧验收报告补成已确认结论。首期试运行以真实完整闭环验证通过为准，系统验收与商业目标持续评价分别记录，见[验收清单](acceptance-plan.md)。
