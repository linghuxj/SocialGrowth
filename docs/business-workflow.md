# SocialGrowth 业务流程

更新：2026-10-06。描述当前有效要求的目标业务流程；R-160～R-163 对单手机、零准备接入及自动连接的修订优先。实际已有接线和待实现范围另见当前实现，不把目标流程当完成清单。范围与配置详见[需求基线](current-requirements-summary.md)。

按 R-153，内部运营通过本系统独立账号登录，保持首期运营同权并记录实际操作人；当前不接入既有公司 SSO。提供者注册及设备关联不创建运营资格，登录按 R-154 使用账号＋密码；R-155 确认首个账号由部署初始化，后续有效运营通过页面开通／停用其他账号。按 R-156，停用只阻止继续访问，保留历史和原责任信息，不自动暂停／恢复项目或设备；未完事项继续由其他同权运营在现有全局待办代办，不增加自动转交或交接审批。

当前以业务闭环为优先，辅助功能按最小方式落实；首批“邀请 → 登录 → 逐台关联 → 状态可见”的正常、失败及重试路径见[首批闭环](first-delivery-flow.md)，完成后按本文件接续设备就绪、执行与反馈流程。

## 职责

| 参与方 | 负责的事项 |
| --- | --- |
| 设备提供者 | 通过客户端注册并接入专用执行手机、参与基础分佣；按授权范围提供设备，不继承内部运营权限 |
| 运营人员 | 提供目标、约束及真实业务输入，确认初始方向，处理方向变化、越界、重大异常和必要验证 |
| 业务 AI | 理解素材与账号条件，形成策略与可执行任务，根据执行与效果反馈作范围内修正 |
| Artemis 执行 AI | 承接获准手机任务，识别当前界面、判断具体动作、执行并回传结果；具体发布身份和范围受系统校验 |
| 系统 | 校验身份、权限和业务边界，协调任务与人工互斥，保留事实、决策和结果，支持提醒与核验 |

首期内部运营同权，均可管理全部项目和资源，包括方向及范围确认、启停、资源分配和手机接管；不设置管理员与项目运营角色划分或项目人员隔离。项目负责人仍接收对应通知并承担处理责任，其他运营可代办；这不改变资源项目专用及 AI 的执行边界，操作仍可追溯。

手机执行引擎按 R-106 采用 Google Artemis。用户按 R-109 确认既有远程执行已验证，后续复用原证据，补查网络共存及新增客户端带来的变化。既有 Demo 的接口和部署方式不自动成为最终方案；官方接口或第三方效果采集渠道继续保留。

常规安排和范围内改进不逐条人工审批。策略、计划、执行与反馈保持关联；完整预设策略库不是任何阶段的前置条件。

## 设备接入

按 R-142，退出管理 App 登录只结束相应管理访问，已接入执行手机按原批准范围与实际条件继续；设备原暂停、恢复复核或永久退出等事实保持，已受理的控制请求不撤销。重新登录核对原设备和请求，不重建身份或自动恢复手机。

按 R-143，项目分配前发生需要运营处理的接入问题，形成可从全局待办及提供者／设备详情进入的同一事项；邀请运营为初始联系人和初始责任人，其他运营可代办并记录实际处理人。提供者端显示对应的等待及必要协助，不因没有项目负责人而遗漏问题，不为此创建虚假项目。分配后的新项目业务事项沿用项目负责人路由，原接入事项保留处理进展。

按 R-136，提供者使用手机号＋短信验证码验证注册与登录身份；首次注册同时核验邀请资格。保有原手机号时更换管理手机，通过验证进入同一提供者身份和原设备记录；不重新注册用户、不重置暂停／退出，也不自动将新管理手机接入执行。原手机号不可用按 R-140：联系原邀请运营 → 人工核验本人 → 验证新号码 → 换绑到原身份，保留设备关联和分佣历史，不解除原暂停或退出。按 R-141，先保留人工处理原则，不将完整 App 内找回及进度系统作为核心闭环前置。

按 R-134，提供者可在日常 Android 手机上登录同一个 App，仅管理本人设备与基础分佣；登录不自动把当前手机接入执行。提供者可从该管理入口逐台暂停、请求恢复或永久退出，实际停止或恢复仍须等待目标设备的核验；永久退出的分佣终点按 R-146 以系统受理并停派时点记录，不等待旧端停止回执。不增加远程屏幕操控或运营权限。

新增执行手机按 R-135：目标手机进入接入流程并展示关联码 → 已登录的管理手机扫码、核对目标并确认 → 关联至本人名下 → 目标手机继续必要授权与检查。关联成功不代表调试配对或业务就绪；重复关联不新增执行资格，不覆盖已有归属或绕过交接。页面和异常细化见[Android App 对齐](android-app-alignment.md)。

按 R-139，已关联执行手机的本机入口可直接请求暂停本机，不要求现场人员再次管理登录；只展示本机必要接入、授权、协助和控制进展，不获得完整设备列表或分佣。恢复和永久退出仍在已登录的管理手机处理。本机记录请求 → 中心受理 → 手机停止确认分别核对；离线下保留未送达及未知事实，不能在重连时丢掉暂停意愿或直接接续旧任务。

运营邀请已联系好的提供者 → 受邀用户注册 → 专用手机关联与授权 → 系统自动检查设备条件及管理连接、调试能力 → 运营确认首次项目及公司媒体账号分配（同一发布身份仅一台当前执行手机，允许只启用一个平台） → AI 协助登录、初始化与发布身份核验 → 就绪后接收任务。客户端承担接入与恢复，Artemis 承担获准手机任务；注册成功、网络在线、调试授权及执行就绪分别判断。

按 R-128，一位受邀提供者可关联多台专用手机，每台分别走上述接入流程；一台就绪不代替其他手机的授权、检查和运营分配。暂停、恢复或永久退出须对应具体手机，其他手机按自身条件继续；同一用户不意味着统一项目分配或共同启停，共享故障仍按实际影响处理。本人多设备展示沿用 R-126，分佣仍按媒体账号与承接期间计算，设备数量及换机不产生重复计佣。

首期由运营发放邀请，仍不允许无有效邀请的公众自行注册。按 R-152 修订 R-138：同一邀请码／链接可供多人注册，共用可配置的成功注册次数上限与有效期，不预绑定手机号、不增加逐次注册审批；用户自行选择号码并通过短信验证。有效凭证被转发后也可能由其他持有人使用，不据此证明原受邀自然人。注册成功才消耗名额，最终提交原子核对有效性与配额；打开、失败、重复提交、已有身份登录及新增手机不重复扣减。运营可查看用量与注册进展并撤销／重新发放，各提供者记录邀请来源及创建运营，沿用 R-143 联系人规则。邀请失效不取消已有身份或停止设备；邀请不代替设备检查、资源分配或执行核验，执行手机仍须专用。具体参数及发送通路在实施时落实。


首期按 R-129 要求执行手机使用稳定的现有 Wi-Fi，不部署额外现场专用网关；接入检查包含实际网络条件。纯蜂窝持续执行留待后续验证，但 Wi-Fi 掉线、切换及恢复仍须检查调试可用性和未决任务，不能仅凭 VPN 恢复就继续发布。

按 R-163，手机已有订阅负责业务上网，不使用 Macmini 作为出口。Tailscale 保留中心 ADB 与 Artemis 的管理连接；须在同一实际配置下分别检查订阅上网和管理通道。两款客户端分别可用不能计作共存通过。

首期允许配套安装官方 Tailscale App。用户在自有 App 注册、查看设备状态和完成必要接入步骤；Tailscale 承担组网及业务出口，自有 App 通知 ADB 端点和状态。两者分别完成所需授权；连接验证不只看 App 开关，还须核对中心可达、调试能力及 FB/YT 所需网络。暂不要求把网络引擎内嵌到自有 App。

客户端按 R-126 仅向设备提供者展示本人设备状态、需要本人配合的事项、基础分佣记录及核对所需的账号标识；项目策略、素材库和逐条发布明细留在运营端，其他提供者的设备和收益不开放。必要协助说明只提供完成配合事项所需的信息，不赋予运营计划修改、公司账号分配或管理权限；临时暂停、恢复和永久退出仍按下述流程处理。这是自有 App 的展示边界，不代表能够隐藏实体手机上已登录的平台内容。

首次分配由运营确认一次，未完成分配或初始化核验不进入日常发布；分配后初始化和日常任务由 AI 推进，验证码、额外授权及异常再交人工，不引入逐任务人工审批。该确认不覆盖之后的换机或跨项目交接，也不授权自动扩大账号或项目范围。

按 R-148／R-151，完成受邀资格核验、执行手机关联及必要授权 → 开放仅到独立核验服务的受限连接 → 系统核对实际网络节点与设备归属 → 正常自动正式准入 Tailscale，异常交运营 → 继续中心 ADB 配对及连接检查 → 运营确认项目与账号分配、完成初始化核验。受限阶段不开放 ADB、其他手机、运营后台或业务出口；核验失败、超时、冲突或退出时不升级许可并回收，实际结果分别记录。关联未核清不正式准入，分配前异常沿用 R-143；重连不解除暂停或退出，入网不表示业务就绪。

按 R-149，执行手机打开系统配对码页面并保持配对服务有效 → 提供者在管理手机该设备配对页核对目标后输入配对码 → 中心按绑定的设备、节点及配对端点完成授权 → 核实实际连接。多台手机可并发推进，各自显示进展；同机重复请求接续原会话，某台失败或重开不取消其他手机。切换设备不复用配对码，失效会话的结果不覆盖新会话；敏感码仅走专用通路。

按 R-150，App 上报端点变化 → 中心校验并使旧连接事实过时 → 在有效权限内验证新连接及原任务 → 正常恢复只更新设备状态和记录；自动恢复失败或明确需要人工时进入对应待办并提醒。项目问题沿用负责人规则，分配前沿用 R-143，同项目同故障复用待办，逐台保留结果。完全离线由中心识别失联，不等待手机发出无法送达的通知；通知已读不表示恢复。

客户端通知 ADB 端口变化；网络恢复后先核对原任务，结果未知不重复发布。服务恢复、开机后恢复与整机重启分开验证；授权撤销或不具备执行条件时，不能继续派发依赖该设备的任务。接入与停止使用围绕核心闭环处理，不扩展为完整设备市场流程。

按 R-133，提供者临时暂停指定手机 → 停止新任务派发 → 在可确认节点尽快停止正在进行的手机操作 → 保留在途及未知结果，等待恢复复核。暂停期间不再用该手机发布、采集或处理其他业务；不影响其他获准渠道的数据采集或结果核实，也不自动暂停其他手机。与项目仅暂停发布不同，不能为了继续效果采集而操作这台已暂停手机。暂停请求、执行端停止确认与最后已知任务状态分别保留，离线不能伪记停止成功；恢复前不能把未知结果当作未发布重发。

设备提供者可在 App 自行恢复临时暂停：提出恢复 → 在有效授权内允许必要的就绪检查和未决结果核验 → 复核通过后继续有效任务，未通过则继续阻止日常任务并按异常规则交运营。恢复核验本身可以按需使用该手机，不要求先将设备标为日常可执行；核验不能变成新发布或无关业务操作。不重新审批原项目和账号分配，不绕过项目/账号暂停；已提交或结果未知的先核实，过期任务不自动补发。临时恢复不代表重新接入已永久退出的设备。

设备提供者可在 App 自行永久退出 → 系统停止新派发，在可确认节点停止当前业务操作并保留在途和未决结果 → 运营处理账号迁移、旧端停止核验及登录清理。停止使用不以运营先批准为条件，后续远程操作仍需有效授权与实际连接；已撤权或失联不记为清理成功。已提交或结果未知的发布沿用原规则核实，不重新提交；不删除平台账号、已有内容或历史记录。已退出设备不能由后台重连或普通暂停恢复重新启用，后续重新接入须重新走接入及授权流程。

### 提供者现场协助

按 R-137，提供者主动进入现场处理 → 请求暂停指定手机 → 等待停止确认及既有控制交还 → 现场完成必要步骤 → 主动请求恢复 → 系统在有效授权内复核 → 条件满足后继续有效任务。正常路径无须每次由运营协调或审批；复杂问题仍按实际职责转运营。

“开始现场处理”复用既有提供者临时暂停，不另设绕过暂停或授权的新模式。用户保存处理结果、离开页面、重新登录或网络恢复，都不自动解除暂停。未明确请求恢复时继续保留暂停；结果未知先核实，不沿用旧界面进度或重复提交发布。

停止或控制交还无法确认时保留实际缺口，不提示已取得独占。若用户直接触碰手机或发生物理处置，按现场实际状态及未决结果复核，不把理想流程当成已经发生的事实。具体页面见[Android 现场协助规格](android-app-page-spec.md#6-本人协助与现场操作and-021022-已确认)。

## 基础分佣作为辅助业务

按 R-144，在账号承接关系尚未结束且没有永久退出或交接时，临时暂停或掉线不关闭承接期间，也不扣除这些时段产生的账号广告收益；收入实际到账且归属核清后仍按原提供者及历史比例计佣。暂停手机仍禁止业务操作和采集，分佣关系不能替代恢复授权。退出后无人承接期间按 R-147 处理。

按 R-147，原承接结束 → 已确认无人承接的空档 → 新承接生效：空档期间产生的广告收益保留为公司收入，不计任何提供者分佣，也不在后来分配给前任或后任。原承接期间的迟到账收益仍按原归属处理；空档收益迟到账也不变成新提供者收益。须核实承接记录和收入期间，不能将资料缺失视为无人承接；跨边界无法可靠拆分时保留待核对，不整段归公司或均摊。

按 R-146，永久退出请求被系统受理并停止新派发 → 对应账号承接期间结束 → 继续追踪旧端实际停止、未决结果及登录清理。10:00 受理停派、16:00 确认停止、次日清理时，承接终点为 10:00；尚未确认送达不能认定已生效，响应丢失后核对原受理时间。终点前产生但迟到账的收益仍归原提供者，跨终点无法可靠拆分的收入待核对，不能按时长均摊。

按 R-145，运营分配账号 → 完成对应账号初始化及真实发布身份核验，手机具备执行条件 → 首次承接生效 → 后续安排并执行首条任务。周一分配、周二核验通过并具备条件、周三首次发布时，起点为周二；准备期不追溯计入，首任务排期不延后起点。各 FB Page／YT 频道分别保留核验依据及生效时点，生效后的暂停、掉线及恢复不重置起点。

关联设备提供者、账号及承接期间 → 记录已到账且核清归属的广告收益 → 按收益产生期间适用的统一比例计算佣金，不另扣运营成本 → 保留结算/付款的实际处理记录。旧收益迟到账保留原提供者和原比例，记录金额不等于完成付款。

按 R-120 暂停支付渠道、自动付款、提现及复杂结算流程设计；未选择人工付款或自动付款方案。已确认原则见[基础分佣边界](current-requirements-summary.md#基础分佣边界)，不能因为付款细节未定而中断下述媒体闭环推进。

提供者查询页分别展示平台预估广告收入、本人可结算佣金和实际已付事实，不汇成可提现余额。按收益所属期间保留本人核对依据，退出或换机不删除旧记录；缺数据、归属不清或比例未定时保持待核对，页面返回及查看不会发起付款。具体页面设计见[Android 基础分佣规格](android-app-page-spec.md#7-基础分佣)，图稿金额不构成真实业务配置。

| 阶段 | 处理内容 | 继续条件与结果 |
| --- | --- | --- |
| 1. 项目准备 | 明确阶段目标、批准范围、负责人、周期配置和引流要求，分配账号及手机，准备现成承接入口 | 账号与手机同期项目专用；按各账号实际资格阶段作安排，不因项目目标推定已开通变现 |
| 2. 设备与身份就绪 | AI 协助已有账号登录与初始化，必要授权、验证码或现场恢复由人员完成 | 核验平台、登录身份与发布身份，具备获准执行条件；管理连接在线不等于可以操作 App |
| 3. 成品准入 | 内部运营人员批量上传成品，人工识别并确认项目、商品/短剧、语言、集数及版本关系，补充基本内容说明、业务事实、来源和未发布声明；系统保留规则性检查 | 信息缺失或冲突由人工补齐；合格且符合批准规则的内容自动进入候选，入库不等于必须发布；首期不依赖 AI 自动识别或关联 |
| 4. 方向确认 | AI 根据目标、素材、账号及已有事实提出初始方向 | 运营确认方向与边界；正式开通前优先分成资格并保留引流，开通后遵循已批准优先级 |
| 5. 计划安排 | AI 基于人工确认的素材信息选择内容、账号、语言版本、形式和时段，生成标题配文并安排有效引流路径 | 检查单平台内容名额、连载账号与依赖、引流最低数、频率、有效窗口及资源条件；不足明确报告 |
| 6. 手机执行 | 按任务核对目标手机的素材版本和文件就绪，再由 Artemis 在批准范围内按队列和并发限制操作并核对实际发布结果 | 保存正确平台、身份和内容的证据；结果未知先核实；进入平台发布流程后普通复盘不改当前任务 |
| 7. 反馈回收 | 及时核验发布结果，按实际数据渠道获取效果，分别记录来源、覆盖区间、截止及采集时间 | 发布完成与效果分别记录；缺失、延迟、真实零值和无法归因分别表达 |
| 8. 复盘与下一轮 | AI 依据已有事实评价当前安排，决定维持或修正，并关联后续任务及理由 | 范围内自行处理，方向或范围变化交运营；证据不足不强行改变；旧任务与新安排不得重复执行 |

准备事项可并行，不要求所有输入按固定页面顺序录入。批量上传后逐份确认文件完整性、人工资料和准入结果；未完成或有疑点的内容不进入候选，合格且无依赖的内容不被整批阻断。重试上传仍检查已有内容及版本关系，不能借重新导入获得新名额。首次准入后的跨平台后续发布继续按既定安排检查，不误判为违反“首次输入尚未发布”。每轮保留足以复核的条件、措施、依据、结果和局限；运营案例供参考，不自动变成规则。

## 项目启动与任务就绪

项目资料可以逐步补齐，素材也可分批进入。准备项目不等于已允许执行；每项任务仅在自身必需输入及批准条件齐备后进入安排和执行，不要求无关账号或所有未来素材同时准备完成。

| 必需输入 | 缺失时的处理 |
| --- | --- |
| 项目目标、当前账号阶段、受众与批准范围 | 由运营补齐或确认，不让 AI 从候选国家语言、历史案例或 Demo 默认值推定本次授权 |
| 人工确认的素材及来源、业务事实、版本/语言/集序关系 | 受影响素材待补充，已合格且不受影响的素材仍可进入候选 |
| 平台发布身份、手机分配、邀请与必要授权 | 未就绪资源不接发布任务；网络连接和业务身份分别核验 |
| 引流入口及任务要求 | 核对实际可用路径；无法满足的报告缺口，不用填写 URL 或静默减量替代 |
| 项目时区、周期起点、有效窗口及适用约束 | 已确认默认值可明确采用，未定的业务数值不得由示例或历史参数冒充 |
| 反馈指标及来源条件、通知负责人 | 记录可得、延迟与缺失；关键反馈缺失沿用原批准计划及暂停相关优化规则，通知故障不放开执行边界 |

上述是同一业务流程的就绪检查，不要求额外建设项目审批模块。真实执行前记录本次采用的输入、配置及批准范围，便于结果核验和后续复盘；各项具体准备责任与完成时点见[当前对应说明](current-implementation.md)。

## 账号资格与阶段衔接

按 R-131，系统取得并核实具体 Page/频道的正式开通证据，且项目已批准开通后的目标优先级时，自动更新该账号阶段，记录来源、核验时间及生效情况，AI 据此安排后续任务。数值达标、可申请或审核中不等于正式开通；同项目其他账号不随之切换。

目标尚未批准或证据不足时转运营，不猜测开通；资格失效或限制按实际受影响范围处理，不能仅因收益资格变化就推定全部发布权限失效。未受阻断且仍获准的任务按原规则继续，方向变化仍需运营确认。阶段更新不删除引流诉求、重写当前周期最低要求或改动已开始/结果待核实任务。

## 发布前素材准备

本节将已确认的人工素材处理（R-125）、自动安排与执行、素材更正（R-108）及结果核验原则串联为完整流程，不新增 AI 素材识别能力或独立审批环节。

人工确认素材及业务关联 → AI 形成获准发布安排 → 任务关联明确文件版本、语言版本、平台、发布身份及手机 → 系统准备文件并确认手机端可用 → Artemis 选取对应素材、填写发布信息 → 提交及结果核验。

- 文件准备采用确定的素材与版本关联，不能让执行 AI 从手机已有文件中凭外观猜目标，也不把“相册最新一条”作为唯一识别依据。实际传输、手机存储及平台文件选择方式仍待技术验证，不在此锁定实现组件。
- 文件未到齐、版本不符或平台无法选取时，任务尚未具备发布条件，保留原因并按既有恢复/异常流程处理；其他不受影响的任务继续。
- 素材更正或撤回后，重新检查受影响的未提交任务及已准备文件，不能因手机已有旧文件就继续发布；已提交或结果不明的仍先核实。
- 断线重试文件准备不代表允许重复提交平台发布；文件准备完成也不代表发布成功。关键证据是任务、素材版本、手机实际选取的内容与最终发布结果能对应。

## 发布核验与效果回收

本节细化既有发布核验、数据来源及归因规则，不新增 AI 素材识别、逐条人工审批或统一数据接口选型。

发布任务 → 核对平台实际发布身份及内容 → 保存关联证据 → 按可用渠道采集对应效果 → 检查数据口径及观察窗口 → 支持复盘与后续安排。

- **对应实际发布**：沿用任务已确定的项目、素材及语言版本、目标 FB Page/YT 频道和执行手机，核对平台实际内容。可取得时保存平台内容标识或链接，并保留足以复核身份与内容的证据；不能假定各入口都能返回标识，也不把链接缺失直接判成发布失败。仅有上传完成、提交提示或 Artemis 执行结束不足以确认成功。
- **关联不清先核实**：不能只因标题相同、发布时间接近或位于账号列表最新一条，就认定是本次发布。身份或内容不符转既有异常处理；结果不明保留待核实，不强行关联，也不重新提交来替代核实。正常核验由系统及执行 AI 完成，必要异常才交人工。
- **分别记录三类事实**：已核验发布、效果数据已取得、数据足以用于比较分别判断。已确认发布的内容暂时没有效果数据，不退回发布失败或再次发布；出现后续平台异常时记录新的事实，不抹去原发布与核验记录。
- **按来源粒度归属**：采集记录对应的平台身份、可确认的平台内容、指标定义、来源及证据位置，并保留实际统计范围、时区、截止和采集时间。来源仅支持账号级数据时保留账号级，不按条数均摊到内容；归属不清保留待核对。资源后续交接不改写原发布的项目、账号及任务归属。
- **回收不重复计数**：重复采集同一结果不产生新的发布完成数；累计指标的多次快照不能相加当成新增效果。更正或补齐数据时保留来源和前后关系，缺失、延迟与真实零值分别表达，不由未知值推导增长或下降。
- **反馈进入下一轮**：默认每日尝试采集，发布结果及时核验；复盘沿用已确认的周期、观察窗口和可比性规则。数据不足时继续原批准范围内安排，暂停依赖缺失数据的优化；数据充分时记录 AI 维持或调整安排的依据，并能追溯后续任务及实际结果，不要求每轮必须改变。

官方接口、授权第三方及手机后台仍按具体指标选择和验证。内容标识的获取、手机后台可见范围与采集可靠性属于待验证能力；本节不将流程定义视为这些能力已经通过验证。

## 发布分支与计划衔接

- **产品展示**：使用已完成成品与业务方现成入口，兼顾分成目标和引流，不承担商品页建设。
- **短剧连载**：同一部剧在同一平台固定账号，前一集核验成功才执行后续依赖；独立宣传片不强制关联集序。FB/YT 各自推进，共享故障按实际范围处理。
- **平台形式**：FB 视频/图文、YT Shorts/常规视频分别核验入口与可点击引流路径；有 URL 不等于可引流，不因平台形式需要而自动增加剪辑制作范围。
- **计划更新**：可保留、取消、重排尚未开始的任务，并保存变更原因与前后关系。排队任务可在批准有效窗口内重排，超窗交人工；已开始和结果待核实的任务分别处置，不能当作普通候选替换。

## 素材更正、撤回与平台撤下

- **素材更正**：保留新旧版本，暂停受影响的未提交任务，对更正内容、发布信息和批准范围重新检查后更新安排。编辑中先核对实际状态，在可确认节点暂停；不一并暂停无关任务，不增加内容名额或延长有效窗口，连载依赖继续适用。
- **正式撤回素材**：停止继续分发并取消确认未提交的关联任务，保留素材、任务及撤回记录；再次使用须重新核准。不能让后续剧集因前置任务取消而跳过依赖。
- **平台已发布内容撤下**：运营明确目标平台、账号、内容及具体操作后，由 Artemis 执行 AI 操作并核验结果，不自行替换操作或扩大至其他平台、内容及整部剧。操作不可用或需要必要人工验证时交运营处理，保留原发布事实及处置记录。

任何已提交或提交状态不明的关联任务先核实，不按未发布任务直接替换、取消或重发。素材更正、撤回以及项目暂停、结束，均不自动授权修改或删除平台已发布内容；执行结束不等于平台处置成功。

## 周期评价与效果评价

项目首次按配置的业务时区、起始日期时间与间隔建立周期。按 R-132，运行中变更间隔或时区从当前周期完整结束后生效，下一周期以该结束的同一实际时刻接续；不任意重设起点，不产生空档、重叠或额外过渡周期，历史保留原配置。引流最低要求按项目汇总，以有效引流平台任务核验成功数评价；计划数、完成数与缺口分别记录，缺口不自动追加下一周期。迟到核验按实际发布时间计回原周期并保留更正，不重复计数。

内容效果评价使用相应观察窗口和可比数据；未满窗口、来源延迟或证据不足时继续观察。允许另设完整平台统计日窗口，与精确小时窗口分开比较，首个不足整日区间单独观察。项目周期、数据采集频率与内容观察窗口分别处理，参数及口径以[需求基线](current-requirements-summary.md)为准。

### 复盘结论如何进入后续执行

复盘使用当前目标与批准范围、人工确认的素材信息、实际执行结果和可用效果数据，记录引用的事实与截止时间。输出须说明维持或调整什么、作用于哪些后续安排、依据和局限；无需建设独立策略库，也不要求保存模型内部思维过程。

| 结论 | 后续处理 |
| --- | --- |
| 维持原安排 | 说明维持依据，关联继续执行的有效任务及其后续结果；不为体现优化而强行改动或复制一套任务 |
| 在批准范围内调整 | AI 更新尚未开始的安排，保留原任务与新安排的关系；系统检查内容名额、连载依赖、频率、有效窗口和资源条件，通过后执行，无须逐条人工审批 |
| 数据不足，继续观察 | 明确尚缺什么以及哪些判断暂不能作出，继续原批准范围内的有效安排并尝试补齐数据；不能将继续观察写成已验证改善 |
| 需要改变方向或突破范围 | 将建议及原因交运营确认；未确认不实施这项变更，仍可执行且未受阻断的原批准任务按原规则继续。确认后结合当时的任务和资源状态重新检查，不把先前建议直接当作仍可执行的安排 |

提出建议、更新安排、任务实际执行及效果评价分别保留事实。安排落地时以任务当前状态为准：已进入平台发布流程的任务不受普通复盘改动，结果未知的先核实；暂停、撤权、素材撤回和有效窗口等约束不会因新复盘结论而失效。

任务因资源或素材不足等原因未能执行时，保留阻断与缺口并按既有异常流程处理，不以报告已生成宣称闭环完成。验证闭环时须能沿着“本轮事实 → 维持/调整依据 → 后续有效安排 → 实际执行及核验 → 新反馈”追溯；流程成立与改进措施是否带来商业提升分别判断。

逐步调整保留为运营偏好，暂不规定固定比例或自动放量流程。重大异常即时处理，不等待常规复盘。

## 手机操作互斥

本节落实既有固定手机分配、队列及接管要求（R-032、R-049、R-060）。同一手机同时只允许一个控制方进行业务界面操作，覆盖 FB/YT 发布、手机后台采集、登录初始化、内容撤下及人工接管；不同平台或任务类型不能绕过互斥。全局并发额度仍有余量，也不意味着同一手机可以同时执行两个界面任务。

切换控制方前核对当前任务已结束或在可确认节点停止，并保存未决状态；接管断开或服务重启不直接放开控制。已提交或未知结果先核实。官方接口采集等不占用手机界面的工作按自身授权及数据条件处理，不要求所有后台工作一律串行。具体协调方式留给技术设计，不新增独立调度平台。

## 项目主动暂停与恢复

运营主动暂停项目时停止启动新的发布，已进入编辑流程但尚未提交的任务在可确认的操作节点停止；已提交的只继续核实，提交状态不明的保持待核实。暂停不撤销平台已经接收的发布，也不触发重发、删除或自动判定任务失败。

保留暂停请求、执行端确认和实际任务状态，不将管理台点击暂停等同于所有手机已经停止。这是主动暂停规则，不受“普通复盘不改动已开始任务”的限制。暂停发布期间按既定安排继续尝试采集已发布内容的效果，保留来源、时间范围与缺失状态；不因取得新数据自动恢复或触发发布。采集使用手机时遵守接管互斥和设备状态，不干扰草稿及待核实任务。

项目恢复时检查原任务的批准范围、素材、账号、设备及有效窗口；仍满足条件的继续或重排，过期及失效任务不自动补发，按既有异常规则处理。连载依赖、内容名额和发布频率继续适用，保留原任务关联。编辑中暂停的先核对现场状态，已提交或提交状态不明的先核实，不能随普通待发布任务重新执行。

## 项目正式结束与效果收尾

正式结束时停止启动新发布，编辑中的任务在可确认节点停止，确认未提交的剩余安排取消并保留记录，不自动补发；已提交或提交状态不明的任务先核实，不直接取消或判失败。结束后的已取消安排不能按普通暂停恢复继续，也不因此删除平台已发布内容或自动释放账号、手机。

项目正式结束后，按项目配置的收尾观察期继续尝试采集历史已发布内容的效果；按期限汇总实际可得数据，形成收尾报告后停止常规采集。记录来源、覆盖区间和数据局限，不为补齐缺失无限期延长采集，也不触发新发布。

结束前已提交但结果不明的发布仍单独核实，报告保留未决状态，不能因结束或收尾到期直接认定成败。资源交接按下述流程由运营确认；本轮不扩展已结束项目的重新开启；后续确有需要时补充规则，不能套用普通恢复。

## 故障换机与任务接续

按 R-130，同一 Page/频道同时仅一台当前执行手机；由运营指定符合项目和支持范围要求的新手机并确认迁移，AI 协助原账号登录、身份核验和任务接续，必要验证交人工。新手机接续前核对旧端交接状态，防止两端执行相同账号的发布安排；旧端离线不能仅以绑定已修改认定其停止，具体方式待技术验证。

旧端已提交或状态不明的发布先核实；未提交任务按当前状态、批准范围及有效窗口接续，保留任务与迁移关系。换机不改变发布账号、历史、内容名额或连载进度，跨项目转移则需另外完成运营确认的交接。

## 资源跨项目交接

运营明确原项目、目标项目与具体账号或手机并确认交接。停止旧项目对该资源的执行，核清未决发布和收尾采集安排后再分配新项目；旧端或依赖状态不明时，不将交接记为完成。正式结束项目不自动释放或转移资源。

新归属仍须满足账号及手机同期项目专用、同手机 FB/YT 身份同项目的约束。历史任务、发布内容、效果及证据保留原项目归属，旧任务不自动转给新项目，不重置内容名额或连载进度。旧项目仍需该资源操作或采集时，须先明确处置，不能以并行占用绕过交接。

## 异常与人工协作

| 情况 | 处理与恢复条件 |
| --- | --- |
| 明确可恢复的技术故障 | 在同一轮执行累计恢复限额内尝试；次数或耗时先达限额且未恢复即转人工，换错误类型不重置 |
| 账号限制、身份不符、必要人工验证 | 直接暂停实际受影响范围，形成待办；不按普通技术故障反复尝试 |
| 提交后结果不明 | 先核实，不盲目重发；依赖其成功的后续剧集继续等待 |
| 主目标效果数据缺失 | 继续原批准计划，暂停依赖缺失数据的优化并补齐，不能记零或擅自换主指标 |
| 引流来源只到账号 | 评价账号结果，保留内容来源未知，不推断单条视频贡献 |
| 引流任务最低数无法满足 | 报告缺口和原因，不静默降低要求、不越权补量 |
| 手机掉线或权限失效 | 按实际影响暂停，远程或必要现场协助；不能假设离线手机仍能主动通知 |
| 人工接管手机 | AI 同期停止操作该手机，交还后复核；其他可用设备继续 |
| 人工提交已处理 | AI 复核通过后继续原任务，并检查有效窗口、顺序等条件；不通过则保持暂停 |
| 改变目标、方向或突破范围 | 由运营确认新的边界后实施相关变更 |

### 从人工介入回到自动执行

以下串联既有待办、接管互斥与恢复复核要求，不增设逐任务审批或独立工单系统。

1. **留下可处理的问题**：待办关联项目、任务、发布身份和手机，说明阻断原因、已尝试的恢复、最后已知执行状态及需要人工完成的事项。手机失联时标明状态无法确认，不把旧截图当作当前现场。
2. **提醒并按需接管**：首期优先邮件提醒项目负责人，详情与处理在管理台，其他内部运营可代办。只有需要操作手机时才接管；先核对 AI 已停止操作，无法确认时不宣称已取得独占控制。接管期间该手机的发布、采集等 AI 操作均受互斥约束，其他可用手机继续；必要现场协助不赋予设备提供者内部运营权限。
3. **记录处理并交还**：保留实际处理人、完成事项及相关结果；涉及手机操作时明确交还。提交“已处理”、关闭页面或通知已读，都不能替代交还与恢复复核。密码、验证码及令牌不写入待办说明或普通证据。
4. **核对当前事实再接续**：AI 复核人工处理结果，系统检查授权、项目/账号状态、手机身份、素材、有效窗口及依赖。人工操作可能已改变界面或发布状态，不能沿用接管前的下一步点击；若实际内容已经发布，核验并关联原任务，不能再次提交。未知结果仍先核实，其他条件不符时保留阻断原因。
5. **逐任务记录恢复结果**：同项目同次故障合并待办与首次提醒，新增影响更新原待办；合并提醒不合并各任务的恢复判断。复核通过且仍有效的任务继续，未通过的保持暂停，不因其中一条恢复就批量解除全部阻断。通知送达、已读或发送失败均不改变这个判断。

待办处理结果、手机交还情况及任务能否继续分别可追溯；本流程定义业务要求，远程查看、独占接管和恢复能力仍须在支持的机型及实际网络上验证。

### 服务或 AI 会话中断后的接续

同样的恢复原则适用于中心服务重启、执行端重连和 AI 会话更换：从已保存的批准范围、素材版本、资源分配、任务事实与暂停/接管状态恢复，不依靠上一轮模型会话记忆判断权限或执行进度。

未开始且仍有效的任务才可继续安排；已进入发布流程的先核对现场，已提交或未知结果的先核实。重复派发、回执或重连通知不能新建一次发布事实、重新占用内容名额或绕过已取消安排。人工处理与平台新证据也须关联原任务，避免中心与手机各自恢复后重复操作；具体持久化和并发实现留给技术设计。

## 完成判断

流程需形成可追溯的真实执行与反馈闭环；生成策略文本、手机操作结束或一次发布成功均不代表闭环通过。验收覆盖与证据见[验收与证据](acceptance-plan.md)，关键事实的验证安排见[当前对应说明](current-implementation.md)。
