# 任务与验收记录模板

更新：2026-09-29。复制以下相应部分到实际任务、PR 或证据目录，保留 WP/CT/AC 编号。模板不是已建立的任务、已执行的命令或通过证据。空值须说明待落实责任与时点，不用“同上”“已测试”替代可追溯内容。

## T1 开发任务卡

```text
任务：WP-xx / 子任务名
基线：需求修订、相关 ADR/页面规格、代码 commit（如有未提交 diff 另记）
需求：R-xxx；契约：CT-xx；验收：AC-xx-a、AC-xx-b
主责姓名 / 协作人 / 非作者复核人 / QA：
状态：待分配 / 待开工 / 开发中 / 待评审 / 待联调 / 待验收 / 已验收
目标：用户从哪个入口做什么，最终哪项事实发生变化
范围 / 排除项：
编码依赖：上游任务、具体产物及版本；已到或未到
交付依赖：实际资源、集成任务、责任人、最晚需要时点
预期修改目录与契约：
数据迁移与权限/并发/幂等/副作用处理：
正常 / 失败 / 冲突 / 超时未知 / 重启接续：
实施子任务和估算：负责人据实际资源填写，不预设日期承诺
完成标准：可观察断言及对应 AC 子场景
验证计划：正式命令/目标、补充检查、真实 Web/原生/设备步骤
服务/设备/公开操作授权依据：沿用会话或任务中已明确范围
提测产物：代码、迁移、契约、安装包/构建指纹、说明、证据索引
未决风险及阻断：原因、已尝试、需要谁提供什么、解除条件
```

## T2 契约变更与跨端交接

```text
CT 编号 / 关联 WP：
契约文件及版本 / 生产者 / 消费者：
变更前后：字段、空值/未知含义、枚举/版本、权限、错误、时间单位
权威记录与不变量：
事务边界与唯一性：
请求幂等：键作用域、冲突、保留期、响应丢失查询、撤权后的读取
正常/重复/乱序/超时/撤权/重启时序：
外部副作用及未知处理：
旧客户端/旧事件兼容、部署顺序、迁移与回滚/前向修复：
安全数据流：哪些字段不得进入日志、模型、截图/trace、普通证据
被影响的 AC 与证据复用判断：
生产者确认 / 每个消费方确认 / QA复核：人名、日期、结论、待办
```

## T3 PR 与提测摘要

```text
WP / R / CT / AC：
问题与最终行为：触发条件、原行为、改后行为
变更范围：目录/接口/数据/页面/执行；不写已放弃的会话过程
实现要点：仅保留评审需要的事务、权限、幂等和外部副作用说明
迁移及版本兼容：部署顺序、数据保留、回退风险
检查记录：每条真实命令、工作目录、目标环境、退出码、输出路径
Web/原生/真机验收：运行编号、实际断言、通过/失败/阻断/未验证
未测范围：原因、主责、待补时点；补充测试与业务验收分开
敏感信息保护：证据是否包含秘密，如何在保存前避免
评审重点：哪些分支需要非作者特别检查
已知缺陷 / 后续任务 / 提测版本及产物哈希：
```

## T4 单次验收与证据索引

建议目录为 `artifacts/acceptance/product/<batch>/<run-id>/`，只在真实执行时创建。证据清单可用 Markdown 或 JSON；二者不重复维护同一状态。需要引用敏感原始证据时使用受控位置，仓库仅保留脱敏摘要及校验信息。

```text
run-id / batch / WP / AC 子场景 / R：
用途：探索 / 补充检查 / 真实业务验收 / 回归
操作者 / 复核者 / 起止时间及 timezone：
版本：commit、dirty diff摘要/哈希、schema、Web/backend、APK签名/哈希、
      Artemis提交与补丁、ADB/Android/Tailscale、模型、配置版本
环境：正式或Demo、服务地址、数据库/队列/对象命名空间（无凭据）
设备与网络：脱敏设备ID、型号/系统、真实样本数、网络/出口路径
前置输入：通过哪个真实入口建立，项目/提供者/设备/任务/请求等关联ID
操作授权：已有授权的目标、动作、范围、时点；未具备则不执行副作用
事前判据：预期断言、样本、观察窗口、性能阈值及冻结版本
执行：实际命令与工作目录/原生操作步骤；故障注入方式和时间点
观察：页面反馈、实际手机/平台事实、只读补充数据分别记录
逐条断言：预期、实际、通过/失败/阻断/未验证、证据相对路径
证据：脚本、日志、截图、结构化回执、来源数据、文件哈希、访问范围
既有证据复用：原记录、适用断言、当前变更未影响的理由
本轮结论：只覆盖哪些环境/形式/机型/场景，不覆盖哪些
失败/阻断：缺陷ID、负责人与下一步；禁止补填模拟成功
清理与遗留：测试账号/对象处理、未知任务、未回收权限、未决外部结果
复核：人名、日期、结论、允许进入的下一门禁
```

截图不保留短信、配对码、密码输入；trace、视频和 DOM 导出同样检查敏感信息。事后修改脱敏文件须记录原因并重新计算哈希，不改写原始业务结果。

## T5 缺陷与资源阻断

```text
编号：BUG-日期-序号 或 RES-xx
类别：实现缺陷 / 环境 / 外部资源 / 待工程决定 / 授权范围
关联 WP / AC / CT / R / 提测版本：
严重度及影响对象：P0/P1/P2/P3，仅阻止哪些模块或操作
预期 / 实际 / 最小复现步骤 / 证据：
已尝试及结果：
临时保护：停止哪些动作，哪些不受影响工作可继续
责任人 / 协作方 / 需要提供什么 / 最晚时点：
解除或修复标准：可重复断言，不能只写“接口200”
修复commit / 复测run-id / 受影响回归范围：
状态与变更记录：未处理 / 处理中 / 待复测 / 已关闭
```

“资源未核实”不自动等于已经阻断；只有实际需要且不能满足时才记阻断。保留历史失败，不用后续通过覆盖其记录。

## T6 批次放行记录

```text
批次 / 基线 / 提测版本 / 日期：
所含 WP 与交付物版本：
必需 AC 子场景：总数、通过、失败、阻断、未验证；分母变化的依据
适用性说明：如有不适用，列业务依据、复核者；不得删掉首期必需范围
核心不变量：身份隔离 / 真正停止 / 未知不重发 / 数据不重复 的证据
依赖满足情况 / 真实资源与授权 / 覆盖平台形式及机型规模：
复用旧证据及本次增量证据：
缺陷、限制、支持清单、安装/运维/恢复说明：
结论：通过 / 失败 / 阻断 / 未验证；代码合并与业务验收分开
可进入的下一阶段与仍禁止/未授权的副作用：
开发主责 / QA / TL / 业务输入核对人：姓名、结论、日期
```

## T7 性能与恢复目标冻结记录

```text
关联 WP / AC / 环境与资源组 / 探索记录来源：
指标名及定义：起止事件、时间来源、分位/成功率口径、排除条件
目标值、样本数、持续时间、并发/排队、真实设备/网络分布：
故障注入点、观察窗口与退出条件：
RPO/RTO、备份范围、对象及凭据恢复边界（适用时）：
技术提出人 / QA复核 / TL确认 / 冻结日期：
实际测量记录链接与结论：测试后填，不能反向改目标
变更：新目标版本、理由及必须重新执行的场景
```
