# 社媒运营核心流程开发清单

更新：2026-10-09。按本次用户确认，先贯通真实发布、单条内容表现、账号成长、复盘与大盘；广告收益和引流保留既有需求，暂不作为本轮闭环完成条件，未接入时明确展示状态。每天尝试采集，内容比较窗口采用发布后 **3 天**，项目复盘默认每 **7 天**。

复用现有正式工程，优先补接线和业务处理。下列勾选项表示待完成的业务衔接，不表示对应模块全部需要重写；当前基础及限制见[当前实现](../../current-implementation.md)，其他规则沿用[需求基线](../../current-requirements-summary.md)。2026-10-09 用户明确要求按本清单开发并串联完整测试，本清单范围内继续开发与验证；仍保留原手机初始化任务、占用及未知结果，不能用新任务覆盖。

## 业务串联

账号绑定手机并核验身份 → 分配项目及目标 → 上传成品切片 → AI 生成发布任务 → Artemis 执行并核验发布 → 每日采集对应内容及账号数据 → 效果分析与大盘展示 → 更新下一轮发布安排。

全链路沿用原记录关联：**项目 → 素材及版本 → 策略及任务 → 平台实际发布内容 → 指标快照 → 分析结论 → 后续任务**。账号、发布身份和手机随任务保存，换机或调整项目资源不改写历史归属；不能靠标题、最新一条内容或手机相册顺序关联。

## 开发事项

### 1 账号设备与项目就绪

- [ ] 接通账号准备的执行消费者与结果回写，核验登录账号、唯一已有 Page／频道及管理权限；分别展示已分配、准备中、可执行和阻断原因。
- [ ] 按任务解析项目、账号、发布身份和手机，解除仅适配固定配置目标的限制；保持资源独占及同机操作互斥，设备在线不等于业务可执行。

衔接结果：项目能够提供真实可用的发布目标，供 AI 选用和执行端校验。

当前进度（2026-10-09）：已增加原任务身份回执读取、可信结果原子回写及 Web 同步入口；组件与 Web 阻断路径已验证，见[记录](records/core-flow-identity-writeback-20261009.md)。本项尚未完成：正式派发仍需接通当前权限与设备执行，原手机未知占用尚未解除，不能将回写组件通过勾选为账号准备闭环完成。

### 2 成品切片进入发布候选

- [ ] 串通批量上传、文件校验、素材登记和候选状态；保存项目、业务说明、系列、剧集顺序、语言及版本，信息或文件缺失时明确阻断。
- [ ] 复用重复检查、平台发布名额和连载依赖；更正或撤回只处理受影响任务，已提交及未知结果先核实，不能重新上传绕过限制。

衔接结果：AI 能读取合格候选；执行任务绑定具体版本及文件，上传不等于必须发布。

### 3 AI 策略生成可执行任务

- [ ] 将项目目标、批准范围、候选素材、账号状态和真实反馈接入现有业务模型，生成选材、账号匹配、文案及执行时间，经过规则校验后写入原任务体系。
- [ ] 接通自动运行入口，处理新增素材、任务到期和反馈变化；计划修订保留原任务关系，只调整尚未开始的任务，离线错过后按有效窗口顺延、不补次数。

衔接结果：计划实际产生可消费任务；没有合格素材、可用账号或有效范围时保存原因，不制造空任务或成功状态。

### 4 发布执行与实际结果回写

- [ ] 将任务指定文件传到目标手机并校验版本及完整性，复用 Artemis 接通正式提交与结果核验；按既有范围覆盖 FB 视频／图文、YT Shorts／常规视频。
- [ ] 核验正确身份及实际内容，保存可取得的平台内容标识或链接、实际发布时间和证据，关联原任务；成功后推进内容名额和连载进度。
- [ ] 区分准备完成、发布成功、失败和结果未知；未知只核实原操作，不直接重发，重复回执不重复执行或计数。

衔接结果：已核验发布记录成为采集目标；现有 Facebook 视频发布前准备不能作为最终发布实现。

### 5 周期采集与数据整理

- [ ] 核实并接入 FB／YT 的内容级表现及账号成长来源；逐指标保存定义、单位、粒度、权限与可用状态，不能用 Page 账号汇总代替单条切片效果。
- [ ] 从已核验发布记录建立每日采集安排，自动执行、保存和恢复，不依赖浏览器页面打开；手机端采集与其他手机任务共用设备占用控制。
- [ ] 保存来源、采集时间、统计区间、截止时间及原始时区；快照去重、更正可追溯，累计值不叠加，缺失不填零，账号数据不摊到内容，数据缺失不触发重新发布。

衔接结果：提供可追溯的内容及账号快照，供分析和大盘共用；某项采集失败不推翻原发布成功事实。

### 6 三天观察与持续优化

- [ ] 从核验后的实际发布时间计算三天观察窗口；窗口未满标记观察中，窗口已满但数据不足或不可比时保留原因，不强行排名或优化。
- [ ] 分析同口径、相应观察区间的数据；只有较晚累计快照时不能冒充前三天效果。来源只能提供平台统计日时保留真实区间，按既有规则与精确小时窗口分开比较。
- [ ] 将合格数据送入业务 AI，默认每七天形成项目复盘，输出依据、结论及维持／调整措施；批准范围内落实到后续任务，保留结论与任务关联，不止生成分析文本。
- [ ] 记录调整后的执行及效果，供下一轮复盘判断；证据不足继续原批准安排，不能擅自更换主目标或扩大范围。

衔接结果：能够追溯“哪些数据支持什么结论、改变了哪些安排、实际执行后效果怎样”。

### 7 大盘总览与内容明细

- [ ] 复用现有项目页与效果页，提供按项目、平台、账号和时间筛选的总览，展示成功／失败／待核实数量、可得效果趋势、账号成长、采集覆盖及更新时间。
- [ ] 提供内容明细，串联素材版本、发布任务、实际内容、效果快照、观察状态及 AI 结论；支持从汇总追到原记录。
- [ ] 汇总与分析使用一致口径；账号整体效果与本系统内容效果分别展示，不混加不同平台定义、重叠区间或累计快照。不新增综合评分、自定义报表或通用数据平台。

衔接结果：页面直接回答发了多少、效果怎样、哪里阻断、后续怎样调整。

### 8 异常与生命周期贯通

- [ ] 将掉线、身份失效、素材失效、暂停及接管状态接入上述链路，只阻断受影响范围；重启后按持久记录恢复，不重复创建发布或采集操作。
- [ ] 项目暂停后停止新发布，按原权限和设备条件继续采集历史内容；项目结束后按配置的收尾观察期采集并形成报告，再停止常规采集。设备被暂停时不继续操作该手机。

## 完成检查

- [ ] 在允许测试及真实发布的条件下，用可复现 Playwright 从正式 Web 串联项目、素材与任务操作，由 Artemis 完成真实手机执行，核对发布记录和实际采集结果；不以直接写库、预设指标或固定手机点击脚本替代。
- [ ] 能从一条真实发布追到对应效果、满足观察条件的分析及后续任务；只有源码、页面或局部检查通过时，不勾选整条闭环完成，缺少条件的部分保留阻断。
