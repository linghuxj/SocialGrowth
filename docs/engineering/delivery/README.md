# 开发分工与质量执行手册

更新：2026-09-30。适用基线以最新需求及用户确认为准，当前R-001～R-157、ADR-0001～0011、Web UI-014、Android AND-001～009。本文档组把范围转为工程任务和质量要求，不新增业务权限、产品功能或已通过的验收结果。正式工程已有部分阶段实现及局部门禁证据，实际状态仅由[开发台账](delivery-tracker.md)与固定任务记录维护，不能从本手册的工作包定义推定全部未开始或已完成。

## 依据和变更权限

业务范围以[需求基线](../../current-requirements-summary.md)及[修订记录](../../requirements-alignment.md)的最新确认为准；流程见[业务流程](../../business-workflow.md)，技术见[技术设计](../../technical-design.md)，正式验收范围见[验收与证据](../../acceptance-plan.md)。[首批契约](../../first-delivery-flow.md)、[接入草案](../../device-connectivity-implementation.md)及两端页面规格是对应任务输入。

本组文档定义工程执行方式。若与上述业务边界冲突，先记录冲突并修正任务，不由开发人员选择更宽松解释。具体组件、字段、端点、依赖版本和正常参数由技术负责人在相关任务内确定并留理由；改变已接受架构、业务授权或首期范围才回到对应决策。不得以任务拆分偷偷引入角色分层、公众注册、逐条发布审批、完整支付、策略平台或自动素材识别。

## 责任分工

以下是开发团队职责，不是产品内角色；没有假定现有团队人数或具体人员。一人可兼任多项开发职责，跨端工作仍只有一名交付责任人。高风险变更由非作者复核；若暂时没有复核人，可继续开发，相关门禁保持待复核，不自报通过。

| 代码 | 职责 | 必须交出的结果 |
| --- | --- | --- |
| TL | 技术及交付负责人 | 分配实名负责人、依赖排程、契约与风险裁决、合并和批次放行结论 |
| BE | 后端／数据工程 | 权威状态、鉴权、事务、迁移、接口、任务与审计事实 |
| WEB | 运营 Web | 真实页面、状态反馈、错误和重试接续、可访问交互及 Playwright 入口 |
| AND | Android | 管理／本机边界、原生授权、持久意愿、发现上报、安装升级与实机证据 |
| EX | 执行适配／网络控制 | Artemis 固定版本及补丁、动作许可、真实停止、目标核对、执行回执 |
| AI | 业务 AI／数据 | 受约束建议、来源数据、比较条件、真实反馈到后续执行 |
| QA | 质量负责人 | 事前判据、用例与证据审查、缺陷复测、批次结论建议 |
| OPS | 开发部署／运维 | 环境隔离、受控凭据、日志、备份恢复、发布回滚和支持清单 |
| BIZ | 业务输入提供方 | 测试项目、素材、平台资源、批准范围、指标与真实计佣依据 |

BIZ 提供项目事实与发布授权，不承担选框架、定义锁或设计协议的工作。QA 判断证据是否满足标准，不能以资源不足更改需求；TL 对实施与放行负责，不能把未验证标为通过。

## 批次与效率原则

| 批次 | 用户可核对的交付结果 | 范围 |
| --- | --- | --- |
| B0 工程基础 | 可复现构建、正式与 Demo 隔离、首批契约可审查 | WP-00～01；只证明工程基础 |
| B1 身份与归属 | Web 邀请、真实短信注册／登录、逐台关联、三类访问范围与状态一致 | WP-02～07 |
| B2 接入与控制 | 新手机可受控接入，暂停／恢复／退出、分配及初始化真实成立 | WP-08～13、WP-20；WP-14 的最小项目／分配基础提前提供 |
| B3 媒体执行 | 人工素材 → 获准 AI 安排 → 正确手机／身份 → 平台核验及异常接续 | WP-14～19、WP-21，复用 B2 |
| B4 反馈与基础分佣 | 来源可核对、周期及点击口径正确、反馈落实到后续执行、本人基础分佣 | WP-22～26 |
| B5 完整验收与交接 | 全形式、两类业务、多设备、故障恢复、部署运维资料及首期判定 | WP-27～29 |

顺序代表业务交付，不是所有任务串行等待。B0 契约通过后 Web 与 Android 可按同一契约并行开发；不依赖真机的项目、素材、反馈数据模型可以提前做。网络与停止能力在 B2 开发中优先验证，不恢复为 B1 开工前的独立实测项目。WP-27 的部署和备份设计从 B0 起跟进，B5 前完成恢复演练。

不得让每个端分别重做同一业务规则。每个跨端包由主责牵头，先交字段与状态样例，再完成真实垂直流程；模拟数据仅用于开发和补充测试，不可作为业务完成证据。人员和资源未确定前不编造日历工期；负责人领取后按子任务估算、记录资源依赖与复核时间，范围变化重新估算。

## 文档一致性检查

从仓库根目录单次运行：

```sh
python3 docs/engineering/delivery/check_consistency.py
```

[检查脚本](check_consistency.py)只读检查需求追踪完整性、工作包/台账一致性、工作包及验收引用、编码和交付依赖的循环、文件链接与 Markdown 锚点；无外部依赖，不启动服务或业务测试。通过仅代表结构检查通过，仍需人工核对业务语义、分批范围及实际证据。新增需求、工作包或用例时同步文档后运行此命令。
