# 质量门禁与监督清单

更新：2026-09-29。适用于[全部工作包](work-packages.md)。门禁是开发管理要求，不能放宽[仓库工程规范](../../../CLAUDE.md)及既有业务授权。下面的空复选框都是待执行检查，不表示已通过。

## 质量状态与责任

任务流程：待分配 → 待开工 → 开发中 → 待评审 → 待联调 → 待验收 → 已验收。任何阶段可另标“阻断”，保留原阶段、阻断原因和解除条件；失败用缺陷关联，不用百分比隐藏。代码合并可以早于真实设备验收，但相应能力不得标可用或进入有副作用的运行。

测试结果只用通过／失败／阻断／未验证；确实不适用时另写适用性说明和依据，由 QA/TL 复核，不能把必需能力标“不适用”规避。代码完成、模块验收、批次通过和首期通过分别记录。

## G0 任务可开工

负责：工作包主责；复核：TL，涉及跨端时由消费方共同核对。

- [ ] 实际任务卡有 WP/R/AC 编号、主责姓名、复核人、明确范围和排除项；所用文档修订与代码基线可定位。
- [ ] 编码依赖已经提供必要产物；联调资源和交付依赖可以未到，但已填责任人、最晚时点及不受阻的工作。
- [ ] 本包所需 CT 项有明确字段/权限/事务/时序，或契约本身就是本次任务产物；不要求全系统接口先写完。
- [ ] 现有修改、Demo 数据、未决任务及历史证据受保护；复用组件列来源、适配点和需补验范围。
- [ ] 已拆成能独立评审的小变更；预期失败路径与测试方式清楚，暂无人日估算时如实填待估，不编造承诺。

## G1 代码与数据可合并

负责：非作者复核人；TL 负责处理跨包影响。作者提交自检证据，不可只写“本地正常”。

- [ ] 实现符合当前需求和已接受 ADR，正式目录、workspace、唯一锁文件正确，不偷偷复用 Demo 固定操作者/成功状态/数据库。
- [ ] TS 严格类型、联合字符串和运行时入参校验；Python 类型与结构化失败；异常被处理并包含可定位的非敏感上下文。
- [ ] 后端验证身份、对象归属、当前许可和版本；页面禁用按钮不能代替服务端校验；本机不能提升管理权限。
- [ ] 事务、唯一约束、并发锁/版本校验及幂等记录足以守住不变量；外部调用失败可接续，不在长事务内等网络。
- [ ] 新迁移在空库和前一正式 schema 上验证；已有数据重名/冲突、部分升级失败和前向修复/回滚有说明；不静默删历史、清暂停或重播队列。
- [ ] 高风险规则有补充单元/集成检查：并发配额、重放、乱序、撤权、未知提交、历史计数、预算及恢复；测试断言业务结果，不只是照抄实现。
- [ ] 代码评审检查敏感字段的完整数据流：日志、错误、截图、trace、模型输入、对象链接、队列载荷；不能先泄露再对报告脱敏。
- [ ] 正式目标的类型/构建/lint及必要补充测试通过；失败、未运行和原因分别记录。可逆低影响文案改动只做适当检查，不为了清单制造无意义测试。
- [ ] 修改接口和状态时同步生产者、消费者、契约版本、UI 文案、AC 与迁移；不把未实现端点写成可运行命令。
- [ ] 未完成的真实能力在产品中不可误报成功或触发未验证副作用；“代码可合并”记录所缺真实验收，不等于上线授权。

## G2 可进入真实联调

负责：QA+OPS，开发主责提供环境，TL 确定范围。

- [ ] 固定 commit（脏工作区另附 diff 摘要/哈希）、APK/构建产物指纹、数据库迁移、Artemis 提交及补丁、模型与配置版本。
- [ ] 确认实际服务地址、正式/Demo 标识、数据库/队列/存储隔离及所需账号、手机、网络、短信和外部服务资源。
- [ ] 核对现有实例与在途/未知任务；按已有任务授权操作，遵守开发者启动或明确授权后启动纪律。统一入口不自动消费设备队列。
- [ ] 每个待执行 AC 有前置状态的合法建立方法、页面步骤、预期结果、样本、阈值、观察时间、证据目录和资源责任人。
- [ ] 真正的故障注入、重启、撤权和公开发布范围已明确；公开发布和撤下不能由“测试一下”推定无限权限，已有明确授权不重复索要。
- [ ] 测试账号与素材、短信号码、现场协助、退出后的清理和未决结果处理有安排；不改生产库或借预置成功通过验收。

## G3 工作包与批次可验收

负责：QA 核对事实，主责整改，TL 签署技术结论；BIZ 核对业务输入和实际平台对象。

- [ ] Web 从真实入口经 Playwright 填表、点击并断言反馈和最终事实；原生 Android 和实际设备操作有对应证据；Artemis 负责媒体 App 识别、决策和执行。
- [ ] 用例包含正常、失败、响应丢失、重复/乱序、权限隔离、重启及当前包涉及的并发；不能只凭截图或脚本零退出判通过。
- [ ] 所有必需 AC 的子场景分别有结果；部分通过不可整行写通过，多机/平台/形式未覆盖明确列出。
- [ ] 只读日志/接口/数据库可补充关联，不能替代 Web 待验收动作；测试 fixture 和 Mock 结果仅在补充测试报告中使用。
- [ ] 对未发生的副作用保留可检查的观察依据：指定设备/任务、完整观察窗口、动作审计与平台核验，不能凭一张截图证明“没有重复发布”。
- [ ] 证据与当前提测版本对应；旧证据只复用未受变化影响的范围；所有敏感内容在保存前保护。
- [ ] P0/P1 缺陷无未关闭项；其余缺陷记录影响、临时处置、责任人与复测计划。必需业务断言失败不能通过降低等级豁免。
- [ ] 交付依赖、安装/使用说明、错误接续和支持范围已交接；未满足条件则分别写失败、阻断或未验证，不写“基本通过”。

## G4 首期放行与运维交接

负责：TL+QA+OPS，业务负责人依据既定范围确认试运行。

- [ ] B1～B5 所有必需范围有证据；两个平台、四种发布形式、产品/短剧、异常及设备规模覆盖见 AC-55/56。
- [ ] 原通过证据、新增实测、失败/阻断及未验证范围明确；R-109 既有执行不重置为全未验证，也不外推为新客户端已通过。
- [ ] 实际部署、升级/回滚、备份恢复、队列故障、对象丢失和旧客户端兼容演练完成；恢复不使暂停/退出/未知任务丢失。
- [ ] 20–50 台管理及分散网络条件按事先定义的负载模型验证；不要求全量同时执行，也不以单机或虚拟设备代替真实支持结论。
- [ ] 支持机型/系统/客户端版本、资源配额、限流/并发、通知与排障、证据保留及账号恢复通路写入手册。
- [ ] 系统闭环与商业结果分别报告；不承诺取得分成资格或收益提升，不把分佣记录视作付款完成。
- [ ] 必需项仍失败/阻断/未验证时不宣称首期完整验收通过；有限范围试用若另行授权，单独记录范围，不能改名冒充完整验收。

## 专项零容忍断言

这些断言是正确性约束，不是事后设定的性能目标；任何一次违反均停止受影响范围的验收和真实执行，定位并修复后回归相关链路。

| 不变量 | 必查场景 |
| --- | --- |
| 不串人、不串设备、不串发布身份 | 扫码/配对交错、旧会话迟到、同端口不同节点、跨人对象 ID、换机和跨项目交接 |
| 未授权不操作、不读取 | 失效凭据、提供者暂停、退出、控制服务不可达、旧代次、监控/人工截图旁路 |
| 未知发布不重发 | 提交后断网、回执丢失、队列重复、中心恢复、模型会话变化 |
| 不丢事实、不重复计数 | 注册配额、平台名额、迟到发布、累计快照、分佣导入、备份恢复 |
| 不假装停止或清理 | 取消进程、超时、租约到期、手机失联、权限撤回响应丢失 |

## 日常监督与缺陷处置

- 开工时 TL 核对依赖、实名责任及风险，不让多人各自修改同一契约或根锁文件；共享文件由当次指定负责人汇总。
- 每次 PR 由作者列变更/需求/断言/证据/风险，复核人按 G1；仅检查代码风格不能替代事务和副作用审查。
- 每次提测 QA 核对 G2；结束后按 AC 子场景登记四态结果和复测版本，台账按实际交付变化更新，不汇报模糊完成比例。
- 每周或每个交付批次（先到者）TL/QA 复核阻断年龄、关键路径、逾期资源和无证据“完成”项；人员紧张时缩小同时在做的包数，不减少必需断言。
- P0：越权真实操作、秘密泄露、破坏性数据错误等，立即停止受影响操作、保留证据并通知 TL；修复、凭据处置或数据修复后验证再放行。
- P1：核心流程失败、未知结果重发、伪停止、关键隔离/恢复错误，阻止对应包或批次通过；P2/P3 为不违反必需断言的非关键问题，留责任与期限，不借等级掩盖必需项失败。

代码或契约改变后按影响选择回归：身份变更回归 AC-01～10/58；许可/队列变更回归 AC-16～20/30/37/59；素材/发布变更回归 AC-27～43；数据口径变更回归 AC-44～51；恢复/迁移变更回归 AC-52/53/60 并抽验相应业务链。全部测试通过后不无依据反复扩大测试。

## 检查命令的适用边界

现有 `pnpm env:check` 只证明仓库运行环境；现有 `pnpm build`、`pnpm build:runtime`、`pnpm test`、`pnpm lint` 与 `pnpm test:playwright` 当前仍以 Demo 为目标，不能声称覆盖未搭建的 product。WP-00 必须维护正式命令清单及实际目标，保留统一 `pnpm test:playwright` 的真实 Web 验证方式，不新增其他 E2E 套件替代。

单元/非 UI 集成、契约、数据库并发及构建是补充检查；允许合成数据验证确定性规则，但与真实短信/原生授权/平台发布报告严格分开。服务不可用且无启动授权时报告阻断，不使用 Mock 或直接改库让业务验收“通过”。文档修改仅需链接、引用、覆盖与差异检查，不要求启动业务或重跑媒体发布。
