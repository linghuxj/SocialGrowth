# 验收执行矩阵

更新：2026-09-29。AC 编号为必须展开的验收场景组，不是已运行的测试脚本或通过记录。当前全部为待实施／未验证；既有证据按本文复用规则引用，不抹去 R-109 或单机局部已通过事实。原始验收范围以[验收与证据](../../acceptance-plan.md)为准。

## 执行与取证规则

1. QA 在提测前将一行拆成可执行子场景，例如 AC-05-a 最后名额、AC-05-b 同号竞争、AC-05-c 响应丢失；为每个子场景填输入、操作、预期、资源、版本、观察时间及阈值。一行内所有必需子场景通过才可汇总通过。
2. Web 相关前置及动作通过实际页面、真实表单/按钮建立，由 Playwright 操作；不能直接调用后端建立成功状态、改库、Mock 业务结果。部署初始化首个运营账号是允许的系统准备，不能代替待验收的页面开通账号。
3. Android 原生入口、系统授权和本机状态用真实 App 操作与设备证据；Artemis 负责媒体 App 判断和执行，不以固定手机点击脚本替代其决策。原生自动化可覆盖自有 App，但不能替代真实短信、网络或平台结果。
4. 并发、时区、接口隔离等确定性规则可用单元/非 UI 集成测试补强；报告标明补充层次，不能据此声称真实链路通过。响应丢失/断网用受控故障造成，不伪造成功回执；无法安全建立情形则记录阻断并说明所缺条件。
5. 每个子场景使用[记录模板](record-templates.md)保留命令或原生步骤、版本、截图/日志、关联 ID、断言与四态结果。证据敏感字段在生成前保护，密码/码输入阶段避免收集截图和 trace。
6. 服务、资源及授权不具备时如实阻断；本矩阵不是启动服务、清队列、重启手机、公开发布或付款的无限授权。

## 既有证据如何复用

- R-109 的既有远程执行继续有效；按[盘点](../../verification-readiness.md)记录原环境和未受变更影响部分，不要求重复证明基本远程控制存在。
- 2026-09-28 的单机前台 NSD 和既有密钥下 IPv6 ADB 身份核对只支持 AC-14 的局部发现/连接前提。不能勾选 AC-11～15 整组通过，首次配对、独立上报、后台、多机与网络共存另测。
- Web 原型九组检查及 metric-availability fixture 仅支持设计/确定性规则检查，不能替代任何正式页面、短信、平台或收益证据。
- 复用记录写明原证据路径、版本与机型、哪些断言复用、当前改动为何不影响、还缺哪些场景；影响无法判断时重新验证受影响范围。

## 判定出口

每次运行记录四态结果，批次结果按[质量门禁](quality-gates.md)汇总到[台账](delivery-tracker.md)。测试数量、截图数量、代码覆盖率和工作包完成数量都不能单独证明业务验收。所有性能数值和观察时间应在测试前写入 QC-性能记录；尚未确定时只能给探索结果。
