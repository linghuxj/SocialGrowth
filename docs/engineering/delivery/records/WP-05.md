## 范围与安全边界

- 执行手机首次启动生成 256-bit 随机根凭据并先安全保存，再用它创建或恢复低权限安装身份。服务端仅保存加 pepper 的凭据摘要；普通请求改用独立安装会话令牌。
- 安装身份只允许读取本机必要事实和创建本机关联会话。它不是 Provider、设备归属、网络节点、ADB 目标或可执行业务许可；公开引导本身不能认领设备。
- 管理手机扫描只读取目标标签和安装 ID；只有登录 Provider 在核对后明确确认，才原子消费一次性会话并创建唯一归属。取消、扫码或查看不会写关联。
- App 重启复用安全保存的根凭据和安装会话。清除数据或重装丢失根凭据时必须建立新安装身份；不按机型、名称、IP、旧设备 ID 或本地残留自动恢复旧归属，也不清除旧暂停／退出状态。
- WP-05 不实现 Tailscale 准入、ADB 配对、执行许可、暂停／恢复／退出或三端完整管理页面；分别属于 WP-08～12 与 WP-06。

## 分阶段执行与提交策略

1. 安装身份权威边界：安装根凭据、可恢复的低权限会话、摘要保存、重装新身份语义及跨端契约；用 PostgreSQL 证明重放不重复建身份、旧会话随身份失效。
2. 关联 HTTP 与结果查询：安装端创建会话/查询本人结果，Provider 扫码查看/确认/查询本人多设备；认证、权限、幂等、迟到结果及真实 PostgreSQL HTTP 回归。
3. Android 双模式流程：执行模式安全保存身份并显示关联码；管理模式扫码、核对、取消、确认和多设备列表；真机覆盖重启、清数据、重复确认及另一 Provider 隔离。
4. 每阶段形成一个可独立复核的凝聚提交，不按文件或单次操作提交。固定提交交同一非作者复核窗口；remaining findings 清零后再交同一验收窗口，验收通过才合入 `Developer` 并进入下一阶段。

## 第一阶段执行状态

- 新增版本化的安装根凭据契约：仅接受 `sginst_v1_` 加 32-byte base64url 随机量，不接受设备名称、硬件 ID 或客户端自填 installationId。
- 新增安装身份认证响应契约：只返回服务端 installationId、代次、状态、会话摘要和会话令牌，严格对象拒绝回传根凭据。
- 新增安装引导服务：以根凭据摘要串行化并发创建；同一根凭据重复请求恢复同一 installation/session/token，不重复创建。根凭据使用带 pepper 的 HMAC 摘要，会话令牌仅保存 SHA-256 摘要，审计不含凭据或令牌。
- 清数据／重装语义已在 PostgreSQL 补充测试中固定：新根凭据产生新 installation，默认没有任何 device association；无法据此认领旧关系。安装状态变为 replaced/revoked 后，旧会话认证失败关闭。
- 第一阶段不暴露 HTTP 路由、不实现 Android 页面，也不宣称扫码、真机重启/清数据或 AC-06～08 通过；这些必须在第二、第三阶段按真实入口验收。
