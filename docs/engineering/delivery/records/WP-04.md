# WP-04 执行记录：提供者短信注册与原身份登录

更新：2026-09-29。状态：开发中；业务验收：未验证。

## 任务卡与分工

- 工作包／批次：WP-04 / B1；主责 AND，协作 BE、QA、OPS。
- 需求／契约／验收：R-110、R-111、R-127、R-134、R-136、R-138（由 R-152 修订）、R-152；CT-01、CT-02；AC-04、AC-05、AC-09。
- 基线：`Developer` 的 WP-03 验收记录提交 `8096a30`；执行分支：`feature/wp-04-provider-registration-stage1`。
- 实施：Codex（阶段实施代理）；非作者复核和正式验收继续沿用既有复核窗口与测试验收窗口。
- AND 负责 Android 管理模式入口、注册/登录交互、会话安全保存与真机证据；BE 负责短信适配边界、用途绑定、限流、注册/登录事务和 HTTP；OPS 负责真实短信服务、支持号码、配额及秘密配置；QA 负责真实短信、同号/末位名额竞争、响应丢失及真机回归。

## 范围与排除项

- 首次提供者使用有效邀请和本人选择的手机号，经真实短信验证后创建唯一身份；已有手机号验证后回到原身份，不要求新邀请、不重复消耗名额。
- 验证码必须绑定手机号、用途、挑战和有效期；发送成功不等于验证成功。错误、过期、重发、限流、供应商失败和成功响应丢失分别表达，失败不得创建会话或消耗邀请。
- 登录管理手机不自动把本机接入执行，不改变已有设备分配、暂停或退出状态，也不授予运营权限。
- WP-04 不实现设备扫码关联、设备状态视图、暂停/恢复/永久退出或完整账号找回；分别属于 WP-05、WP-06、WP-12。原号码不可用的人工核验换绑按 R-140/R-141 留在 WP-06 最小受控办理范围。

## 设计与实现输入

- Android 页面语义以 `docs/android-app-alignment.md`、`docs/first-delivery-flow.md` 和需求基线为准。
- 注册视觉参考必须同时读取 `docs/design/android/provider-registration-v1.png` 与 `provider-registration-prompt.txt`，并以 `docs/design/android/README.md`、`DESIGN.md` 校正；参考稿是方向证据，不复制示例手机号、验证码、邀请值、设备或成功状态。
- 现有 `registerProvider` 契约、`phone_verifications`/`providers`/`provider_sessions` 表及注册事务是 WP-01/WP-03 的工程输入，不代表短信发送、HTTP、Android 页面、真实会话或 AC 已实现。

## 分阶段执行

1. 权威短信与身份契约：挑战申请/确认、用途与号码绑定、重发/过期/限流/供应商失败、首次注册与原身份登录、提供者会话和 Android 消费；同步数据约束及跨运行时反例。
2. 后端与真实短信适配：供应商端口、秘密配置、发送/验证分离、注册/登录 HTTP、Cookie/移动会话边界、幂等接续、同号和末位配额并发；外部调用不得处于数据库长事务内。
3. Android 管理模式：邀请入口、手机号与验证码流程、已有身份登录、安全会话保存、退出；真机验证登录不接入本机、不改变已有设备事实。
4. 每阶段形成凝聚提交，交同一非作者复核窗口；remaining findings 为零后才进入对应正式验收或下一阶段。真实短信资源 RES-03 未就绪不阻止第一阶段契约开发，但会阻断第二/三阶段真实联调和 AC 汇总通过。

## 第一阶段启动状态

- 已确认 WP-01 与 WP-03 编码依赖可定位，现有邀请注册事务已覆盖末位名额、同号唯一、响应重放和回滚的 PostgreSQL 工程基础。
- 当前缺口是完整短信挑战、提供者登录/会话、HTTP 与 Android 消费契约；第一阶段先收口这些权威语义，不用模拟短信结果宣称真实送达或验证。
- 真实短信供应商、支持号码、发送配额与安装入口由 RES-03 跟踪；秘密不得写入任务卡、提交、普通日志或截图。
