- 运营视图用判别联合固定 active/disabled 与 `disabledAt` 的一致性，并携带 `factVersion` 支撑停用竞争检查。
- 一次性 DDL 增加显示名、事实/凭据版本、密码更新时间、停用时间、会话 CSRF 摘要/凭据版本/撤销原因及登录限流表；约束状态与时间一致性。

## 第二阶段非作者复核整改

- 固定提交 `937a94f` 复核结论为需修复：运行时缺失 CSRF 可进入读认证分支；首次限流记录与账号锁存在反向等待；会话认证与凭据恢复锁序相反；已封锁请求仍先执行 scrypt。
- 整改将写认证显式设为强制 CSRF，缺失/畸形值使用不命中摘要并失败；登录在 scrypt 前做只读封锁快拒，事务内仍按数据库时间权威复核。
- 登录事务统一为账号行→限流行，会话认证/退出/恢复统一为账号行→会话行；首次限流冲突仍由原子 upsert 累计。真实 PostgreSQL 用例增加存在账号首次并发失败、缺失 CSRF、认证/恢复交错及 `pg_stat_database.deadlocks` 前后不变检查，10/10 重新通过。
- 二次复核确认四项实现缺陷均已关闭，但要求排除并发用例假通过：存在账号并发限流现逐项断言 `INVALID_CREDENTIALS`、数据库累计 5 次且第 6 次 `LOGIN_RATE_LIMITED`；认证/恢复用外部事务锁住会话行，并通过 `pg_stat_activity` 分别确认认证等待会话、恢复等待账号后才释放屏障，双方必须成功且 deadlock 计数不变。

## 第三阶段非作者复核整改

- 固定提交 `6eccf60` 复核结论为需修复：新标签页继承 session cookie 但没有标签页级 CSRF 时会进入不可写状态；页面内 401 不返回登录态且失败退出提前删除 CSRF；网络失败重试生成新幂等键；代理部署下客户端限流范围不明确；未知服务异常不符合产品错误 envelope。
- Web 在已有 cookie 但无 CSRF 时明确要求重新认证；所有页面内 401 统一清理本地凭据并返回登录态，非 401 退出失败保留原 CSRF。开通/停用以规范化业务输入保存待确认幂等键，网络失败重试复用，成功或输入改变后更新。
- 后端增加脱敏、可重试的 `INTERNAL_ERROR` 契约边界，Web 对非 JSON/非契约响应提供安全兜底。代理信任默认关闭，仅允许通过 `SG_PRODUCT_TRUST_PROXY_HOPS` 按固定拓扑显式开启；本地 Vite 发送转发地址，联调后端固定信任一跳。
- 回归增加 API 单测和真实 Playwright 场景：无 opener 新标签页要求重新登录，账号被停用后的当前页面写操作直接收到 401 并切回登录页；完整两账号、最后账号保护和退出流程重新通过。该整改仍须交回同一非作者复核窗口，未取得复核通过前不得进入正式验收。
