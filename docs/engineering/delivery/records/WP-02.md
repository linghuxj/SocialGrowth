## 第一阶段当前产物

- 新增运营登录、账号视图、列表、开通和停用契约；登录只携带 request trace，写操作携带幂等 metadata。登录标识要求调用方提交已规范化的小写 ASCII（Web 提交前显式规范化），避免 TypeScript、JSON Schema、Python 和 Kotlin 的隐式转换差异；密码仅存在于写请求，任何 view/response 均不返回。
- 固定无效凭据、登录限流、账号重名、账号停用和最后有效账号保护的机器可判定错误码；错误仍使用统一 envelope，且不泄露账号是否存在。
- 运营视图用判别联合固定 active/disabled 与 `disabledAt` 的一致性，并携带 `factVersion` 支撑停用竞争检查。
- 一次性 DDL 增加显示名、事实/凭据版本、密码更新时间、停用时间、会话 CSRF 摘要/凭据版本/撤销原因及登录限流表；约束状态与时间一致性。
- 本阶段尚未实现密码哈希、会话服务、初始化命令、HTTP 路由或 Web 页面，不能执行真实登录或账号管理验收。

## 第一阶段非作者复核整改

- 固定提交 `338057b` 的复核结论为需修复：Python 参考消费器不支持列表数组；显示名边缘 Unicode 空白在 TS/Python 中语义不同；登录/停用成功响应未锁定操作后的账号状态。
- 整改为 Python 递归校验数组元素并严格检查 `items` 规格；显示名显式列出 Unicode 空白边界以保留其他数字/时间正则的 ASCII 语义；登录/开通响应只允许 active，停用响应只允许 disabled，列表仍允许两种状态。
- 增加数组元素未知/敏感字段、状态矛盾、Unicode 空白及操作结果相反状态的 TS/Python 反例。本阶段仍须经同一窗口复核和正式子范围验收，不能提前进入后端身份服务阶段。
- 二次复核确认数组与响应状态问题关闭，但发现 JavaScript `\\s` 还覆盖 Python `re.ASCII` 不覆盖的 `U+FEFF`；最终整改显式加入该字符，并在 TS/Python 同时覆盖首尾反例。
