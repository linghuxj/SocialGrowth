## 分阶段开发与质量门禁

1. 权威事实读取与跨端契约：运营 Cookie 身份读取提供者及当前设备归属，返回同一数据库语句快照、服务端读取时间、脱敏号码和明确未知的连接观察；管理端已有本人设备接口、本机已有自身状态接口保持隔离。补契约/权限/数据库回归，不增加模拟连接事实。
2. 运营 Web：按当前有效设计实现提供者/设备事实视图，含空态、加载、刷新、错误、返回及退出后的资料清除；Playwright 从真实页面操作与断言，旧响应不能覆盖新身份/新刷新。
3. Android：管理端本人清单与详情、登录帮助及明确退出；执行端只看自身必要事实。真实设备覆盖冷启动、退出重登、管理与执行隔离；不把退出管理登录当作设备暂停或永久退出。
4. 三端联调和缺口复核：按 AC-08/09/57 分场景记录通过、失败、阻断、未验证；双机光学扫码人工补验与真实短信 R-157 分别保留原责任与证据，不借其他检查填通过。

每阶段形成凝聚提交后交原非作者复核窗口，问题清零再交原验收窗口。代码可按 G1 合入；工作包和 B1 的 G3 业务验收仍按真实证据独立判定。

## 第一阶段实施边界

- 新增严格版本化的运营事实响应契约与 `GET /api/operator/device-facts`：只接受有效运营 Host Cookie，由同一数据库读取当前提供者和未结束的归属设备；无设备提供者保留在列表中，同一提供者多设备不重复提供者行。
- 服务端返回读取时间、提供者脱敏号码末四位、设备归属/状态/事实版本。`connectionState=unknown` 且 `lastConfirmedAt=null`，后续有真实连接观察来源时须另行修订契约和跨端消费者。
- 本阶段不建设 UI、不修改 Provider 或 Installation 的既有 API，也不宣称三端真实页面或退出行为已验收。
