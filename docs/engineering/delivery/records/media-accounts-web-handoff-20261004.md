## 一、已经确认的产品边界

### 账号分别管理

| 对象 | 用途与边界 |
| --- | --- |
| 内部运营账号 | 公司内部人员登录 Web，管理项目及资源；沿用内部运营同权，不新增角色层级 |
| 真机管理账号 | 设备提供者登录自有 Android App，管理本人手机和查看本人基础分佣；一人可以有多台手机，不授予公司社媒账号或运营管理权 |
| 公司社媒登录账号 | 公司持有、预先申请的 Facebook／Google 登录账号；用于受控登录，不在首期自动注册 |
| 发布身份 | 登录账号下实际 FB Page／YT 频道，独立保存平台身份与管理权限核验依据；不是登录账号的显示别名 |

“真机管理账号”不指 Android 系统 Google 账号。提供者管理登录不自动接入本机，也不改变社媒账号的公司归属。

### 独占分配与身份核验

- 同一时间，同一手机、同一平台只分配一个公司社媒登录账号；同一个社媒登录账号反向也只分配一台执行手机。
- 同手机对应平台固定一个 Page／频道，同一发布身份只由一台执行手机承接；不允许同一父登录账号以不同 Page／频道同时分配多台执行手机。
- 手机及账号同期专用于一个项目，同手机启用的 FB／YT 身份属于同一项目。暂停或掉线不自动释放分配；换机、跨项目转移沿用 R-103／R-107，核清旧端停止、未决任务及相关收尾安排，保留历史。
- 此处是系统执行分配规则，不承诺平台外部所有登录会话已被清除。不能用重复登记同一真实账号绕过独占约束。
- 个人登录账号注册不在首期范围；R-158 已确认的 Page／频道检查、已有复用及缺少时创建继续保留。创建及初始化不自动授权内容发布。

### 录入与辅助登录

- 登记账号必须提供平台、登录标识和密码，可使用运营显示名帮助识别；密码由系统加密保存。首期不提供缺密码的建档路径。保存成功不代表密码有效或登录成功。
- 姓名、生日、性别等是**可选的既有真实核验资料**，仅供必要人工核验，不设为必填、不生成虚构人设、不用于自动注册。
- 完成项目和手机分配且当前授权、设备控制条件满足后，Artemis 判断登录界面，通过受控通道填入凭据、提交登录并核验准确父登录身份。验证码、双重验证和异常确认交人工，处理后仍需核验实际结果。
- 密码不进入 AI 对话、普通日志、截图或查询响应；受控填入接口传递秘密不等于允许将秘密放入模型工具参数。前端清空表单不能被描述成保证销毁浏览器或 JavaScript 中所有秘密副本。
- 登录成功后继续核验指定 Page／频道及管理权限。登记、预留、绑定、登录、发布身份核验及具备执行条件分别成立；首次承接起点仍按 R-145，不从保存或分配时点开始计佣。

`canonicalAccountRef` 在现有模型中表示平台规范身份标识，不得沿用原文“任意英文／数字／下划线标识名”的解释。运营显示名、登录邮箱／手机号、平台父登录标识、Page／频道标识各自表达；建档声明与后续核验事实分别保存。准确标识尚未取得时如何登记及补齐，由契约方案明确，不用编造已核验标识填空。

## 三、接手工程清单

以下保留 2026-10-04 接手时的待办，不是实时任务清单。哪些已经实现或通过、哪些仍阻断，以[2026-10-05 实施记录](media-accounts-r159-20261005.md)为准。

1. **契约和数据一致性。** 明确账号登记、查询、凭据更新及分配的输入、身份语义和错误反馈；可选核验资料不得设非空门槛。增量迁移编号按实际仓库状态确定，更新恢复清单，不在交接中抢占固定 `0039` 编号。
2. **密钥接线与原子保存。** 现有 `MediaCredentialStore.write()` 自行获取连接并开启事务，不能直接嵌入外层新建账号事务。账号、凭据、审计及命令去重须形成一致的事务边界，失败不留下部分成功。密钥缺失时保留明确的不可用状态。
3. **原请求恢复。** 重复点击、并发登记和响应丢失需要原键与原请求核对；不能因前端清空密码后无法重试就换新键自动新建。错误日志、请求审计和验收 trace 不记录秘密。凭据覆盖／失效与平台改密／退出登录分别表达。
4. **运营页面和资源分配。** 建立全局媒体账号列表、登记、必要资料维护及凭据替换入口，与后台运营账号和提供者账号明确区分。展示可识别账号、对应发布身份、项目及手机分配和真实核验状态；从项目筹备衔接账号／手机分配，后端原子拒绝独占冲突，不能仅靠下拉框过滤。
5. **受控登录与核验。** Artemis 自主观察和决定界面动作，秘密通过受保护输入通道消费；消费时核对当前账号、凭据版本、任务范围、目标手机和控制许可，拒绝过期或失效凭据。所有实际界面动作遵守单机互斥、暂停／退出和未知操作规则。必要人工验证后回读指定父登录及发布身份，不能用模型报告替代业务核验。
6. **资源交接与承接。** 明确占用及阻断原因，接入换机／跨项目交接需要的原资源、旧端及未决事实，不通过修改当前绑定覆盖历史。承接起止仍分别依据 R-145／R-146，不因保存账号、登录或轮换凭据而重置。

不扩展公众注册、虚构人设生成、运营角色分层或独立资金系统。现有 R-158 创建 Page／频道属于已确认范围，不新增个人登录账号注册入口。
