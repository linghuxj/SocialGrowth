## 当前实施决定

- 正式 TypeScript 包使用 Node 24.16.0、TypeScript 5.9.3，并通过根 pnpm 8.14.0 的唯一 lockfile 管理。
- 后端采用 NestJS 12.1.1；Web 采用 React 19.2.6、Vite 8.0.13；跨端运行时输入使用 Zod 4.6.5。版本是 WP-00 的可逆工程选择，不新增产品需求。
- 正式 Web、后端和本地 PostgreSQL/Redis/MinIO 使用不同端口、数据库名和具名卷；示例配置不包含可用秘密。
- 正式 executor 的 WP-00 入口固定为 `disabled`，不消费 Demo 或正式设备任务。
- `pnpm test:playwright` 保持 Demo 默认行为以兼容既有使用；`SG_WEB_TARGET=product` 或 `pnpm test:playwright:product` 明确选择正式 Web。两者都必须从真实页面操作，不用接口状态代替。

## 分批、分工与协同确认

- 批次按 B0 工程基础、B1 身份归属、B2 接入控制、B3 媒体执行、B4 反馈分佣、B5 完整验收依次形成可核对结果；编码可按依赖并行，但批次验收不跨过交付依赖。
- 每个 WP 只有一名交付负责人，另列协作人、非作者复核人和 QA。人员未实际领取前维持待分配，不以职责代码或实施代理冒充实名接受任务。
- 每个任务按 G0 开工、G1 合并、G2 联调、G3 工作包/批次验收、G4 首期放行推进；代码完成、模块验收、批次通过和首期通过分别记录。
- 跨端变更先完成对应 CT 字段、权限、事务、幂等和时序交接，再由各端实现；生产者或状态变化同步通知消费方并更新契约、AC 与迁移说明。
- `delivery-tracker.md` 是唯一状态入口，`records/` 保存任务卡和证据摘要；Playwright、Android 真机、Artemis 和只读补充证据按各自边界执行，任何阻断、失败或未验证不得改写为通过。
