# WP-07 首批真实闭环验收：阶段一执行准备

更新：2026-09-30。状态：证据归集与场景拆分中；**WP-07／B1 尚未通过 G3**。

## 基线、职责与限制

- 工作包 WP-07、批次 B1，输入为 WP-02～06 的正式工程产物；本阶段基线 `Developer@02b7ed5`，执行分支 `feature/wp-07-b1-acceptance-stage1`。需求以 `docs/current-requirements-summary.md`、`docs/requirements-alignment.md` 和最新用户确认为准；验收场景以 `docs/engineering/delivery/acceptance-matrix.md`、`docs/acceptance-plan.md` 为准，门禁和记录格式依 `docs/engineering/delivery/quality-gates.md`、`record-templates.md`。旧 Demo 和设计稿中的样例数据不能建立正式业务事实。
- QA 主责拆分 AC 子场景、冻结判据、操作真机并汇总 T4/T6；BE 负责权威账号／邀请／设备事实、隔离数据库和只读核对；WEB 负责真实 Web 入口与 Playwright；AND 负责管理及执行两台独立实体手机和构建指纹；OPS 负责隔离环境、真短信接入资源与服务清理；BIZ 负责真实号码、人工身份核验与换绑授权口径；TL 负责 G0/G2/G3 门禁及残余风险结论。上述为职责，不代表实名成员已领取：各方姓名、联调时点和设备清单均待负责人实际填写，不能编造。
- 用户已默认授权本项目临时启动隔离服务和已连接手机真机联调；须先核对现有实例、在途任务及数据隔离，测试后清理。此授权不提供第二／第三台实体手机、真实短信供应商、生产操作、公开发布或受控换绑的业务授权。人员与环境缺口写入 T5，不阻停能独立完成的证据复用、脚本准备、E0 Web 流程与单机局部测试。
- Web 验收只用真实页面上的 Playwright 表单、点击和最终状态断言；原生步骤需真实 App／设备。部署 CLI 初始化首个运营账号是合法环境准备，第二运营账号与邀请必须走待验收 Web；不得直接调用业务 API、改库或 Mock 成功来拼接闭环。接口／数据库只读检查是补充证据。

## 阶段门禁和下一步

1. **阶段一：**QA/WEB/BE 整理现有报告索引，按上表展开最小 T4 子场景与版本适用性；补 E0 可在真实 Web 独立运行的回归，不向用户要求重复提供已明确授权的服务启动许可。形成一个凝聚提交交原非作者复核窗口检查覆盖与遗漏；文档或补充检查通过不等于 WP-07 G3。
2. **阶段二：**AND/QA 在现有 Samsung 做无需第二机的注册／管理/中断局部回归，使用受保护开发验证码仅闭合工程流程；与真实短信明确分列。若需要清设备数据或安装新 APK，先核对现有数据、在途任务和测试机范围。
3. **阶段三：**OPS/AND/QA 有管理手机＋一台独立执行机时可先跑 AC-06 基本光学关联、AC-07 B1 归属重启／重装、AC-08/09 单机非空事实及 AC-10 单执行机链路，但只登记各自局部 T4。**AC-10 完整多机**需同一提供者的两台独立执行机逐台扫码确认并在三端核对；**AC-03/08 多人及异主**需两名提供者/号码；AC-04 原号换管理机需另一台管理实体手机；真实短信到位后再跑相应 AC-03～05/10 短信分支。并发/重放/失效/响应丢失逐子场景记录，不因某一资源到位就解除其他阻断。AC-07 控制状态回归仍待 WP-12/20/21 建立真实暂停／退出，AC-58 还须先有安全复核的受控换绑实现和业务授权。资源不足按 T5 写真实需求、责任方、最晚需用时点待协作方确认及解除标准，继续其他可独立项。
4. **阶段四：**QA 汇总 T6：逐个 AC 子场景复核，WP-02～06 的局部证据只按原范围复用；TL/BIZ 对技术与业务输入分别签收。存在必需场景失败、阻断或未验证时，B1 不放行、不公开发布，不以工程分支合并替代 G3。
