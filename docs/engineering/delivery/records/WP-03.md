## 范围与排除项

- 运营创建、查询、复制和撤销可多人使用的邀请；成功注册次数上限和有效期可配置，同一共享码与链接共用额度；创建运营、实际注册提供者及关联进展可追溯。
- 只有最终注册成功才消耗一次名额。打开、复制、短信失败、验证码失败、重复提交、已有身份登录及新增设备均不扣次；到期、撤销或耗尽只阻止新注册，不取消已有身份或设备。
- WP-03 不实现短信发送/验证码供应商、提供者登录或实际注册页面；这些属于 WP-04。也不实现自动群发、逐人审批、预绑定手机号、虚构项目或独立工单系统。

## 页面与设计输入

- 页面语义以 `docs/workbench-page-spec.md` §8.2、`docs/first-delivery-flow.md`、需求基线和 AC 矩阵为准。
- 视觉方向采用 `docs/design/workbench/README.md` 的 UI-014 浅色工作台，参考 `provider-detail-v1.png` 与 `provider-detail-prompt.txt` 的提供者上下文、状态密度和逐台进展表达。

## 分阶段执行

1. 权威契约与数据模型：创建成功的一次性共享码/注册链接、列表、撤销、用量/剩余量、注册及关联进展、事实版本和撤销操作者。
2. 后端事务与 HTTP：运营会话授权、创建/列表/撤销、数据库权威时间、幂等接续、撤销/注册竞争与实际操作者审计。
3. Web 与正式验收：邀请创建/复制/列表/详情/撤销；Playwright 从真实页面验证管理流程，并在 WP-04 接入后完成多人注册、末位配额及响应丢失的跨端 AC。
4. 每阶段完成实现、文档和验证后形成一个凝聚提交，交同一非作者复核窗口；remaining findings 为零后才进入对应正式验收或下一阶段。
