# 首条闭环：关键表单与操作约束

版本：design-v1，2026-09-19。状态：产品实施规格，页面未按本版实现或验收。用于 B-05 与客户接入意见，细化[首条闭环产品规格](../product-first-loop-spec.md)已确认的动作；不新增客户门户、岗位、审批层级、自动素材提取或多重排序要求。

## 通用输入与反馈

内部运营人员选择项目后进入相关功能区域；保存不完整草稿不阻断其他项目整理。批准、实际执行、人工恢复分别校验。字段错误显示在对应输入旁；业务条件缺失显示对象、原因及可处理去向。请求失败保留输入，不显示成功，也不重复提交。

ID 由系统生成或从现有对象选取，用户看到可辨识名称及所属客户/账号；历史引用不能以改显示名称覆盖。字符串去除首尾空白后判空；URL 校验格式，实际可用与权限另核验，格式正确不等于目的地有效。时间输入包含业务时区，显示实际时间点；有结束时间时必须晚于开始时间；日期精度不足以决定执行时间的草稿不得批准排期。

以下“动作必需”不是所有字段都必须在首次保存填完。权限和业务校验必须由服务端再次执行；前端禁用按钮不能代替数据约束。

## 项目与账号接入

| 字段/组 | 输入及动作必需条件 | 校验与缺失表现 |
| --- | --- | --- |
| 项目名称、客户 | 文本、客户选择；形成正式运营范围必需 | 不以客户名代替项目主目标；未选客户可存草稿，显示待补 |
| 当前主目标、受众、期限、责任 | 主目标说明、受众说明、项目期限与负责人；提出策略/批准前明确相应范围 | 不强制全局目标排序；期限不能倒置，目标切换显示受影响的未开始安排待重审 |
| 账号、平台、所有方、授权方 | 账号选择、来源主体；关联真实运营前必需 | 平台/设备绑定必须一致；所有方不从当前服务客户自动推导 |
| 服务客户/项目、授权依据、动作与数据范围、有效期 | 关系选择、证据引用或说明、范围及期限；执行相应动作前必需 | 凭证材料的安全引用即可，不强制新增附件上传系统；不在普通表单录入密码、TOTP 种子或验证码 |
| 共享服务例外 | 存在同期间多客户关系时，补共享范围/期间、冲突与归因边界、人工批准记录 | 无记录不允许共享执行；不是让用户简单勾选即可绕过授权 |
| 退出/维护约定 | 原项目内容、入口维护期限、责任及继续/停用约定 | 退出后新增动作停止；未处理事项显示待办，历史记录不删除或转给其他客户 |

操作顺序：新建/选择项目 → 补目标和账号服务关系 → 显示接入缺口 → 进入素材/策略。资料未全不禁止编辑草案；不能把草案保存提示成授权已生效。

## 素材与库存

| 字段/组 | 输入及动作必需条件 | 校验与状态反馈 |
| --- | --- | --- |
| 文件/资产引用、来源、剧情范围 | 选择资产并提供来源、片段说明；成为候选必需 | 无文件或来源待补；不要求本轮实现自动元数据提取 |
| 内容身份、语言/版本关系 | 关联已有身份或提交身份核对；成为合格候选必需 | 字幕/配音/封面变化不能默认创建新独立身份；不靠文件名或哈希自动证明不同内容 |
| 时长、比例、语言、标签 | 数值/选项/文本，按目标平台及项目适配检查 | 时长为正数；适配阈值来自当前规则，不在此发明平台统一上限；未知元数据标待核查 |
| 权利范围、期限、证据 | 引用权利记录；针对目标客户/账号/目的的准入必需 | 权利失效或覆盖不明时禁止成为该安排的可执行素材，显示原因 |
| 剧情重叠 | 指向相关片段，记录重叠范围、主体不同的人工结论及依据 | 待核对不能自动放行；不新增秒数/比例阈值 |
| 归属、发布事实 | 系统只读展示身份归属、所有版本、进行中/未知/已发及证据 | 发布事实不做可任意编辑的状态下拉框；归属动作按 G-03a，已发不能“解锁后重发” |

列表至少能识别项目适用范围、内容身份和不能选用原因；现有筛选可复用。合格库存为空形成带语言/权利/目的地适配原因的补充需求，不自动购买或生成新内容。

## 策略草案、审阅与批量操作

| 字段/组 | 草案/批准条件 | 修改及响应 |
| --- | --- | --- |
| 项目/目标/规则版本 | 草案可显示待补依据；批准时关联有效版本 | 变更生成可辨认版本差异，不覆盖历史依据 |
| 账号、内容身份/文件、入口版本 | 批准前明确并核对授权、归属和适配 | 内容被其他安排抢先占用，当前项显示冲突，不自动替换后悄悄批准 |
| 文案、动作、排期与时区 | 保存草案可不完整；批准时满足对应动作及有效时间要求 | 修改已批准范围内关键内容，使受影响旧批准失效并重审；不继续显示原批准可执行 |
| 试验假设、范围、发布量/成本、期限、观察与停止条件 | 新策略小批试验批准必需；从具体项目录入 | 没有全局默认 SLA、预算、频次或改善阈值；日常托管必须落在已验证且已授权范围 |
| 主指标/单位/来源/观察窗/判断依据 | 提出并批准试验前说明 | 不可用时显示缺口或需重设并批准，不静默换指标强选赢家 |

草案保存后仍显示“草案”；送审显示“待审”；批准成功显示指定版本及范围；执行状态另列。驳回保留理由和版本；再修改形成待审版本，不能抹掉原处理记录。

批量批准先明确选中项及版本，每项分别核对；冲突项返回具体原因，其余项分别显示实际处理结果。页面不能只给整批成功提示掩盖失败，也不能把未选项计入批准。排序可沿用已有列表，批量安全性不依赖新增多重排序功能。

## 执行待办、核对与恢复

| 展示/输入 | 动作约束 |
| --- | --- |
| 当前任务/账号/设备/内容、技术状态、发布事实、原批准和排期 | 分列显示；completed/failed、设备在线或验证码通过不能直接显示“业务已恢复” |
| 异常原因、影响对象与不能排除的关联范围 | 展示同源受影响安排；明确核对依据后才能将对象排除，不按账号不同自动排除 |
| 核对证据引用、结果、操作人 | 结果未知时只允许补证据/核对；禁止直接重发、释放或更改已发历史 |
| 恢复依据、当前权限/批准/排期核对 | 条件不满足显示具体原因；原排期过期引导重新安排，不自动补发；明确失败后的恢复保留旧尝试 |
| 身份验证待办 | 展示挑战类型、时效和有权限处理人；不把通知当接管，不在提示或日志回显验证码；验证完成继续核对平台限制 |

取消未提交安排前明确展示撤销的范围以及是否符合释放条件；已提交/未知显示不能释放的原因。保留来源和核对历史，不能用一次编辑覆盖证据。

## 页面验收对照

按已有 C-01 至 C-14 走查，重点检验：可保存不完整项目、缺资料不批准、跨语言冲突、批量部分失败、已批准修改后重审、未知结果无法重发/释放、验证完成不自动恢复、退出保留历史。测试应检查实际页面与服务端行为；本规格只完成字段及交互定义，原页面不因本文更新被视为已修复。
