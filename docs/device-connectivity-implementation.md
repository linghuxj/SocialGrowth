## 2. 可信绑定与准入顺序：R-151 已确认边界

### 2.1 为什么不能只比名称或 IP

分别保存提供者身份、业务设备 ID、自有 App 安装密钥身份、Tailscale 节点身份及实际 ADB 执行身份。名称、型号、端口、局域网地址、单次入网凭据均不能独立证明这些身份属于同一台实体手机。自有 App 安装密钥可用 Android Keystore 实现，但“不可导出”能力须按支持机型核实；不把安装身份当作不可伪造的硬件身份，重装／密钥丢失不得自动建立新设备绕过旧状态。

推荐用设备密钥签名的短期挑战，结合网关观察到的真实 Tailscale 来源身份，建立可审计的安装身份与网络节点关联；随后通过中心 ADB 连接与本机 App 的新挑战关联验证，补齐执行目标一致性。该组合用于发现误绑和串号，不声称可以识别所有恶意代理转发或被攻陷手机。

### 2.2 两阶段接入

1. **公网受认证引导**：完成受邀资格及设备归属核对，建立 `enrollmentId`，登记设备安装公钥。此处不依赖 tailnet，也不签发公司网络管理权限。
2. **受限核验连接——R-151 已确认**：由中心为本次接入提供单次凭据；候选采用仅允许访问独立核验服务的网络身份。Tailscale 层先允许此受限节点连接，禁止 ADB、业务出口、其他手机及内部运营入口。不能以整个中心的 `443` 端口混用核验服务和运营 API。
3. **来源与持钥核验**：执行 App 经该核验通道取得单次挑战并签名提交；服务端从实际连接的 `RemoteAddr` 调用本机可信 LocalAPI 查询来源节点，再与接入记录、设备密钥及权威节点资料关联。挑战绑定接入 ID、设备 ID、候选节点 ID、用途及失效时间，原子消费，不能跨接入重放。
4. **正式网络准入**：中心在同一业务变更中检查归属、退出事实、节点唯一绑定、接入代次与挑战结果，记录批准意图；策略应用及实际路径核对完成后记录准入成立。仅一台网络节点对应一个当前设备绑定；发生冲突转 R-143，不覆盖旧绑定。
5. **首次 ADB 配对**：管理手机输入系统配对码，绑定指定执行中心、该手机的配对会话及当前配对端点；按 R-149 多机并发、单机互斥。配对完成后再核实连接目标，最后进入运营分配及初始化。

步骤 2 是真实的有限网络许可，不得在记录中冒称“尚未准入所以完全无权限”。用户已按 R-151 接受此先行阶段，补充 R-148 的自动准入顺序；正式准入仍需节点绑定核验，不增加逐台运营审批。签名挑战、来源识别和策略应用方式是工程方案，确认顺序不证明其已经通过实测。

受限策略必须先建立并检查叠加权限，再允许候选节点连接。不能先发放可访问全网的凭据、待节点连上后再收窄；无法证明受限范围时阻断该接法并记录原因，不用查看相同名称／IP或默认批准替代核验。

### 2.3 信任路径的实现约束

- 核验服务从实际 Tailscale 连接获取来源；不信任客户端提供的 `X-Forwarded-For`、节点 ID 或任意代理头。若部署反向代理，固定可信代理链并禁止绕过入口；不能用公网 Exit Node 出口 IP 认领手机节点。
- 同一连接在核验、策略应用及正式连接前后都检查 `networkRevision`。节点 ID、节点公钥及 Tailscale 地址分别保存；密钥轮换与地址变化不能仅因值变化就新建设备，也不能默认仍为旧绑定。
- 设备安装密钥只允许本机接入、端点上报及已确认的本机操作，不授予完整管理权限。签名不能由管理手机代替执行手机生成。
- ADB 连接目标核验候选：中心通过受控 ADB 路径将新的非敏感挑战交给目标 App，App 再以安装密钥签名经管理通路回复；收发绑定当前配对会话和连接版本。具体 Android 组件及读取方式须原型验证，不能仅以 `adb devices` 的型号或序列号为充分证据，也不先执行媒体任务试探目标。
- 受限凭据、挑战及失败节点有清理作业和真实回执。超时不等于清理成功，API 响应丢失先查原节点，不重复创建；退出后迟到批准不得开放访问。

### 2.4 受限许可生命周期与失败收口

以下状态是工程建模建议，界面使用清晰中文事实，不直接暴露枚举名。每次外部结果应用前检查接入代次、原设备归属与退出版本；一台失败不回收另一台。

| 阶段 | 可用范围及进入条件 | 后续与异常 |
| --- | --- | --- |
| 待建立受限连接 | 邀请及归属已核实，受限策略已准备；尚无已确认网络许可 | 仅签发本次受控凭据，不开放正式访问；响应未知先查询原对象 |
| 受限核验中 | 实际仅允许到独立核验服务，禁止 ADB／其他手机／运营端／业务出口 | 核验失败或期限到达就拒绝继续核验并安排回收；短时请求超时先核对原挑战，不反复创建节点 |
| 核验通过、正式权限应用中 | 节点绑定证据成立，正式策略尚未确认应用 | 不提前标为正式准入；核验结果已失效、退出或策略应用失败时停止升级并收口实际权限 |
| 正式准入 | 当前策略与实际路径核对成立，保存绑定和许可依据 | 接续配对及业务准备；本状态不代替调试授权或业务就绪 |
| 回收中／回收待处理 | 已禁止该接入继续升级，记录实际残留权限及清理作业 | 撤销未使用凭据与已注册节点许可分别处理；API 返回未知或失败时保留待处理和 R-143 事项 |
| 已回收 | 本次受限凭据／节点许可回收有证据，原接入会话保持失效 | 新接入须重新核对旧归属及未清事项，旧成功回执不能重新激活 |

接入服务在期限到达或资格失效时立即拒绝旧挑战和许可升级；网络规则收回可能稍后才确认，期间仍不授予任何正式访问。参数表的 10 分钟是工程候选，不能依赖入网凭据自动过期来替代已连接节点回收，也不把“清理作业已排队”显示为“已回收”。正常完成受限阶段不额外提醒，回收失败或需要人工处理按 R-150 提醒。

准入升级需重新核验当前状态，不能仅凭此前挑战成功永久放行。策略应用过程中出现退出，中心立即使升级作业失效并追踪实际已开放权限的回收；迟到结果只更新原作业事实，不反向清除退出。具体策略传播和旧连接收口仍须真实验证。

## 3. 网络访问策略与动态 ADB 端口

网络策略是产品控制的第二层约束，不能代替每次操作的业务许可。候选网络身份按执行中心、核验服务、业务 API、出口及执行手机分类；标签适用性、套餐和管理 API 权限仍须在实际 tailnet 核实。手机不持有修改标签、策略或签发密钥的权限。

| 来源 → 目的 | 候选允许范围 | 开放条件 |
| --- | --- | --- |
| 受限接入手机 → 独立核验服务 | TCP 443，仅接入核验 API | R-151 已确认；受邀归属已核实、受限策略有效且接入会话未失效 |
| 已准入手机 → 设备上报服务 | TCP 443，设备凭据鉴权 | 当前设备与节点绑定有效 |
| 指定执行中心 → 指定手机配对端点 | 一个当前配对 TCP 端口 | 有效配对会话、目标绑定、中心身份及本人授权 |
| 指定执行中心 → 指定手机连接端点 | 一个当前连接 TCP 端口 | 端点版本有效；所有 ADB 动作还受控制许可约束 |
| 已准入手机 → 已分配业务出口 | 所需公网流量 | 实际出口配置和业务网络验证成立；受限核验阶段不开放 |
| 手机 → 其他手机、内部运营服务 | 不授予访问 | 不能用同一提供者、多机并发或相同标签作为放行依据 |

不默认开放手机全部高位端口或固定 5555。策略编译器从中心已认可的节点地址和端点快照生成精确源、目的及 `tcp:<port>` 授权；同时处理已认可 IPv4／IPv6 地址，不接受任意 LAN 地址、公网地址或客户端可控主机名作为连接目的。地址来自权威绑定，不能仅检查“属于 Tailscale 地址段”。

处理顺序：受理新版端点 → 原连接事实过时并阻止新动作 → 生成策略目标版本 → 应用并核对实际路径 → 运行绑定该版本的连接核验 → 再检查控制事实和原任务。配对端口完成后移除，连接端口更新后旧许可收回；清理尚未确认的旧规则独立记录，旧端点不再被执行器采用。

多台同时更新策略采用单一串行策略写入者、版本检查和合并期望状态，避免 A 的修改覆盖 B。写入范围限本系统管理的规则；实施前审查全体 ACL／Grants 的叠加授权。发现其他规则已放开全网时阻断准入验证，不擅自删除其他团队规则，也不能以新增窄规则宣称隔离已成立。

策略 API 返回成功不证明所有节点已经应用，规则移除也不证明既有 TCP／ADB 会话或在途动作已停止。准入靠实际正反向连接证据，动作停止靠执行侧确认；传播延迟和残留连接必须单独测量。中心停派与控制许可失效不等待策略传播。

## 4. 最小持久对象及幂等边界

| 对象 | 核心内容与约束 |
| --- | --- |
| DeviceIdentity | 设备 ID、提供者、安装公钥指纹、凭据代次、参与意愿及控制版本；归属变化不得覆盖历史 |
| Enrollment | 接入 ID、设备、预期公钥、候选节点、阶段、期限、已消费挑战摘要及原请求 ID；同设备一个当前接入，不保存明文配对码 |
| NetworkBinding | 权威节点 ID／密钥资料／地址、绑定版本、核验依据、期望与实得许可状态；设备及节点的当前绑定各自唯一 |
| PairingSession | R-149 会话、中心身份、配对端点版本、尝试及状态；同设备一个当前会话，不同设备独立 |
| EndpointSnapshot | 设备、来源代次、序号、报告 ID、网络版本、用途、端点存在／消失／未知及中心接收时间 |
| ConnectivityIncident | 设备、项目上下文、相关任务、原因与首次失效时间、恢复进展、对应待办和提醒发送状态；同端口数字不是故障合并键 |
| NetworkPolicyRevision | 期望规则、基准版本、应用结果及实际核验，单写者推进；冲突重新读并合并，不盲目重试覆盖 |

业务状态变更与待发外部动作在同一数据库事务中保存；Tailscale API 与数据库之间不假装有跨系统原子事务。作业消费后回写实际结果，响应未知先核对原外部对象；唯一约束与比较版本保证重复回调不重复绑定、配对或提醒。

## 5. 接口收敛

路径是工程建议，正式实现可调整命名，但不改变身份与并发语义。

| 接口 | 身份与数据 | 成功及异常边界 |
| --- | --- | --- |
| `POST /device-self/enrollments` | 已关联本机身份、请求 ID、公钥持有证明；提供者及设备从凭据推导 | 返回原接入 ID、阶段和期限；重复请求不签发第二个有效接入 |
| `POST /enrollment-proof/challenges` 与 `/responses` | 仅核验服务；当前接入身份、网关观察的来源节点、单次挑战及设备签名 | 消费挑战后记录绑定依据；旧代、过期、重放、节点冲突拒绝；公网访问不能替代节点来源证明 |
| `PUT /device-self/adb-endpoint` | 延续总体设计的报告 ID、来源代次、序号、网络版本、配对／连接端点及状态 | 按设备和来源序列替换完整快照，载荷明确包含配对与连接两类各自存在／消失／未知，不能用一个端口覆盖另一用途；相同 ID 同载荷返回原结果，同 ID 不同载荷冲突，旧报告不覆盖 |
| `POST /provider/devices/{id}/pairing-sessions` | 管理身份、本人目标、请求 ID、所见设备版本 | 接续当前会话或报告冲突；不得自动取消其他入口的在途尝试 |
| `POST /provider/devices/{id}/pairing-sessions/{session}/attempts` | 本人身份、会话及端点版本、请求 ID、敏感配对码 | 返回尝试受理，不冒称配对成功；敏感码不进入普通持久队列、URL、访问日志或模型 |
| `GET /provider/devices/{id}/connectivity` | 本人管理身份 | 返回分层事实、各事实时间及可处理事项，不返回配对码、公司网络凭据或其他设备信息 |

预期鉴权失败、冲突、过期、过时分别返回稳定业务错误码；网络异常或 5xx 不表示原操作未发生。轮询和刷新仅读取记录，不自动执行 ADB 截图或重新授权。通知事件在权限过滤后才送到对应端。

## 6. 首轮联调参数：工程候选，可配置

这些值用于获得可比较的测量结果，不能写入产品为承诺。系统配对窗口更早失效时立即失效，不以服务端计时延长系统授权。

| 参数 | 候选初值 | 含义与调整依据 |
| --- | --- | --- |
| 接入记录窗口 | 10 分钟 | 未完成核验则失效并安排回收；不声称这是 Tailscale auth key 原生最短期限，须主动撤销未使用凭据 |
| 单次节点挑战 | 60 秒 | 一次消费；时钟以中心为准，慢网络可重取挑战，不能复用旧响应 |
| 配对提交窗口 | 最长 120 秒 | 与系统窗口取更早失效；进入执行队列前及执行前再查有效性 |
| 上报请求超时 | 10 秒 | 超时查询原报告，重传同一 ID；不等于设备离线 |
| 报告退避 | 1、2、4、8、16、30 秒，之后上限 30 秒，附加 0–20% 抖动 | 网络失联时不密集重试；恢复连接后优先最新快照；不触发重复业务恢复 |
| 管理存活确认 | 30 秒；90 秒未获新鲜确认标过时 | 不以缓存心跳刷新端点观察时间；后台无法维持时如实过时，不绕开系统限制 |
| 单机主动连接恢复 | 同时 1 个作业，整轮最多 120 秒，连接尝试最多 3 次 | 仅有效许可内；授权／身份错误直接转处理，超限进入待办。已有人工作业则不另起自动操作 |
| 多机并发 | 中心配对最多 4 个、连接核验最多 4 个；单机操作仍共用互斥控制 | 起步覆盖三台同人和另一提供者；20–50 台容量需独立测量，排队不能无限保留配对码 |
| 提醒发送失败重试 | 首次后 10、30、60 秒各一次，之后保持失败待处理 | 仅在渠道实际配置后生效；保持同一提醒标识，渠道超时可能已送达，不承诺跨邮件系统严格一次 |

心跳、端点新鲜度和动作许可有效性是不同计时器；90 秒不能被拿来作为“离线后仍可操作 90 秒”的许可。ADB 已明确断开或端点变更时立即使相应执行条件过时，无需等心跳阈值。

R-075 的任务恢复仍累计最多 2 次／5 分钟：工程上在每次恢复编排开始前持久增加一次尝试，计时覆盖该编排中的等待、连接与核验；报文重传和单轮内的 TCP 重试不新建任务恢复轮次。恢复成功后同一任务一轮执行的累计值不清零，换故障、端口、进程不清零；人工处理后新一轮须有明确交还／恢复复核记录并生成新的执行代次，原轮统计保留。重启后无法证实已完成的恢复耗时，按中心记录保守计入，不借重启重新获得额度；人工等待不作为自动恢复继续运行。

无在途任务时使用独立的连接维护预算，不虚构任务以套用 R-075。有在途任务时同时受连接维护和剩余任务预算约束，任一不足就停止自动处理。已暂停／退出设备不因维护预算未耗尽而允许 ADB 操作。

## 7. 分步交付与验证

| 阶段 | 可交付内容 | 通过证据 |
| --- | --- | --- |
| D1 身份与接入记录 | 受认证入口、设备密钥、接入状态、幂等与唯一绑定、失效记录 | 权限和重放的单元／集成检查；Web 流程仍须实际页面验证，不能用接口通过代替 |
| D2 核验通道与策略 | 按 R-151 实现最小通道、真实来源识别、策略版本及回收 | 未绑定节点只能到核验服务；不能到 ADB、其他手机、运营端或出口；重放／错节点不能升级许可 |
| D3 原生发现与首次配对 | App 发现本机端点、管理端输入码、中心配对、目标挑战 | 无现场电脑，四台交错真实配对；故意切换码／目标时不串号；迟到结果只落原会话 |
| D4 上报与受控重连 | 完整快照、旧代拒绝、原任务核对、异常待办及提醒记录 | 真实切换／掉线／回收 App，观察端点变化；正常恢复无人工提醒，异常不误恢复或重复发布 |
| D5 参数及容量 | 固定环境后扩大到需求范围，记录队列等待与实际恢复耗时 | 独立给出通过、失败、阻断、未验证，不用四台通过代表 20–50 台全部通过 |

Web 入口由 Playwright 实际操作并断言页面反馈、最终状态及对应目标；原生安装、Android 系统授权与设备侧发现另取真机证据，媒体操作仍由 Artemis 决策。只读日志／接口／数据库补充关联证据。没有真实客户端或设备时只交付静态／补充检查结果，不预置成功、改库或 Mock 网络结果作为业务验收。

必要样本：相同局域网及不同网络的多机、同端口数字不同节点、越权设备上报、节点换代、端点消失、单机配对超时、多机策略并发、策略传播延迟、已暂停收到新端点、退出中迟到批准、通知发送失败。回收验证包含“业务停派”“网络撤权”“实际停止”“登录清理”四类事实，不能互相替代。
