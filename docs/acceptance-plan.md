# SocialGrowth 验收与证据

更新：2026-09-27。依据[当前需求基线](current-requirements-summary.md)与[业务流程](business-workflow.md)整理；以下为目标场景，不表示全部未验证。用户按 R-109 确认既有远程执行已验证，应复用原证据并标明覆盖范围，仅补测未覆盖或变更影响，不将 Demo 全部结果自动外推。

## 验证层次

| 层次 | 需要证明什么 | 不能据此推定什么 |
| --- | --- | --- |
| 局部可行性验证 | 特定环境下，某项手机操作、网络连接、引流入口或数据采集能力可用；可使用 Demo 或原型 | 最终架构确定、完整业务闭环成立或全部机型可用 |
| 最小真实闭环 | 真实目标与方向确认 → AI 安排 → 边界检查 → 手机执行 → 发布核验 → 真实反馈 → 有依据的后续安排及执行 | 首期所有平台形式、异常和设备规模均已覆盖，或商业效果已提升 |
| 首期完整验收 | 覆盖已确认业务范围、必要配置与异常，以及 20–50 台管理目标和分散部署条件 | 已获得广告分成资格、达到收入或引流业务目标 |

少量资源先验证属于实施顺序，不缩减首期完整范围。暂停策略算法细化不取消真实 AI 决策与反馈能力，也不要求先建设策略库或实验平台。

## 证据规则

- 每项验证记录需求依据、实际输入、环境、操作、证据、结果和局限；状态区分通过、失败、阻断、未验证。
- 通过管理台的操作使用 Playwright 从真实 Web 入口验证，手机及平台结果保留真实证据；遵循[工程规范](../CLAUDE.md)，不以直接改数据、预置成功或模拟结果替代业务链路。
- 核验实际提供给 AI 的目标、范围与事实，以及其形成的安排、依据和对应结果。模板草案、模式标签、拼接分析文字不能单独证明真实 AI 决策，不要求保存模型内部思维过程。
- 截图、输入及日志保护密码、验证码和令牌。界面存在、脚本无报错或生成报告均不等于验收通过。
- 下列场景是行为要求，不意味着每行必须建设独立模块。通过门槛和样本在实际验证前落实，不能事后以结果反推标准。

## 业务范围与决策闭环

| 场景 | 验证行为 | 关键证据 |
| --- | --- | --- |
| 项目与身份 | 自营与客户项目可分别管理，账号和手机同期项目专用；登录身份与 FB Page 区分，手机可只启用一个平台，同平台不轮换身份，同一 Page/频道同时只有一台当前执行手机 | 项目分配、身份核验、同一身份被分配多台执行手机时的阻止记录；换机交接不形成双端执行 |
| 内部运营同权 | 不同内部运营均能管理全部项目及资源，负责人以外的运营可代办；通知仍按项目负责人发送；资源专用、AI 批准范围和接管互斥继续校验，客户不因此获得入口 | 不同运营的跨项目操作及实际操作者记录、负责人通知与代办、业务边界仍生效的证据 |
| 成品准入 | 内部运营人员批量上传成品，逐份核对文件完整及准入结果，人工确认素材身份及项目、商品/短剧、语言、集序、版本关系和必要业务事实，系统做规则性检查；缺失或冲突交人工，合格素材自动成为候选，不依赖 AI 识别与关联 | 人工确认信息、来源材料、检查与处置记录、候选及选用结果；包含来源及未发布声明、已有发布或重复疑点的暂停与人工处置、部分上传失败不阻塞无依赖合格内容、重试不新建名额，以及首个平台发布后另一平台仍按既定范围继续的记录；不要求 AI 自动识别或全网未发布证明 |
| 执行引擎与分工 | 业务 AI 形成获准任务，Artemis 执行 AI 负责手机界面判断、操作与反馈；系统持续校验身份、范围和接管条件，引擎完成不直接等于平台业务成功 | 业务任务、实际 Artemis 调用与执行记录、设备及账号关联、平台核验；版本与部署条件如实记录，Demo 标签或固定脚本不能替代实际执行证据 |
| 项目与任务就绪 | 可逐步准备项目，每项任务只在必需输入、有效授权和资源齐备时执行；无关素材或账号未就绪不阻塞合格任务，缺失参数不以 Demo 默认值冒充 | 本次项目输入、配置及批准范围、逐任务检查和受阻原因；缺失输入被补齐后重新检查的记录 |
| 方向与计划 | 运营确认目标及初始方向，AI 按账号阶段和项目约束形成发布安排；范围内自主处理，越界转人工 | 真实决策输入、理由、批准边界、关联任务和拒绝越界的结果 |
| 账号阶段切换 | 核实正式开通且已有批准的开通后目标时自动切换，各账号独立；数值达标、申请中不冒充开通。目标未批准、证据不足或资格失效转运营，不自行改变方向、历史及当前周期要求 | 资格来源、核验时间及生效记录、预先批准目标、后续任务安排；目标缺失与资格异常的处理，未受影响账号继续的证据 |
| FB/YT 与两类业务 | 覆盖产品展示、短剧，FB 视频/图文与 YT Shorts/常规视频的实际发布入口和正确身份 | 内容、账号、手机与任务关联，平台发布核验证据 |
| 内容名额与连载 | 同内容每平台只选一个账号和语言版本，YT Shorts/常规视频共用名额，换形式或重新导入不获得新名额；整部剧固定账号、前集成功才能继续；独立宣传片可单独安排 | 发布记录、名额检查、依赖等待与解除、固定账号记录 |
| 跨平台进度 | FB 某集失败而 YT 成功时，FB 后续依赖等待，YT 可按条件继续；共享故障按实际影响暂停 | 分平台进度及共享设备故障处置 |
| 反馈与下一轮 | AI 使用真实执行与效果反馈维持或修正安排，落实到后续执行和新反馈；维持原安排不复制任务，数据不足不强行优化；建议、安排生效和实际执行分别记录，受阻如实说明 | 本轮事实及截止时间、维持/调整依据、前后任务关系、后续实际执行与核验、新反馈及局限；报告生成不等于闭环完成，流程通过不等于证明商业提升 |
| 复盘变更与当前状态 | 范围内调整通过边界检查后执行，越界变更须运营确认；确认时重新核对当前任务及资源，已开始或未知结果任务不被普通复盘替换，暂停或撤权不被新安排绕过 | 批准边界、确认前后的变更状态、任务当前状态检查、未获确认的越界变更被阻止及仍有效原任务的处理记录 |

## 执行、可靠性与人工协作

| 场景 | 验证行为 | 关键证据 |
| --- | --- | --- |
| 登录与凭据 | 协助已有账号初始化，必要验证交人工；敏感凭据受控且不进入 AI 对话或普通证据 | 凭据录入、更新、按需使用及失效后的授权检查；实际模型输入、截图/屏幕文字及日志的保护证据，不能先将秘密发给模型再仅对报告脱敏；正确身份及人工协作结果 |
| 发布前素材准备 | 任务关联确定素材及语言版本、平台、发布身份和手机；实际文件准备及可选取后才进入发布，未到齐或版本不符不发布。素材更正/撤回使受影响旧文件不能继续用于未提交任务；重试传送不重复发布 | 任务与文件版本对应、目标手机文件就绪及实际选取证据、传送失败和旧版本阻止记录；最终平台结果另行核验 |
| 发布结果核验 | 将任务、素材版本、目标发布身份与平台实际内容对应，提交后断网等未知结果先核实，不重复提交；仅有提交提示、相同标题或列表最新一条不足以确认成功 | 平台身份与实际内容证据、可取得的内容标识或链接、与任务的对应关系、未知状态及核实过程、重复执行防止记录 |
| 素材更正与任务更新 | 保留新旧版本，暂停受影响未提交任务，重新检查后更新安排；编辑中先核对实际状态，已提交或状态不明的先核实；无关任务继续，不绕过批准范围、内容名额、连载依赖或有效窗口，不自动修改平台已有内容 | 修订前后版本及任务关联、暂停与检查结果、更新安排和旧信息未继续执行的证据、未知结果及不合格更正的处置 |
| 素材正式撤回 | 停止继续分发并取消确认未提交的关联任务，编辑中的在可确认节点停止；已提交或提交状态不明的先核实；无关素材不自动取消，连载依赖不被绕过；保留记录，重新使用须重新核准 | 素材及任务关联、撤回确认、停止与取消结果、未知发布核实、依赖和无关任务处置、重新使用未获核准时的阻止记录 |
| 已发布内容撤下 | 运营确认平台、账号、内容与具体操作后，AI 在手机上执行并核验；不扩大到其他平台或内容，不自行替换操作；结果未知先核实，保留原发布事实和处置记录，不自动重发 | 具体目标及操作确认、手机执行及平台结果、未知或需人工时的处置、未发生越范围操作的证据；平台实际支持待验证 |
| 并发、队列与有效窗口 | 按配置并发与排队，未开始任务在批准窗口内重排，超窗交人工 | 排期、并发、超窗处置及实际完成记录 |
| 单机操作互斥 | 同一手机的发布、手机采集、登录、撤下及人工接管共用控制边界，不因 FB/YT、任务类型或全局并发有余量而同时操作；切换前核对当前状态，后台接口采集按自身条件处理 | 同手机同时到达发布和采集、两个平台任务、多人接管请求，以及控制方掉线后的处理；无界面争用、旧控制方恢复不抢回已交还控制的证据 |
| 新旧计划衔接 | 未开始任务可保留、取消或重排；旧安排不重复执行，已进入平台发布流程或结果未知的任务不被普通复盘直接替换 | 变更原因和版本关系、执行起点与未知结果的独立处置 |
| 主动暂停项目 | 停止启动新发布；编辑中未提交任务在可确认节点停止；已提交及提交状态未知的仅核实，不重发、不删除、不自动记失败或取消；未取得执行端确认时不宣称已全部停止 | 暂停请求、执行端确认、编辑中停止与已提交核验记录、提交状态不明的处置；本场景不同于普通复盘 |
| 暂停期间效果采集 | 发布暂停期间按既定安排继续尝试采集已发布内容的效果，发布暂停保持有效；新增数据不触发发布，采集仍受权限、设备状态及人工接管互斥约束，延迟或缺失如实记录 | 暂停期间采集与来源对照、暂停持续生效及无新发布记录、接管或故障导致采集受限的处置 |
| 项目恢复与原任务 | 恢复前核对批准范围、素材、账号、设备、有效窗口及依赖；有效任务继续或重排，过期及失效任务不自动补发；编辑中暂停的检查实际状态，已提交或状态不明的先核实 | 暂停前任务与恢复检查、有效和失效任务的不同处置、重排关联与未重复发布证据 |
| 正式结束与剩余任务 | 停止新发布，编辑中的任务在可确认节点停止；确认未提交后取消剩余安排并保留记录，不补发；已提交或提交状态不明的先核实，不直接取消或判失败；不因普通恢复继续已取消安排 | 结束请求及执行端实际状态、取消及保留记录、未决发布核实、没有补发及误删平台内容的证据 |
| 项目结束后的收尾采集 | 按项目配置期限继续尝试跟踪历史内容效果，按期限形成如实报告后停止常规采集；缺失数据不无限延长采集，不触发发布；已提交但结果未知的继续单独核实 | 收尾期限、采集与停止记录、含来源区间及缺失的报告、未决发布核实记录；具体期限待配置 |
| 自动恢复 | 明确可恢复故障在限额内处理；默认同任务一轮累计 2 次/5 分钟，分别覆盖任一上限先到、更换故障类型不重置；账号限制、身份不符及必要验证直接转人工 | 生效参数、恢复次数及累计耗时、转人工记录；限额不是发布结果未知时的重发许可 |
| 人工待办与提醒 | 待办能定位项目、任务、身份及手机，说明原因、已尝试恢复和待人工事项；项目负责人收到提醒，其他运营可代办。发送失败不完成待办，送达或已读不恢复任务 | 路由配置、发送结果、最后已知状态与证据时间、实际处理人及处置记录；首期邮件优先，具体服务待定，敏感信息不进入普通待办或证据 |
| 同次故障合并 | 同项目同次故障合并待办与首次提醒，新增影响更新原待办；不同故障不因文字相同合并。逐任务复核，一条恢复不批量解除其他仍存在的阻断 | 故障关联、待办数量、通知和影响范围变化、部分任务恢复而其余保持暂停的记录 |
| 接管与恢复 | 核对 AI 已停止操作后才确认独占接管，发布与采集均不争用；交还后按当前界面、身份、授权及发布事实复核，不沿用旧操作进度。已发布的关联原任务，不重发；未知先核实，仍有效的任务才继续，其他设备可继续 | 接管请求与实际停止、互斥及交还证据；人工已处理但复核失败、接管期间界面或发布状态改变、任务过期及其他暂停仍有效时的处置记录 |
| 中心与会话恢复 | 中心重启、执行端重连或 AI 会话更换后按持久记录和当前事实接续；原暂停、接管、取消与授权边界仍有效，未知发布先核实，重复派发或回执不重复执行和计数 | 中断前后任务、实际平台结果与权限状态对照；恢复持久记录后仍核对最新暂停/撤权及未决结果，不将过时记录当作当前执行许可；未收到回执但平台已发布、旧消息迟到等情形的处置，具体实现不由本表锁定 |
| 运营确认换机 | 运营指定同项目新手机并确认后，AI 协助原账号登录与身份核验；接续前检查新端条件、旧端交接状态及任务结果，未知发布不重发；保留历史、内容名额和连载进度，未提交任务继续受有效窗口约束 | 迁移确认与设备身份、登录核验、旧端隔离及重连后不重复执行的证据、任务与历史接续记录；旧端隔离方案待验证 |
| 资源跨项目交接 | 运营确认原项目、目标项目和资源，旧项目执行停止且未决发布及收尾采集安排核清后再分配；同手机平台身份不得跨项目混用，旧端状态不明不记交接完成；历史归属不变，旧任务不自动转给新项目 | 交接确认、旧端停止与未决任务处置、收尾采集安排、新分配及专用检查、迁移前后历史归属对照和不重复执行证据 |
| 原厂手机与分散网络 | 无 Root、无现场网关条件下验证控制、接管、后台运行、锁屏、掉线及重启恢复，必要时现场协助；管理与业务上网同时可用 | 型号版本、实际部署网络、授权与故障过程、恢复条件 |
| 管理规模 | 在已确认支持范围内验证 20–50 台管理、队列、并发和可靠性，不要求全量同时操作 | 实际资源、负载与运行记录；不能用一台样机推定全量稳定 |

## 周期、引流与数据口径

| 场景 | 验证行为 | 关键证据 |
| --- | --- | --- |
| 引流入口与归因 | 验证观众侧可点击并跳转；记录过滤后点击；账号级可用，内容来源不明时不强行分配，链接绑定不作为来源证明 | 实际入口、点击跳转、过滤及归因记录；不将点击等同真人、到达或成交 |
| 引流任务安排与计数 | 项目周期按固定最低数安排，合格 FB/YT 平台任务分别计数，恢复重排不重复；不足报告原因，不降要求或越界补量 | 项目配置、有效入口、计划及各状态记录；不要求逐账号满足最低数 |
| 完成、缺口与迟到核验 | 以核验成功数评价，失败或待核实不计完成；缺口不自动追加下周期；迟到成功按证据中的实际发布时间更正原周期，不明时归属待确认 | 原报告与更正、发布时间和核验时间、原周期配置、跨周期去重 |
| 周期配置 | 首次可配业务时区、起始日期时间与间隔（默认 7 天）；运行中变更间隔/时区从当前周期结束的同一实际时刻连续衔接，暂不任意重设起点，当前及历史保持原边界和最低要求 | 首次配置与生效周期、跨时区前后的实际时刻及唯一归属；无空档/重叠/过渡周期，起点不同于首次复盘到期，来源日汇总不被改标签冒充 |
| 数据获取与缺失 | 默认每天尝试更新，保留来源、时间范围、实际截止及采集时间；延迟、未知与真实零值区分；缺失时继续原计划并暂停依赖该数据的优化 | 来源对照、权限、采集与缺失处置；及时发布核验不受每日采集节奏限制 |
| 发布与效果关联 | 已确认发布但暂无指标时保留发布成功、不重发；效果按来源的内容级或账号级粒度关联，不强行分摊。重复回收不增加发布完成数或累加累计快照，资源交接后历史发布归属不变 | 发布任务与平台内容对应、原始来源和统计范围、重复采集与数据补齐/更正记录；关联不明不用于单条内容比较 |
| 内容观察窗口 | 项目默认值可按平台和形式覆盖，比较等待对应窗口结束及可比证据；未满或数据不足不强行判断，项目汇总与重大异常照常 | 实际配置、发布时间、来源覆盖区间、比较依据及不足说明 |
| 完整统计日窗口 | 来源粒度不足时明确采用另设窗口；首个不足整日区间单独观察，与精确小时口径分开；同天数不自动等于同年龄或时长 | 原始时区、实际起止及发布后偏移，涉及夏令时的实际时长，来源覆盖与比较限制 |

## 新增客户端与分佣的验收准备

R-110 至 R-133 确认新增产品范围、专用执行手机及仅按 FB/YT 广告收益分佣。R-120 要求以客户端接入及媒体闭环为重点，分佣仅保留基础业务核验，不要求先建完整结算或支付系统：

| 主题 | 需要保留的证据与未决边界 |
| --- | --- |
| 注册与设备接入 | 仅受邀提供者可注册加入，未获邀请不能自行注册；保留邀请校验依据，受邀不绕过执行准入。用户和专用手机关联及授权可追溯；系统自动检查设备条件，运营确认首次项目及公司媒体账号分配，AI 登录初始化并核验实际发布身份后才接收日常任务；缺少分配或核验不发布，日常任务无额外逐条审批，必要验证交人工；设备提供者不取得全项目运营权限 |
| 一人多设备 | 同一受邀用户可关联多台专用手机，每台独立授权、检查、分配及核验；一台通过不使其他手机自动就绪。核验指定手机暂停、恢复、退出不误影响同用户其他可用手机，共享故障按实际范围处理；本人信息范围和账号分佣依据保持有效，换机或重复关联不重复计佣 |
| 客户端信息范围 | 提供者仅查看本人设备状态、必要协助事项、基础分佣记录及核对所需的账号标识；不开放其他提供者信息、项目策略、素材库或逐条发布明细，不取得运营计划修改和公司账号分配权限。验证不同提供者的信息范围及必要协助说明，同时保留暂停、恢复和退出能力；自有 App 限制不作为实体手机内容已隐藏的证据 |
| 设备自主暂停 | 提供者暂停指定手机后停止新派发，当前操作在可确认节点尽快停止；暂停期间不再使用该手机发布或采集。已提交/未知结果保留待核实，其他获准渠道可核实，不借核验继续控制暂停手机；不误停其他设备。证据覆盖发布前、编辑中、已提交未回执及手机离线时的暂停记录；请求与执行端确认分别展示，失联不伪记已停止；暂停后手机采集被阻止，重连不自动恢复，原分配和历史保留 |
| 设备自主恢复 | 设备提供者自行恢复临时暂停，不要求运营每次审批；用户请求恢复后，在有效授权内允许必要的就绪及未决结果核验，无须先放开日常执行；授权、连接、原项目/账号身份及任务事实复核通过后才恢复日常任务，失败交异常处理。覆盖必须使用该手机核实未知结果的情形，确保不会等待“先恢复才能复核”，也不借复核发起新发布。覆盖项目或账号仍暂停、权限撤销、结果未知与任务过期，确认恢复不能绕过阻断或重复发布 |
| 设备自主退出 | 用户退出后停止向该设备派发任务，在可确认节点停止当前业务操作，不以运营先批准为条件；保留在途和未决结果，运营处理账号迁移及登录清理。失联或撤权不伪记旧端已停止或清理成功，远程操作不越权；不删除平台账号、已发布内容和历史，不被重连或普通恢复重新启用 |
| 配套客户端 | 自有 App 与官方 Tailscale 可作为首期组合；分别验证注册及设备关联、组网授权、状态与 ADB 端点通知。用户无需为管理和业务上网并行启动两套系统 VPN，首期不要求网络引擎内嵌；安装成功不等于链路通过 |
| 网络准入与业务权限 | 分别核验邀请、网络节点、ADB 和业务执行权限，手机入网不获得其他提供者数据或运营权限；验证必要中心连接与上报、无授权的设备间 tailnet 访问被阻止。退出后停止业务派发并核对节点权限，单独撤销入网密钥不充当设备已退出；账号清理仍受有效授权约束，同一地点局域网另核查 |
| 内网与外网并行 | 首期在稳定现有 Wi-Fi 条件下验证实际客户端版本、管理连接及 FB/YT 上网同时可用，覆盖 Wi-Fi 掉线、切换、恢复及出口故障；分别记录 VPN、ADB 和任务状态，两个 VPN 界面都开启不能作为通过证据。纯蜂窝持续执行不作为首期前置 |
| ADB 端口通知 | 区分配对与连接端口，证明 App 识别本机而非同网其他手机；当前端点、变化上报、中心实际可达及中心 ADB 授权分别验证。覆盖无现场电脑的首次配对、端口变化、Wi-Fi 断开和授权撤销；失效端点不继续使用，VPN 在线不冒充调试就绪，重连不重复执行 |
| 自动恢复 | 分别记录重连、服务恢复、开机后恢复和整机重启的权限及结果；无法自动恢复时如实转人工，用户撤销授权不被恢复机制绕过 |
| 基础分佣记录 | 用户、设备、账号承接期间及到账收入可追溯，按产生期间适用的统一比例计算且不另扣运营成本，迟到账保留原归属及比例、不重复计佣；未知金额如实待核对，处理记录不冒充实际付款。具体比例等在实际使用前落实，不要求支付渠道、自动付款或提现体系作为媒体闭环验收前置 |

## 首期完成判定

- 真实证据能贯通目标和批准范围、人工素材资料、AI 安排、正确手机与发布身份、平台发布、效果回收、下一轮安排及执行；维持原安排也必须有依据和后续结果。
- 完整覆盖已确认的 FB/YT 发布形式、产品展示与短剧、必要人工协作、项目/素材/设备变化和目标设备规模；少量资源验证不能替代全部首期覆盖。
- 关键边界验证未出现尚未解决的串号、越权、未知结果重发或重复计数问题；按规则转人工或记录数据缺失可以是正确行为，不能把绕过问题当作通过。
- 运行参数及性能/恢复目标按事先明确的判据验证；必需场景仍有失败、阻断或未验证时，保留缺口，不宣称首期完整验收通过。
- 系统闭环通过与账号取得分成资格、商业收益改善分别评价；基础分佣验证不要求先完成完整支付体系。

本轮是文档对齐，不新增真实验证通过结论。既有用户确认的执行能力仍保留，后续实测按[工程规范](../CLAUDE.md)操作。
