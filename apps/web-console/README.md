# @socialgrowth/web-console

SocialGrowth 首批业务闭环运营工作台。

当前版本统一使用 `lib/first-loop` 的领域状态，不再加载旧静态演示数据库，也不提供设备 Ping、自愈、2FA 注入、批量下发或伪发布成功等演示操作。页面中的项目、授权、内容、入口、策略、批准、排期、观察、复盘和审计记录保存在浏览器 `localStorage`，仅用于受控业务流程验证。

## 证据边界

- 页面顶部持续显示“外部发布连接未配置”和“受控工作区”。
- 批准与排期表示业务授权边界，不表示任务已下发、设备在线或内容已发布。
- 真实发布必须由外部执行器写入关联内容、文件、账号及证据引用的回执。
- `unknown`、缺失、延迟、无权限和真实零值分别记录，不静默补零。
- 每个领域命令产生结构化审计日志，并以 `[first-loop-audit]` 输出到浏览器控制台。
- 生产数据库、身份权限、平台账号、真机执行器和真实指标源仍需单独接入与验收。

目标 PostgreSQL 结构保留在 `data/schema.sql`；浏览器本地适配不是数据库已经接入的证据。

## 页面结构

1. 运营总览：资料缺口、未分配内容、未知回执和待确认复盘。
2. 项目与授权：项目草稿、激活、账号服务关系及有效期。
3. 内容库存：内容身份、文件版本、权利引用和独占账号分配。
4. 入口与策略：共享入口、版本、规则和受控策略草案。
5. 批准与排期：逐草案批准范围、停止条件、观察条件和业务时区。
6. 观察与复盘：数据可用性、来源、时间窗、完整性及人工后续动作。
7. 审计日志：接受与拒绝操作的原因码、对象和关联信息。

## 本地开发

```bash
npm install
npm run dev
npm test
npm run build
```

`npm run lint` 当前仍会报告未被工作台引用的上游通用 UI 组件规则问题；本次改动文件需单独保持无新增告警。
